# 2026-09-02 물류 배송 메뉴 — 연락처·배송 화면·문자 발송·홈 복귀(1~4단계)

관리자가 로봇에 물건을 실어 보내고, 도착하면 그 장소에 저장된 번호로
"비카가 물건을 가지고 문 앞에 와 있습니다"를 문자로 보내는 기능. 문 닫힌
방에서는 도착 음성이 안 들려서다. 브랜치 `app_delivery_mode`(앱·ROS·루트),
`feat/app-ux-mode-split` HEAD 에서 분기. **app-ux 에 머지하지 않는다** — 실기
때 사용자가 직접 한다. 앱 265·ROS 미션 346·ROS 목적지 저장 20 통과.

## 0. 검토에서 확정한 것

- 배송은 새 주행이 아니라 **원격 주행에 "송장"을 붙인 것**. 주행·도착 신호·
  도착 음성은 기존 그대로, 새로 다는 건 ① 연락처 칸 ② 배송 메뉴 ③ "이번
  주행은 배송" 기억 ④ 문자 보내는 길 넷뿐이다.
- **문자는 B안**: 관리자 안드로이드 폰 유심으로 직접 발송(`SEND_SMS`).
  반자동(문자앱 열어주기)은 "로봇 도착까지 기다렸다 또 눌러야 한다"로 거부.
  API(C안)는 발신번호 사전등록·젯슨 인터넷 `[미검증]` 때문에 뒤로.
- **private 목적지도 배송은 간다.** 일반 주행·음성은 그대로 막는다.
- **번호는 마스킹**(`010-****-5678`), 저장은 유지, 로그에는 안 적는다.
- 도착 후 **2분 대기 → 홈 복귀**. 처음엔 5분·출발 자리 복귀였는데 같은 날 바꿨다 —
  배송은 일회성일 수 있고, 홈 복귀는 기존 서비스라 로봇에 새 문이 필요 없으며,
  관리자가 앱에서 취소하고 다시 부를 수 있다. 2분은 시험용, 나중에 늘린다.
- 시나리오 문서(`guideline/vica_scenario.md` 2절)가 "도착 후 대기"·"개인정보
  관리"를 범위 밖으로 둔 것과 부딪힌다 — 문서 범위 갱신 필요 `[GAP]`.

## 1. 연락처 한 칸 왕복 (앱 `1e6a2b4`, ROS `696b4a3`)

- ROS `storage.py:normalize_destination` 은 **적힌 키만 새 dict 로** 만든다.
  앱만 고치면 저장은 성공처럼 보이고 다시 불러오면 비어 있다. 그래서 앱과 ROS
  를 같은 날 같이 고쳤다. `contact_phone` 은 숫자만(`01012345678`) 남기고
  `01[016789]+7~8자리`가 아니면 거부. `abc` 처럼 숫자 없는 값은 빈 값으로
  눙치지 않고 거부 — 오타가 조용히 사라지면 관리자는 적었다고 믿는다.
- 앱 `core/contact_phone.dart` 가 같은 규칙. 지도 설정 화면에 '도착 문자
  연락처 (선택)' 칸, 어느 분류든 보이고 비워도 됨.

## 2. 배송 화면·상태 기계·도착 포착 (같은 커밋)

```
배송 출발 ─▶ 목적지 요청 서비스 (수락됐을 때만 '배송 중' 기억)
/vica_goal_event ─▶ location_id 가 내 배송이면
     succeeded ─▶ 문자 1회 → 결과 팝업     failed/canceled/estop ─▶ 중단, 문자 없음
```

- 로봇은 배송인지 모른다(goal 이벤트에 목적지 id·이름뿐). "이번 주행이 끝나면
  이 번호로"는 **앱의 기억**(`DeliveryJob`)이고 앱이 닫히면 같이 사라진다 —
  문자도 앱(폰)이 보내므로 의도된 한계.
- **이름이 아니라 id 로 맞춘다.** `GoalEvent` 에 `location_id` 파싱 추가. 같은
  이름 장소가 둘이면 이름 비교는 엉뚱한 사람에게 문자를 보낸다.
- 같은 도착이 두 번 와도 문자는 한 번(`notified` 빗장, 비동기 발송 전에 건다).
- "물건을 실었습니다" 체크 없이는 출발 불가 — 적재 센서가 없어 사람의 선언이
  전부다. 빈 손으로 가서 "물건 왔습니다" 문자가 나갈 수 있음은 감수.
- 발송 수단은 `DeliveryNotifier` 문 하나 뒤에 숨겼다. 2단계는 `Preview`
  (안 보내고 `sent=false` 로 알림 — 나간 척하면 안 간 문자를 갔다고 믿는다).

## 3. private 허용 + 실제 SMS 발송

- ROS: `/vica/mission/request_delivery` (타입은 같은 `RequestDestination`).
  `on_app_destination(allow_private=True)` 로 authorization 검사 하나만 풀고
  접근 가능·지도 경계·Nav2·E-stop 은 그대로. 이름을 따로 둔 근거는
  `MissionCommand.srv` 의 "무엇을 할지는 service 이름이 정한다"와 홈 복귀의
  "음성은 서비스 클라이언트가 없어 이 문에 못 닿는다". 시험 5건 추가.
- 앱: `another_telephony` 0.4.1 로 `SmsDeliveryNotifier`. 유심 여부 → 권한
  요청(첫 발송 때 팝업 1회) → `sendSms` → 통신사 `SENT` 확인(15초 시한)까지
  받아야 성공. `createDeliveryNotifier()` 가 안드로이드만 SMS, 개발 PC(리눅스)
  는 미리보기 — 시험은 그래서 자동으로 미리보기다. `AppSettings.
  missionDeliveryService` + 설정 화면 칸, `SEND_SMS` 매니페스트.
- 알아둘 성질: 받는 사람에게 관리자 개인 번호가 찍힘 / 기본 문자앱이 아니라
  폰 문자함에 기록 안 남음(앱 로그가 유일) / 한글 45자 넘으면 조각(본문이
  길이를 재서 장소 이름을 뺌).
- APK 빌드 검증: 아래 4절.

## 4. 도착 뒤 2분 → 홈 복귀 (앱만, ROS 변경 없음)

- 도착 이벤트에서 `returnAt = now + 2분` 을 적고 `Timer` 를 건다. 울리면 기존
  `/vica/mission/return_home` 을 부르고 **수락됐을 때만** '홈 복귀 중'. 거부
  (홈 없음·E-stop·연결 끊김)면 도착 상태로 남기고 사유를 적는다 — 로봇은 문 앞에
  서 있고 관리자가 '다시 복귀'나 '지우기'를 고른다. 복귀 중 실패·취소도 도착으로
  되돌리고 **자동 재시도는 없다**(E-stop 뒤 자동 재개 금지와 같은 이유).
- 화면: `m:ss 뒤 홈 복귀` 카운트다운, '지금 복귀'·'복귀 취소'. 복귀 중 취소는
  앱 취소 서비스 그대로(Mission 의 `on_app_cancel` 은 ESTOPPED 빼고 어느
  상태든 받는다). 배송 중·복귀 중·복귀 예정 중에는 표시를 못 지운다.
- 앱이 닫히면 시계도 사라진다. 그때는 다시 켜서 홈 복귀를 누르면 된다(기존 버튼).
- 시험 276 통과(`fake_async` 로 2분 경과·취소 뒤 미발동).

## 5. 남은 것


- **APK 빌드 실측(개발 PC, Flutter 3.41.9·AGP 9.0.1·Gradle 9.1)**: 두 겹으로
  막혔다. ① 제 변경과 무관하게 **기준 HEAD 도 실패** — `android/app/build.gradle.kts`

  손대지 않았고, 임시 폴더에서만 그 블록을 떼어 다음을 확인했다. ② 플러그인
  `another_telephony` 가 Kotlin 목표 1.8 / Java 목표 11 불일치로
  `compileDebugKotlin` 에서 멈춘다 → `gradle.properties` 에
  `kotlin.jvm.target.validation.mode=warning` 한 줄로 통과, `app-debug.apk`
  생성·`aapt dump permissions` 로 `SEND_SMS` 포함 확인. **이 줄은 저장소에
  넣었다.** ①은 우분투에서는 원래 APK 를 못 굽고 사용자가 윈도우에서 굽는다
  (사용자 확인) — 윈도우 빌드에서 ②의 한 줄이 충분한지 확인 `[미검증]`.
