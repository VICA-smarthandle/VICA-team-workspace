## 지도별 목적지 정본과 Mission Goal 권한 통합

- 목적지 영구 저장 정본을
  `~/vica_data/destinations/<map_id>/destinations.yaml`로 결정했다.
- 기존 `locations.json` 데이터는 이관하지 않고 빈 catalog에서 시작한다.
- `vica_destination_manager` 패키지를 추가해 앱 JSON 저장·목록·삭제 요청을 검증하고
  같은 디렉터리의 임시 파일에서 원자적으로 교체하도록 했다.
- 목적지 ID는 UUID v4만 허용한다. 전송용 `request_id`, `map_id`, `timestamp`와 앱의
  임의 저장 경로는 YAML 목적지 항목에서 제외한다.
- 저장·삭제 후 `/vica/mission/reload_destinations`를 호출한다.
- 앱·CLI의 공개 주행 요청을 `/vica/mission/request_destination`으로 통일했다.
  Mission Manager는 UUID 존재, 현재 지도, IDLE, E-stop, Nav2 준비, pose,
  `authorization == public`, 접근 가능 여부를 검사한 뒤에만 NavigateToPose를 보낸다.
- `vica_goto_goal.py`의 직접 Nav2 action 권한을 제거하고 Mission service client로
  변경했다. 터미널 사용성을 위해 현재 지도의 목적지 YAML에서 이름을 UUID로 해석하지만,
  지도·접근 권한·Safety·Nav2 검증과 Goal 생성 권한은 Mission Manager에 유지한다.
- Mission Manager가 `/vica_goal_event`를 발행해 앱 상태 bridge가 같은 주행 상태를
  받도록 연결했다.
- Flutter 목적지 UI는 계층 카테고리, 별칭, 건물·층, public/private, 접근 가능 여부,
  중첩 pose와 UUID v4를 사용한다. 지도별 저장과 지도 이미지 구조는 유지한다.
- 음성 노드는 같은 지도별 YAML의 변경 시각을 확인하고 다음 발화 전에 public 목적지만
  다시 읽는다.

## Nav2 Goal 미생성 reset 경계 보완

- `/navigate_to_pose` action server와 `app_emergency_node` status 구독의 QoS 연결은
  정상이지만, Goal을 한 번도 요청하지 않은 Nav2가 status 메시지를 발행하지 않는 것을
  실시간 graph와 4초 수신 확인으로 재현했다.
- status 수신 이력이 없으면 Nav2 미실행 또는 Goal 미생성 상태로 구분해 Goal 검사를
  생략하도록 변경했다.
- 실제 주행 E-stop에서 Mission Manager가 Goal을 `CANCELED`로 전환했지만 reset이 약
  4.8초 뒤 호출되어 2초 status timeout에 걸리는 문제를 재현했다. action status는 주기
  heartbeat가 아닌 상태 변경 이벤트이므로 메시지 나이 검사를 제거하고 마지막 상태값을
  사용한다. 활성 상태이면 전체 취소 후 요청 이후의 새 terminal 상태를 확인하며,
  Supervisor의 `/cmd_vel_req=0` 또는 stale 검사는 유지했다.

## Supervisor 앱 연동 통합 실행과 지도 자동 감지

- 현재 앱 저장소에 있는 ROS 보조 노드의 임시 운영 편의를 위해
  `VICA_Supervisor/ros2/supervisor_bringup.launch.py` 독립 실행 파일을 추가했다.
- 이 파일은 rosbridge WebSocket 9090, 지도 HTTP 서버 8000, Destination Manager,
  Map List Node와 Status App Node를 함께 실행한다. Safety·motor·localization·Nav2는
  기존 기능별 launch로 분리해 유지한다.
- Map List Node는 지도 메타데이터와 이미지 URL만 발행하므로 실제 PNG 제공을 위해
  `vica_ros2_ws/`를 기준 디렉터리로 하는 HTTP 서버를 포함했다.
- Status App Node의 `map_yaml`은 선택 항목이다. 비어 있으면 2초마다
  `/map_server/get_parameters`의 `yaml_filename`을 조회하고, 유효한 경로를 한 번
  감지하면 조회를 중단한다. 이후 `map -> base_footprint` TF가 기본 3초 이상 끊기면
  `/robot_status`를 `waiting`, 사유를 `Nav2/AMCL 미실행`으로 발행한다.
- 이 통합 파일은 실행 조정 계층이므로 사용하지 않게 되면 제거할 수 있다. ROS 보조
  노드의 장기 이동 대상은 `vica_ros2_ws/src/vica_supervisor_bridge/`이며 아직
  `[TARGET]`이다.

- 운영 모드를 SLAM 모드와 Nav2 자율주행 모드로 나누고, Nav2 모드를 터치센서 상태에

- 터치센서와 가변저항(knob)은 별개 입력으로 확정했다. 터치센서는 모드 활성/비활성만
  판정하고, knob 연속값은 활성 모드에서만 CAN으로 motor에 전달해 보행 속도를 추종한다.
  비활성 모드는 knob를 읽지 않고(또는 디폴트값 고정) 순수 Nav2 속도로 주행한다.
- 활성 모드에서 터치 미감지(핸들 놓음)는 짧은 유예 → TTS 안내 → N초 후 감속·정지로
  처리하고, 비활성 모드에서는 정지 사유가 아님을 명시했다. 모드 진입 안내 TTS 예시
  멘트를 scenario에 기록했다.
- 정지 유예·정지 지연 시간값, 최종 등급(STOP/ESTOP), 모드 전환 판정과 knob 게이팅
  담당 노드는 확정하지 않고 `[TARGET]`·팀 확정 항목(19장 1-1·1-2)으로만 남겼다.
