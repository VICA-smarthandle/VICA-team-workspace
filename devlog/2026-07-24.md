## 지도별 목적지 정본과 Mission Goal 권한 통합

- 목적지 영구 저장 정본을
  `~/vica_data/destinations/<map_id>/destinations.yaml`로 결정했다.
- 기존 `locations.json` 데이터는 이관하지 않고 빈 catalog에서 시작한다.
- `vica_destination_manager` 패키지를 추가해 앱 JSON 저장·목록·삭제 요청을 검증하고
  같은 디렉터리의 임시 파일에서 원자적으로 교체하도록 했다.
- 목적지 ID는 UUID v4만 허용한다. 전송용 `request_id`, `map_id`, `timestamp`와 앱의
  임의 저장 경로는 YAML 목적지 항목에서 제외한다.
- 저장·삭제 후 `/vica/mission/reload_destinations`를 호출한다.
- 앱·CLI의 공개 주행 요청을 `/vica/mission/request_destination`으로 통일했다.
  Mission Manager는 UUID 존재, 현재 지도, IDLE, E-stop, Nav2 준비, pose,
  `authorization == public`, 접근 가능 여부를 검사한 뒤에만 NavigateToPose를 보낸다.
- `vica_goto_goal.py`의 직접 Nav2 action과 파일 검색 권한을 제거하고 Mission service
  client로 변경했다.
- Mission Manager가 `/vica_goal_event`를 발행해 앱 상태 bridge가 같은 주행 상태를
  받도록 연결했다.
- Flutter 목적지 UI는 계층 카테고리, 별칭, 건물·층, public/private, 접근 가능 여부,
  중첩 pose와 UUID v4를 사용한다. 지도별 저장과 지도 이미지 구조는 유지한다.
- 음성 노드는 같은 지도별 YAML의 변경 시각을 확인하고 다음 발화 전에 public 목적지만
  다시 읽는다.
