# 2026-08-30 — EKF 정밀도: 회전 스케일과 자이로 편향을 순서대로 잡는다

`AMCL yaw 보정 추세 -1.81 도/분 -> +0.03 도/분`. 두 원인을 하나씩 닫았다.

## 시작 — 계획이 틀렸다

2026-08-24 에 개선 순서를 이렇게 합의해 두었다.

```
1. IMU 공분산 0.01 -> 4e-4     (한 줄, CPU 0)
2. 바퀴 제원 UMBmark
3. ZUPT
4. cuVSLAM
```

근거는 "IMU 가 신고하는 공분산 0.01 이 정지 실측 잡음(1.2e-5)의 800배라 EKF 가
휠을 4배 더 믿는다"였다. **틀렸다. 재보니 순서가 뒤집혔다.**

## bag 으로 먼저 쟀다 — 실기 없이

`/imu/base_link` 와 `/wheel/odom` 이 이미 bag 에 담기고 있어서 지난 주행을 그대로
쓸 수 있었다. 세 가지가 드러났다.

### ① EKF 는 이미 IMU 를 90 % 따르고 있다

누적 yaw 를 세 갈래로 비교했다(run0918, 242초).

```
최종   휠 +11.37도   EKF +2.97도   IMU +2.18도
       EKF 는 휠에서 8.4도, IMU 에서 0.8도 떨어져 있다
```

매 구간이 일관되게 IMU 83~107 % 였다. 공분산만 보면 휠을 4배 더 믿어야 하는데
반대다. **빈도 때문이다** — IMU 32 Hz, 휠 9.45 Hz 로 IMU 가 3.4배 자주 보정한다.
가중치가 낮아도 자주 오면 그쪽으로 끌려간다.

즉 **1단계(공분산 내리기)는 효과가 작다.** 이미 90 % 를 따르니 95 % 가 될 뿐이다.

### ② 정지 잡음은 기록보다 4배 더 좋다 — 다만 선별이 중요하다

```
느슨한 정지 판정   분산 3.46e-03   (손으로 옮긴 구간이 섞였다)
5초 이상 연속 정지  분산 3.26e-06   구간별 2.0e-6 ~ 4.1e-6 으로 일관
```

1,000배 차이다. 첫 측정을 그대로 믿었으면 "0.01 은 3배 과장일 뿐"이라는 반대
결론에 갔을 것이다.

### ③ "진동"의 80 % 는 진동이 아니었다

직진 중(휠이 회전 0 이라고 보는 구간) IMU 를 보면 정지 대비 2,700배 시끄럽다.
그런데 주파수를 보면 마스트 떨림이 아니다.

```
0 ~ 1 Hz   80.6 %     최대 성분 0.2 Hz (5초 주기)
5 Hz 이상   5.3 %      마스트가 떨면 여기 몰려야 한다
평균 -0.0026 (표준오차 0.0042)  ->  0 과 구별되지 않는다 = 좌우 대칭
```

0.2 Hz 는 **로봇이 실제로 천천히 방향이 틀어지는 것**이다. 휠이 바퀴 지름 차이나
미끄러짐 때문에 "똑바로 간다"고 보는 상황이다. 대칭이므로 적분하면 상쇄되어
각도를 갉아먹지도 않는다.

따라서 **IMU 를 빼거나 필터링하는 것은 답이 아니다.** 없앨 고주파가 5 % 뿐이라
필터를 걸면 진짜 신호만 뭉갠다.

## 원인을 셋으로 갈랐다

AMCL 이 EKF yaw 를 -1.8 도/분으로 계속 되돌리고 있었다. 그 정체를 나눴다.

```
① 휠 회전 스케일 4.7 %    550도 회전에 26도     회전한 양에 비례
② 자이로 편향 0.013도/초   243초에 3.07도        시간에 비례
③ 나머지 약 3도
```

**성질이 다르므로 따로 잡아야 한다.** 그리고 나타나는 지표도 다르다 — 스케일은
보정 '최대값'에, 편향은 보정 '추세'에 나온다.

## ① 회전 스케일 — wheel_base_m 0.37 -> 0.387

1초 넘게 이어진 회전 구간 10개에서 IMU 와 휠의 회전각을 견줬다(편향은 빼고).

```
IMU / 휠   구간별 0.902 ~ 0.973,  가중평균 0.9527
           10개가 모두 같은 방향 -> 우연이 아니라 계통 오차
```

자이로의 스케일 오차는 보통 1 % 이내이므로 휠 쪽으로 봤다. 회전각은
`(오른바퀴 - 왼바퀴) / wheel_base_m x 시간` 이라 이 값이 작으면 회전각이 크게
나온다. `0.37 x 1.047 = 0.387`.

실주행(run1139) 결과:

```
IMU/휠      0.953  ->  1.010      1 % 안에 들어왔다
보정 최대   12~39도  ->  7.94도    절반 이하
보정 추세   -1.16 도/분            거의 안 변했다  <- 예상대로
```

추세가 안 변한 것은 예상된 것이다. 그것은 시간에 비례하는 성분이고 원인이 ②다.

## ② 자이로 편향 — ZUPT

기존에는 기동 직후 1000표본(25초)으로 한 번 재고 고정이었다. 편향은 온도에 따라
변하므로 30분 뒤에는 안 맞는다.

정차할 때마다 다시 재어 20 % 씩 섞도록 고쳤다.

### 가장 큰 위험 — 직진을 정차로 착각하는 것

직진 중에도 자이로 평균은 0 에 가까워 크기만으로는 정지와 구별되지 않는다.
그런데 직진 중에는 마스트가 흔들리므로 그 흔들림을 편향으로 잡으면 나빠진다.

```
정지 중   sigma 0.0018 rad/s
직진 중   sigma 0.0939 rad/s      52배
```

크기(`max_abs_rate`)와 함께 **흔들림 폭(`max_abs_dev`)** 을 본다. 구간의 어느
표본이든 첫 표본에서 그만큼 벗어나면 정차가 아니라고 보고 버린다.
시험 `test_shaky_stretch_is_rejected` 가 이것을 지킨다.

"틀린 상수를 빼는 것은 드리프트보다 나쁘다"는 기존 규칙은 그대로 지켰다 —
통째로 교체하지 않고 alpha 만큼만 섞고, 급변은 거부하며, 구간이 끊기면 모으던
표본을 버린다.

### 실주행(run1202, 317초 · 44.4 m)

```
AMCL yaw 보정 추세   -1.16 도/분  ->  +0.03 도/분
주행 중 28회 갱신
```

로그가 결정적이다.

```
  8.3 s  #39  +163 deg/hour
 31.4 s  #41  +210
 91.7 s  #50  +165
137.5 s  #53  +145
234.3 s  #58  +221
314.7 s  #66  +153
```

**편향은 고정된 값이 아니었다.** 주행 내내 145 ~ 233 deg/hour 사이에서 60 % 폭으로
움직인다. 기동 시 한 번 재서 고정하면 그 순간 값에 갇힌다.

가장 긴 주행이었는데도 추세가 0 에 붙은 것이 특히 의미가 있다 — 편향은 시간에
비례해 쌓이므로 길수록 잘 드러나야 하는데 그렇지 않았다.

## 배운 것

**재보지 않고 순서를 정하면 효과 없는 것부터 건드린다.** 8/24 계획의 1단계는
근거가 정지 실측 하나뿐이었고, 주행 중을 재니 전제가 달라졌다. bag 에 이미
필요한 토픽이 담기고 있었으므로 실기 없이도 확인할 수 있었다.

**측정 선별이 결론을 뒤집는다.** 정지 구간을 느슨하게 고르면 분산이 1,000배
부풀려져 반대 결론이 나온다. "손으로 옮긴 구간"이 섞였기 때문이다.

**오차의 성질을 나누면 지표도 나뉜다.** 회전한 양에 비례하는 오차는 보정
최대값에, 시간에 비례하는 오차는 보정 추세에 나타난다. 한 지표만 보면 "안
좋아졌다"고 오판한다.

## 남은 것

**IMU 공분산(8/24 계획 1단계)** 은 보류한다. EKF 가 이미 IMU 를 90 % 따르므로
효과가 작다. 코드는 `stash` 에 있다.

**cuVSLAM(4단계)** 은 그대로다. `ekf.yaml` 의 `odom1` 블록과
`vslam_covariance_adapter` 가 주석으로 준비돼 있다. **유일하게 각도 그 자체를
주는 입력**이라, 지금처럼 각속도만 적분하는 구조의 한계를 넘는 유일한 길이다.
CPU 경로 최적화가 선행 조건.

**UMBmark** 은 여전히 유효하다. 이번에 잡은 것은 회전 스케일뿐이고 직진 거리
(`wheel_radius_m`)는 확인되지 않았다. UMBmark 는 둘을 함께 잡는다.

## 건드리지 않은 것

- **AMCL 출력을 EKF 에 넣지 않는다.** AMCL 이 이 EKF 의 `odom->base` TF 를 먹고
  `map->odom` 을 내므로 되먹임 고리가 된다.
- **IMU 선가속도(ax) 융합 금지.** 카메라가 마스트 위 0.885 m 다. 각가속도
  1 rad/s² 면 IMU 자리에 0.885 m/s² 의 가짜 수평 가속도가 잡히는데
  robot_localization 은 이 지렛대(α×r)를 보정하지 않는다.
- **IMU 저역통과 필터 금지.** 없앨 고주파가 5 % 뿐이고 나머지 80 % 는 진짜 신호다.
- **`process_noise_covariance`** 는 `ekf.yaml` 에 없어 기본값을 쓴다. 측정 공분산과
  짝을 이루는 값이라 함께 봐야 하지만, 이번에는 한 번에 하나씩 원칙으로 남겼다.
