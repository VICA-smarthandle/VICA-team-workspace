## 1. 자동 홈 복귀를 기본으로 껐다 — 왜 되돌렸나

어제 홈 좌표를 `return_destination` 에 넣으면서 **의도하지 않은 부작용**이 생겼다.
사람에게 다가갔다가 거절당하면 로봇이 **홈까지 스스로 달리게** 된 것이다.

그 동작 자체는 설계대로다. 문제는 **실기로 한 번도 확인되지 않았다**는 점이다.
확인 전에 자동 주행부터 켜면 **아무도 안 보는 사이에 로봇이 처음 달려 보게 된다.**

### 무엇을 바꿨나

```python
MissionLogic(auto_return_home=False)   # 기본값
```

- **꺼짐(기본)**: 접근을 마친 자리에 그대로 선다 — 홈 좌표를 넣기 전의 원래 동작
- **켜짐**: 홈까지 달린다

**관리자가 앱에서 부르는 복귀(`/vica/mission/return_home`)는 이 값과 무관하게 늘
동작한다.** 사람이 보고 있는 상태에서만 달리는 셈이고, 실기 확인은 그쪽으로 한다.

launch 파라미터로 열어 뒀다:

```bash
ros2 launch vica_mission_manager mission_manager.launch.py auto_return_home:=true
```

### 함정 하나 — `on_tick` 의 종료 판정

```python
# 틀림
if self.return_destination is None or nav_status in (...):
# 맞음
if self.active_destination is None or nav_status in (...):
```

꺼진 상태에서는 **홈이 지정돼 있어도 이번 복귀에 목적지가 없다.**
`return_destination` 을 보면 **오지 않을 주행 결과를 영영 기다린다.**

### 실기 확인이 끝나면

`auto_return_home` 기본값을 `True` 로 바꾸면 '접근을 마친 자리 = 홈' 이 된다.
그때 이 절과 `mission_logic.py` 의 주석도 함께 정리한다.

## 2. 일시정지 뒤 '다시 출발' 버튼이 안 뜨던 것

앱에서 일시정지를 눌러도 재개 버튼이 뜨지 않아 **다시 시작할 방법이 없었다.**
오류는 안 났고 화면만 '주행 중' 으로 남았다.

### 원인 — 문자열 하나에 기댔다

화면이 이렇게 판정하고 있었다.

```dart
final paused = robot?.waitingReason.trim() == '일시정지';
```

그런데 `waiting_reason` 은 **일시정지를 마지막에 검사한다**
(`vica_status_app_node._waiting_reason`).

```python
if error_reason:              return ""
if not nav2_pose_available:   return "Nav2/AMCL 미실행"
if not self._odom_fresh():    return "위치 데이터 수신 대기"
if self.navigation_paused:    return "일시정지"      # ← 여기까지 와야 한다
```

**앞의 셋 중 하나라도 걸리면 '일시정지' 가 나오지 않는다.** 문구를 한 글자만
바꿔도 깨지는 것은 덤이다.

그리고 `driving = drivingGoal.isNotEmpty && !paused` 이므로, `paused` 가 false 로
잘못 판정되면 **'주행 중' 으로 보이고 [일시정지] 버튼만 남는다.** 정확히 그 증상이었다.

### 고친 방법 — goal 이벤트를 정본으로

```dart
bool get navigationPaused {
  if (_pausedByEvent) return true;              // 정본
  return robot?.waitingReason.trim() == '일시정지';  // 보조
}
```

- `goal_paused` → 켠다
- 새 goal · 도착 · 취소 · 실패 · 비상정지 → 끈다
- 연결이 끊기면 비운다 (끊긴 사이 누군가 재개했을 수 있다)

앱은 어제부터 `/vica_goal_event` 를 구독하고 있어 **배선이 늘지 않았다.**

문자열은 보조로 남겼다. 앱이 일시정지 중에 새로 접속하면 그 사이 이벤트를 못
받는데, 1 Hz 로 오는 상태가 그 구멍을 메운다.

**둘 중 하나라도 일시정지라고 하면 일시정지로 본다.** 재개 버튼이 안 뜨는 쪽이
잘못 뜨는 쪽보다 훨씬 나쁘고, 잘못 떠도 Mission Manager 가 게이트에서 거부할 뿐이다.

시험 12건(`test/providers/navigation_paused_test.dart`).

## 3. 홈을 찍어도 지도에 아무것도 안 보이던 것

지도를 눌러도 점이 안 찍혀 **어디를 골랐는지 확인할 수 없었다.**

`MapCanvas` 는 `pickedLocation`·`poseArrow` 를 그릴 수 있는데 홈 지정에서
**아무것도 넘기지 않았다.** 장소 저장과 같은 주황 원을 쓰게 했다 — 같은 모양이어야
관리자가 새로 배울 것이 없다.

방향을 고르면 **화살표도 함께 그린다.** 어느 쪽을 보고 서게 될지는 '위' 라는
글자보다 그림이 빠르다. 선 자리를 확인한 뒤에는 **채점이 바로잡은 자세**를 그려
"12 cm 옮겼습니다" 가 눈으로 보인다.

## 5. APK 빌드가 막히던 것 — `dev` 에 push 했다

8/26 릴리스 빌드가 **build-tools 36.0.0 을 자동 설치하다가 중간에 끊겨** 실행
파일이 하나도 없는 폴더가 남았다. 그 뒤로 디버그 빌드가 막혔다.

```
Installed Build Tools revision 36.0.0 is corrupted.
```

**AGP 9.0.1 은 36.0.0 을 기본값으로 못박고 다른 버전을 스스로 고르지 않는다.**
멀쩡히 설치된 36.1.0 이 있어도 쓰지 않았고, 깨진 폴더를 치워도 같은 메시지가 났다 —
AGP 에게는 "파일이 없다" 와 "폴더가 깨졌다" 가 같은 오류다.

### app 모듈만 고치면 부족하다

```
처음:  :app:compileDebugJavaWithJavac
①후:  :shared_preferences_android:compileDebugJavaWithJavac
```

플러그인 모듈은 **각자 `android` 블록을 갖고 있어 다시 기본값을 집는다.**
루트에서 모든 모듈에 일괄 적용해야 한다.

### `subprojects` 블록의 위치가 중요하다

`evaluationDependsOn(":app")` **보다 뒤에 두면** 모듈이 이미 평가된 뒤라
`afterEvaluate` 를 걸 수 없다.

```
Cannot run Project.afterEvaluate(Action) when the project is already evaluated.
```

**이 수정만 `dev` 에 커밋·push 했다**(`14c5d9e`). 다음에 누가 어디서 빌드하든 바로
적용돼야 하기 때문이다. `feat` 브랜치에는 같은 내용이 미커밋으로 남아 있고,
나중에 `dev` 를 머지하면 정리된다.

## 6. APK 설치가 안 되던 것 — 원인은 잔여 앱이었다

새 APK 가 기존 기기에만 안 깔리고 다른 기기에서는 됐다. **삭제해도 안 됐다.**

원인은 **앱이 덜 지워진 것**이었다. 이 앱은 커스텀 권한을 선언한다.

```
com.vica.vica_supervisor.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION
```

**다른 사용자 프로필이나 듀얼앱 공간에 앱이 남아 있으면** 그 권한이 이미 등록돼
있어 새 설치가 거부된다. 주 화면에서 지워도 거기 것은 안 지워진다.

완전히 지우자 149 MB universal debug APK 가 그대로 설치됐다.

### 다음에 같은 증상이 나면

"앱이 설치되지 않았습니다" 는 **원인 열 가지를 뭉뚱그린 문구**라 화면만으로는
못 좁힌다. 순서는 이렇다.

1. **잔여 앱 완전 삭제** — 다른 사용자 프로필 · 듀얼앱/보조공간 ·
   설정 → 앱 → *시스템 앱 표시* 후 검색
2. **USB 로 `adb install`** — 실패 코드를 그대로 뱉어 한 번에 확정된다

```powershell
C:\Users\myw\AppData\Local\Android\Sdk\platform-tools\adb.exe install -r <apk>
```

### 헛짚었던 것

처음에 **서명 불일치**로 봤다. 8/2 에 다른 PC(x86_64 노트북)에서 빌드해 그 기기에
설치한 이력이 있었고(`docs/handoff_laptop_firmware_and_apk.md`), 디버그 APK 는 PC
마다 다른 키로 서명되기 때문이다. **삭제해도 안 된 시점에 그 가설은 죽었어야 했다** —
앱을 지우면 서명 기록도 사라지므로.


```powershell

flutter pub get
flutter build apk --debug
```

**`flutter clean` 은 만들어둔 APK 도 지운다.** 8/26 릴리스 APK 가 그렇게 사라졌다.

`--split-per-abi` 로 쪼개면 arm64 82 MB 로 줄지만, 이번 설치 실패의 원인은
크기가 아니었다.

### 실기에서 확인할 것 (우선순위 순)

**A. 홈 위치 — 이번 회차의 본체**

1. 홈을 **두 방식으로 각각 잡아 비교** — 지도에서 찍은 것과 세워놓고 잡은 것이
   실제로 얼마나 차이 나는지. **복도 맹점의 크기가 여기서 드러난다**
2. 홈 좌표로 **3회 왕복**해 도착 산포를 잰다 — 8/25 기준선은 축 39 cm
3. 지도를 눌렀을 때 **주황 원과 방향 화살표가 보이는지** (오늘 고친 것)
4. 안내 주행 중 홈 복귀 버튼이 **잠기는지**
5. 홈 복귀 중 **E-stop → 해제** 시 스스로 다시 출발하지 않는지
6. 같은 map_id 로 지도를 다시 저장했을 때 **"아직 가 본 적이 없습니다" 가
   되살아나는지**

**B. 오늘 고친 앱 결함**

7. 일시정지 → **'다시 출발' 버튼이 뜨는지** → 눌러서 재개되는지
8. **주행을 일부러 실패시켜** 원격 주행 화면에 팝업이 뜨는지

**C. 자동 복귀 — A 가 끝난 뒤에만**

9. `auto_return_home:=true` 로 띄우고 사람 접근을 거절 → **홈으로 가는지**
10. 확인되면 기본값을 `True` 로 바꾸는 커밋
