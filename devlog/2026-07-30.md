# 2026-07-30

Nav2 주행 튜닝을 하루 종일 했다. 같은 코스(방2 → 화장실 → 안내소)로 **12회** 주행했고
`vica_ros2_ws`의 `nav2-plannerhybrid-change` 브랜치에 커밋 7개를 쌓았다.

결론부터 적으면, 이날 확인한 가장 중요한 것은 **planner·controller·복구 동작이
서로 다른 충돌 임계값을 쓴다**는 사실이고, 그 비대칭은 파라미터로 닫을 수 없다.
하루 동안 nvblox·costmap·planner 축을 차례로 소진했지만 어느 것도 이 결함 자체를
건드리지 못했다. 마지막에 Spin 회전각을 줄여 사람이 있는 조건에서 처음으로 3/3
완주(155.4 s)를 얻었으나, 그것도 위험을 줄인 것이 아니라 회피한 것이다.

이 문서는 2026-07-25 ~ 07-30의 Nav2 작업을 한 번에 다시 읽을 수 있게 정리한 것이다.
세션 요약이 여러 번 압축되면서 근거가 흐려졌기 때문에, 커밋 메시지·계약 테스트
주석·실측 로그를 다시 읽어 사실만 남겼다.

## 3. 확정된 사실

### 3.1 충돌 임계값 비대칭 (기계어로 확인)

| 주체 | 검사 | 253(INSCRIBED) |
| --- | --- | --- |
| planner `GridCollisionChecker::inCollision` | `cmp w1, #0xfc` | **거부** |
| DWB `ObstacleFootprintCritic::pointCost` | `cmp #0xfe` / `#0xff` | 통과 (0xfd 비교가 없다) |
| Spin `CostmapTopicCollisionChecker::isCollisionFree` | 254만 | 통과 |

Spin이 쓰는 함수는 헤더에 임계값 인자가 없어(`isCollisionFree(pose, fetch)`) 설정으로
바꿀 수 없다. `nav2_costmap_2d` 또는 `nav2_behaviors`를 fork해야 한다.

연쇄는 이렇다.

```
footprint가 253 밴드에 닿음
  -> planner "Starting point in lethal space"  -> 재계획 실패
  -> BT 복구  -> Spin은 254만 보므로 회전 허용
  -> 후방 0.675 m가 쓸림  -> 충돌
```

### 3.2 기하

- footprint `[[0.305,0.227],[0.305,-0.227],[-0.565,-0.227],[-0.565,0.227]]`, padding 0.05
- 내접 **0.277** / base_link → 후방 꼭짓점 **0.675** / → 전방 꼭짓점 **0.450**
  (2.25배 차이라 회전 시 손잡이만 부딪히는 것이 기하로 설명된다)
- footprint 기하중심은 x = −0.130이고 네 꼭짓점이 그로부터 등거리 0.559다. 그러나
  **회전축은 base_link**다 — 90° 회전 시 AMCL 변위 0.073 m로, 구동륜 축(x −0.154)
  가설이 예측한 0.225 m와 맞지 않는다.
- `published_footprint` 변 길이 `[0.554, 0.970, 0.554, 0.970]`. **핸들 0.97 m가
  런타임에 정확히 들어가 있다.** Nav2가 길이를 못 계산하는 것이 아니다.
- 후방 기준은 STL(−0.505)이 아니라 줄자 실측(−0.565)이다. 핸들 기둥 위치도
  CAD(−0.265~−0.305) 대비 실측(−0.205)이 7~10 cm 어긋나 CAD 후방부를 신뢰하지 않는다.

### 3.3 통로와 오차

- 방2 → 화장실 **직선로는 물리적으로 통과 불가**(병목 여유 0.250 m < 내접 0.277).
  우회는 정답이고 고칠 대상이 아니다.
- 우회로 최협 여유 **0.412 m**, 최협 코너 폭 **1.10 m**
- 경로 추종 오차 중앙값 0.045 / p95 **0.120** / 최대 0.164 m. 속도와 무관하다
  (상관 −0.065). CAN·드라이버 300 ms 지연이 후보다.
- 따라서 inflation 창은 하한 0.277 + 0.120 = 0.397, 상한 0.412 → **0.40이 유일한 값**

### 3.4 nvblox

- 실질 소멸 기준은 `tsdf_decayed_weight_threshold`(0.001)가 아니라
  **`esdf_integrator_min_weight`(0.1)** 다. `5.0 x 0.95^n <= 0.1` → n=76 tick →
  2.5 Hz에서 30.6 s
- 필요 기억은 계산된다 — 90° 회전 3.93 s + 차체 통과 3.35 s = **7.3 s**
- `convert_to_binary_costmap: True`가 **가장 덜 예민한** 설정이다(`distance<=0`만 LETHAL)
- `esdf_slice_min/max_height`는 최대투영 밴드를 2D 한 장으로 접는 것이고,
  `esdf_slice_height`는 출력 z 인덱스일 뿐이다. 양자화가 floor 기반이라
  min_height < 0.05는 복셀 0으로 스냅되어 바닥이 들어온다.
- **global의 nvblox는 있는 편이 낫다**(A/B: 있음 2/3·평균 LETHAL 6,865 vs
  없음 1/3·2,891). 예민함은 비용이 아니라 기능이었다. 지금은 지시로 빠져 있고
  블록은 남아 있어 한 줄로 되돌린다.

### 5.4 복구 Spin이 반대 방향으로 돌았다

`spin_dist="0.30"`은 양수라 **항상 좌회전(반시계)** 이다. 첫 Spin이 wz +1.000으로
0.5초 돌아 yaw 64.4° → 94.4°가 됐고, 그 사이 footprint의 LETHAL 겹침이
**1 → 4 → 6개로 늘었다.** 좌회전이 정확히 틀린 방향이었다. 이후 Spin 3회 모두
`Collision Ahead`로 중단됐다.

```
t+74.4  Spin 시작  wz +1.000 (좌)   yaw 64.4 -> 80.7    LETHAL 1 -> 4
t+76.3  Collision Ahead - Exiting Spin
t+77.6                              yaw 94.4            LETHAL 6
t+83.1  Spin 재시도 -> 0.1초 만에 Collision Ahead
t+86.0  AMCL 재정렬 (정지 상태, odom 불변) 15 cm / 10.8도   LETHAL 6 -> 2
t+94.5  DWB 첫 유효 궤적  wz -0.400 (우회전)  -> 탈출
```

`odom`은 t+76~95 내내 (4.54, −6.71)로 고정이었다. 로봇은 물리적으로 서 있었고,
빠져나온 계기는 Spin이 아니라 **AMCL 재정렬**이었다. 그 뒤 DWB가 낸 첫 궤적이
wz −0.400, 즉 **우회전**이다. 처음부터 필요했던 그 우회전이 20초 늦게 나왔다.

### 5.6 조치 후보

1. **지도의 map (2.00~2.10, 3.40~3.65) 구간을 지운다.** 직접 해결이다.
