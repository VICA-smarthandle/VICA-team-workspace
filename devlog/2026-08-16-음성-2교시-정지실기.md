## 요약

reSpeaker·스피커를 장착하고 음성 스택 단독 실기(2교시)를 처음 수행했다.
**5개 시험 전 항목 통과.** 도중에 결함 3건을 발견해 2건은 코드로 근본 수정,
1건은 기계 로컬 설정(.env)으로 해결했다. 남은 것은 3교시(주행 스택 포함

"가죠"로 전사했지만 intent 매칭에는 영향이 없었다.

## 2. 발견한 결함과 해결

1. **`.venv` 에 openwakeword 부재** — 감시 스레드가 import 에서 즉사.
   `--no-deps` 로 0.6.0 + 부속(scipy·scikit-learn·joblib·threadpoolctl) 설치,
   전처리 모델 1회 다운로드. onnxruntime-gpu·ctranslate2 는 건드리지 않았다.
   상세 절차는 `vica-voice-llm/docs/jetson-handoff.md` 에 추가.
2. **검증 STT 가 stt 모듈을 안 거침** — faster_whisper 직접 import 로
   ① libctranslate2 선적재 누락(so 미발견) ② .env 미로드(기본 cpu/int8 →
   CUDA 전용 빌드가 거부). `from . import stt` 한 줄로 근본 수정(cb183ef).
   검증: 환경변수 없는 맨 셸에서 RED(so 미발견) → GREEN(cuda/float16 로드).
3. **whisper 버전 질의 무한 대기** — 캐시 1.43GB 가 있는데도 HF 서버 질의가
   응답을 못 받아 감시 스레드가 27분 매달렸다(소켓 7KB 수신 후 정지).
   이 장비 `.env` 에 `HF_HUB_OFFLINE=1` 로 해결(새 모델 받을 때만 잠시 해제).

## 3. 운영 사고와 교훈 — 음성 스택 중복 실행

디버깅 중 launch 를 거듭 띄우며 정리 확인을 `pgrep -f "A\|B"` 로 했는데,
**pgrep 은 ERE 라 `\|` 가 리터럴이 되어 항상 0건**으로 나왔다(헛확인).
그 결과 음성 세트가 3벌 동시에 떠 TTS 가 겹쳐 말했고, reSpeaker 직접
연결(6ch)도 실패해 기본 마이크 폴백(1ch)으로 돌았다. 전부 내리고 한 벌만
올리자 6ch 직결로 정상화됐다.

- 정리 확인은 `ps -eo pid,cmd | grep -E "src\.ros_|launch/vica_voice"` 처럼
  노드 모듈명을 전부 커버하는 패턴으로 한다.
- 같은 계열 선례: Nav2 재기동 오도메트리 중복(2026-08-13).
