스피커 음량 문제를 쫓다가 **자가 각성 방어의 실체**를 재게 됐다. 결론 두 가지다.

2. **AEC 는 자가 각성을 막지 못한다.** 82 % 를 걸러도 **9초에 한 번** 발동한다.

이에 따라 **인사말 구간은 마이크를 mute 하기로 확정**했다(2026-08-13).

이 문서는 `devlog/2026-08-12-TONY0043.md` 의 AEC 서술을 **두 번 정정한 최종본**이다.

## 1. 스피커 음량 — 원인 셋

| 원인 | 조치 | 효과 |
| --- | --- | --- |
| PulseAudio 출력이 54 % | 100 % 로 | +16 dB |
| 기본 출력이 Jetson 내장 잭 | reSpeaker 로 전환 | 경로 교정 (AEC 참조가 살아난다) |
| **TTS 가 여유의 26 % 만 사용** | `src/tts.py` 정규화 | **+10.8 dB** |

앞의 둘은 설정이라 **재부팅하면 풀릴 수 있다.** 세 번째는 코드라 유지된다.

### 1-1. 하드웨어에 음량 조절기가 없다

```text
ReSpeaker (card 2)   음량 컨트롤 없음
Jetson APE (card 1)  음량 컨트롤 없음 — I2S 라우팅 설정만 있음
```

둘 다 라인 출력이다. PulseAudio 100 % 가 그 장치의 최대치이고, 더 키우려면
소프트웨어 증폭뿐이다. 스피커는 **볼륨 버튼이 없는 고정 게인 앰프** 모델이라
입력 신호 크기가 그대로 음량이 된다.

### 1-2. TTS 정규화

```text
정규화 전   최대진폭 0.259   RMS -27.2 dBFS
정규화 후   최대진폭 0.950   RMS -16.4 dBFS   (+10.8 dB, 클리핑 없음)
안내음      최대진폭 0.399   RMS -15.2 dBFS   ← 이제 음량이 맞는다
```

`src/tts.py` 에 `normalize_peak()` 를 넣고 `_synthesize()` 와 `save()` **양쪽에** 걸었다.
`save()` 도 고친 이유는, 그 함수가 원래 `_synthesize()` 를 거치지 않아 **미리 만들어 둔
안내 음성만 작게** 나왔을 것이기 때문이다 — 능동 접근에서 인사말을 녹음으로 대체하기로
했으므로 여기가 어긋나면 안 된다.

`PEAK_TARGET = 0.95`. 1.0 에 맞추면 반올림으로 클리핑이 난다.

시험 **221 통과** (회귀 없음).

## 2. AEC — 무엇이 사실인가 ★

### 2-1. 레벨 지표로는 판정할 수 없다

같은 장비에서 조건만 바꿨는데 결과가 뒤집혔다.

| 신호 | 원음 − 처리음 | 겉보기 해석 |
| --- | --- | --- |
| 백색잡음 8초 (뒷 절반) | **+20.3 dB** | "AEC 가 잘 지운다" |
| TTS 음성 3~5초 | **−20.8 dB** | "AEC 가 오히려 키운다" |

이유는 **AGC** 다. ch0 은 AEC·빔포밍·AGC·잡음억제가 모두 적용된 최종 신호이고,
AGC 는 최대 31.6 dB 까지 되살린다. 게다가 백색잡음은 적응 필터가 수렴하기 가장 좋은
신호라 유리하게 나온다.

**레벨로 AEC 를 판정하지 말 것.** 판정기가 발동하느냐만 본다.

### 2-2. 결정적 시험 — 사람 목소리 되틀기

사람이 "비카야" 를 말한 8초를 녹음해(`human_bikaya.wav`) 스피커로 45초 되틀면서
운영과 같은 판정기(웨이크워드 모델 + `FrameGate` 문턱 0.6 · 연속 2프레임)로 채점했다.

| 구간 | 최고점 | 발동 |
| --- | --- | --- |
| 대조군 — 녹음 직접 채점 | 0.994 | **8초에 5회** |
| 되틀기 0~5초 | 0.993 | 1회 |
| 5~10 | 0.690 | 0회 |
| 10~15 | 0.993 | 1회 |
| 15~20 | 0.930 | 0회 |
| 20~25 | 0.993 | 2회 |
| 25~30 | 0.888 | 0회 |
| 30~35 | 0.991 | 1회 |
| 35~40 | 0.200 | 0회 |
| 40~45 | 0.825 | 0회 |

45초는 8초 녹음의 약 5.6배이므로 억제가 없다면 **28회쯤** 발동해야 한다. 실제 **5회**.

```text
억제율      82 %
발동 간격   9초에 한 번
인사말 환산  7.24초당 약 0.8회
```

**82 % 를 걸러도 인사할 때마다 거의 매번 자기가 깨어난다.**

> 구간별 들쭉날쭉함으로 **수렴 여부를 판정하지 않는다.** 8초 녹음을 5초 창으로 잘라
> 창마다 "비카야" 개수와 위치가 달라진 탓일 수 있다. 확실한 것은 **끝까지 발동한다**는
> 것이고, 결론에는 그것으로 충분하다.

### 2-3. TTS 는 발동하지 않았다 — 그러나 AEC 덕분이 아니다

| 재생 내용 | 호출 모델 최고점 | 발동 |
| --- | --- | --- |
| 사람 목소리 "비카야" | 0.994 | **★ 발동** |
| TTS "멈춰. 정지. 스톱. 비카야." | 0.000 | 안 함 |
| TTS "지금 이동 중입니다…" | 0.000~0.001 | 안 함 |

**같은 경로로 나갔는데 사람 목소리만 발동한다.** 경로가 걸렀다면 둘 다 낮아야 한다.
차이는 **음색**이다 — 모델은 사람 목소리로 학습됐고 TTS 합성음은 그 분포 밖이다.

지금까지 "TTS 는 자가 트리거가 안 난다" 고 본 것은 **AEC 덕분이 아니라 모델이 TTS 를
못 알아본 우연**이다. **녹음 음성으로 바꾸면 그 우연이 사라진다.**

### 2-4. 왜 다 못 지우는가

| 이유 | 설명 |
| --- | --- |
| 모델은 크기에 둔감 | 20 dB 줄여도 "비카야" 의 소리 모양은 남는다. 모델은 패턴을 본다 |
| AGC 가 되살린다 | 지운 만큼 최대 31.6 dB 까지 다시 키운다 |
| 비선형 왜곡은 못 뺀다 | AEC 는 선형 에코만 모델링한다. 스피커 왜곡분은 원본과 비례하지 않는다 |

세 번째는 **이번 정규화(+10.8 dB)로 커졌을 것**이다. 스피커를 더 세게 울리기 때문이다.

## 3. 결정 — 인사말 구간 mute 확정

**2026-08-13.** 인사말을 재생하는 동안 마이크를 mute 한다. AEC 는 보조일 뿐 방어로
치지 않는다.

`devlog/2026-08-12-능동접근-설계-TONY0043.md` 결정 1("인사 발화 중에만 mute")과
같은 방향이며, 그 근거가 이번 측정으로 확정됐다.

### 구현 조건 — 경로가 mute 를 걸어야 한다

`audio_cue.play()` 는 **설계상 `/vica/tts_state` 를 켜지 않는다**(0.15초 순음 전제,
`audio_cue.py:7-10`). 인사말이 이 경로로 나가면 **mute 가 걸리지 않는다.**
2026-08-12 되먹임 버그가 정확히 그것이었다.

따라서 능동 접근 결정 9(녹음 인사말)를 구현하려면 **음성 파일 전용 재생 경로**를
새로 만들어 `tts_state` 를 켜게 해야 한다. 순음 경로는 그대로 둔다 — 회전 효과음은
오히려 mute 가 걸리면 안 된다(회전 중 "멈춰" 를 들어야 한다).

### 대본 제약

**녹음 대본에 "비카야" 가 들어가면 안 된다.** 능동 접근 5-2 가 바로 그런 문장이다.

> 🤖 "**'비카야'** 라고 불러보시겠어요?"

이 문장을 사람 목소리 녹음으로 만들면 재생할 때마다 자기가 깨어난다. mute 가 정확히
걸리는 것이 전제이며, mute 가 한 번이라도 새면 즉시 재현된다.
