## 0. 요약

YOLO 세그멘테이션으로 시각장애인을 감지해 **1.1 m 앞까지 다가가 안내가 필요한지
음성으로 묻고, 답에 따라 갈라지는 것**까지를 구현한다. 회전·핸들 접촉·목적지 안내는
이번 범위에서 제외한다.

새로 만드는 ROS 노드는 **하나**(`person_detector_node`)이고, 새 계약은 **셋**이다.
음성 쪽 새 계약은 **없다** — 기존 파이프라인을 그대로 탄다.

`guideline/vica_scenario.md` 41행이 "사람 자동 탐지·접근"을 서비스 범위 **제외**로
명시하고 있다. 이 구현은 그 줄을 지우는 것을 전제하므로 `GOVERNANCE.md` §4의
**팀 승인이 필요하다.**

## 1. 확정된 범위

```
탐지 → 접근 → 질문 → 응답분기        ← 이번 범위
      회전 → 핸들 → 목적지 안내      ← 다음 사이클
```

로봇은 **대기 위치에 서서** 지나가는 사람을 본다. 순찰하지 않는다. 주행 중 추론이
없어 CPU 부담과 카메라 흔들림을 동시에 피한다.

## 2. 구조

```
Isaac ROS Docker              Host ROS 2                  vica-voice-llm
─────────────────             ──────────────              ───────────────
 RealSense D455                Mission Manager  ←───────→  STT / TTS / LLM
 nvblox                        Nav2 → Safety → motor
 person_detector_node (신규)
   └─ /vica/person_detection ──→
```

**추론은 컨테이너 안에서 한다.** 근거는 둘이다.

1. 카메라 드라이버가 컨테이너에서 돈다(`run_d455.sh`). 호스트에서 추론하면 컬러
   이미지를 컨테이너 밖으로 넘겨야 하고, 640x480x30 Hz 는 초당 약 27 MB 다.
   **CPU 가 이미 병목**(코어 81 %, load 14.16/8, GPU 35 %)이라 해서는 안 되는 일이다.
2. TF 는 `/tf` 토픽이라 컨테이너에서도 **조회**된다. `vica_nvblox_bringup/README.md`
   가 금지하는 것은 **발행**이지 조회가 아니므로 `map` 변환을 컨테이너가 해도 규칙에
   어긋나지 않는다.

컨테이너 밖으로 나가는 것은 `PersonDetection` 토픽 하나뿐이다(수십 바이트).

코드 동기화는 `vica_nvblox_bringup` 과 같은 방식을 쓴다. 정본은 git 에 두고
`~/workspaces/isaac_ros-dev/src/` 를 **읽기 전용 바인드 마운트 + 심볼릭 링크**로
연결한다(수동 `cp -r` 를 없앤다).

## 3. 새 계약 — 셋

| 종류 | 이름 | 내용 |
| --- | --- | --- |


## 4. Mission 상태 기계

```
IDLE ──approachable──→ APPROACHING ──도착──→ AWAITING_USER
 ↑                          │                     │
 │                          │ 실패·이탈·포기      ├─ "네"     → (이번 범위 끝)
 └───────── RETURNING ←─────┴─────────────────────┴─ "아니오"·무응답 8초
```

- `AWAITING_USER` 에서 **주도권은 음성**에 있다. Mission 은 타임아웃만 센다.
- 이 상태에서 다른 목적지 요청은 거부한다.
- E-stop 이 걸리면 접근을 버리고 `IDLE` 로 간다. **목적지를 보관하지 않는다.**
- `RETURNING` 완료 후 같은 `track_id` 는 60초간 재접근하지 않는다.

## 5. goal 계산

사람 위치 **P**, 로봇 위치 **R** 일 때

```
goal.position = P + (R - P) / |R - P| * 1.1     사람에서 로봇 쪽으로 1.1 m
goal.yaw      = atan2(P - goal.position)         사람을 바라본다
```

Nav2 에는 좌표 하나만 간다. **Nav2 는 그것이 사람인지 모른다.** 등록된 목적지로 갈
때와 완전히 같은 `NavigateToPose` 다.

사람이 움직이면 새 goal 을 보낸다. `NavigateToPose` 는 preempt 되므로 취소·재전송이
필요 없다. 다만 **BT 가 처음부터 다시 시작**하므로 갱신 임계(0.5 m)를 지켜야 한다.
자주 갱신하면 재계획만 반복하고 한 발도 못 뗀다.

## 6. 값

### 6.1 출발 조건 — 판정을 둘로 나눈다

`stable`(1초)만으로 출발하면 안 된다. 1초는 "진짜 사람인가"의 판정이지
"다가갈 가치가 있는가"의 판정이 아니다.

| 판정 | 조건 | 무엇을 거르나 |
| --- | --- | --- |
| `stable` | 신뢰도 0.6 이상 + **1.0초 연속** | 오탐 |
| `approachable` | **3초간 이동 0.3 m 미만** + 거리 **1.5 ~ 4.0 m** | 지나가는 사람 |

출발까지 최소 3초가 걸린다.

**두 판정은 모두 `person_detector_node` 가 한다.** 시계열을 보는 판정이라 탐지 이력을
가진 쪽이 해야 하고, Mission Manager 는 `approachable == true` 인 `RequestApproach` 만
받아 goal 로 바꾼다. Mission 은 탐지 이력을 쌓지 않는다.

**근거 — 로봇은 걷는 사람을 따라잡지 못한다.**

| 로봇 속도 | 보행 1.2 m/s 대비 |
| --- | --- |
| 0.3 m/s | 4.0배 느림 |
| 0.5 m/s (주행 상한) | 2.4배 느림 |

3 m 앞 사람에게 0.3 m/s 로 가면 6.3초가 걸리는데, 그동안 걷는 사람은 7.6 m 를 간다.
접근 포기 기준(2.0 m 이탈)을 4배 넘긴다. **1초 탐지로 출발하면 출발하자마자 포기하고
돌아오는 동작만 반복하며, 그 자체가 통행에 방해가 된다.**

이 제약은 시나리오와도 맞는다. 도움이 필요한 사람은 대개 멈춰 있다 — 길을 찾거나,
방향을 잃었거나, 무언가를 기다리는 중이다.

거리 상한 4.0 m 는 그 이상에서 출발하면 도착까지 10초를 넘겨 **도착 시점에 상황이
이미 달라지기** 때문이다.

### 6.2 동작 값

| 항목 | 값 | 근거 |
| --- | --- | --- |
| **정지 거리** | **1.1 m** | 6.3 절 계산. 여유 10.4 cm |
| **접근 goal tolerance** | **0.10** | 여유가 25.4 cm 로 늘어난다. 일반 주행은 0.25 유지 |
| **접근 속도 상한** | **0.3 m/s** | 주행 상한 0.5 의 60 %. `/speed_limit` 으로 접근 구간에만 건다 |
| **추론 주기** | **5 Hz** | CPU 병목. 1.2 m/s 보행 시 0.24 m 마다 갱신 — 갱신 임계 0.5 m 에 충분 |
| goal 갱신 임계 | 0.5 m | 재계획 폭주 억제 |
| 탐지 신뢰도 | 0.6 `[미검증]` | 모델 실측 후 확정 |
| 접근 포기 | 2.0 m · 3초 | 최초 탐지 위치 기준 |
| 응답 대기 | 8초 | **재생 종료 시점부터.** STT 검증 1.84초 포함 |
| 재탐지 억제 | 60초 | 같은 `track_id` |

### 6.3 정지 거리 1.1 m 의 근거

회전은 다음 사이클이지만, 정지 거리는 **회전 반경이 정한다.** 미리 만족시켜 두지
않으면 다음 사이클에서 접근 거리를 다시 바꿔야 한다.

```
안전거리 > circumscribed(0.4962) + 사람 몸 반경(0.25) + goal 오차
```

현재 `nav2_params.yaml` footprint 기준이다(`17f6820` 로 꼬리 0.595 → 0.495).

| goal tolerance | 하한 | 1.1 m 일 때 여유 |
| --- | --- | --- |
| 0.25 (일반 주행) | 1.00 m | +10.4 cm |
| **0.10 (접근 전용)** | **0.85 m** | **+25.4 cm** |

> **2026-08-12 설계의 "하한 1.10 m" 는 옛 footprint(circumscribed 0.596) 기준이다.**
> 현재 형상에서는 1.00 m 다.

### 6.4 접근 마지막 구간은 저절로 느려진다

`collision_monitor` 가 이미 배선돼 있다.

| 폴리곤 | 범위(base_link) | 동작 |
| --- | --- | --- |
| `PolygonSlow` | x 0.36 ~ **1.10**, y ±0.32 | 40 % 감속 → 0.3 x 0.4 = **0.12 m/s** |
| `PolygonStop` | x 0.36 ~ 0.60, y ±0.28 | **완전 정지** |

접근 거리 1.1 m 와 `PolygonSlow` 1.10 m 가 겹친다. **마지막 구간 감속은 설정 오류가
아니라 의도된 동작이다.** 멀리서는 0.3 m/s, 코앞에서는 0.12 m/s 가 된다.

`observation_sources` 가 `["scan"]` 뿐이라 **라이다만 본다.** 흰지팡이는 얇아 잡히지
않는다.

## 8. 오탐 처리

학습 클래스가 `visually-impaired` 하나뿐이라 **일반 행인은 탐지되지 않는다.** 반대로
오탐으로 일반인에게 접근했을 때, 이번 범위의 퇴장 경로는 **질문에 "아니오"로 답하는
것 하나뿐이다.** 태블릿 안내는 다음 사이클이다.

1차 방어는 6.1 절의 두 판정이다 — 신뢰도 0.6 **그리고** 1초 연속 **그리고** 3초 정지.
스쳐 지나가는 오탐은 여기서 걸린다.

## 13. 조사 중 발견 — `docs/nav2_backlog.md` 수치가 옛 footprint 기준이다

| 백로그 표기 | 현재 footprint 실제 |
| --- | --- |
| 제자리 회전 필요폭 **1.31 m** (265·288·332행) | **1.09 m** |
| "inscribed **0.555 m**" (339행) | 통과 필요폭 **0.550 m**. inscribed 반경은 0.225 이며 0.555 는 `2 x (inscribed + padding)` 이다 |

§9 는 `RotationShim` 을 *"제자리 회전에 1.31 m 필요한데 통로가 1.0 m"* 로 기각했으나,
현재 형상에서는 **1.09 m — 0.09 m 부족**이다. 0.31 m 부족과 0.09 m 부족은 다른
판단으로 이어진다. 288행의 "1.31 → 0.84 m" 표도 갱신 대상이다.

**2026-08-23 이 문서와 함께 정정했다.** 백로그 5곳(§6 도입부·무엇을·효과, §9 두 항목)에
현재 값과 옛 표기의 출처를 함께 남겼다. `RotationShim` 기각 근거는 부족분이
0.31 m → 0.09 m 로 줄었으므로 **재검토 여지가 있다**고 표시했고, 판단 자체는 바꾸지
않았다.
