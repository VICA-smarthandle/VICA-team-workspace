## 2. 시스템 진단이 여섯 개 결함으로 뒤덮인 이유 — 어댑터 사망

증상(사용자): 주행은 정상인데 진단 화면에 라이다·위치추정(STOP)·인지·안내·음성·앱
(DEGRADED)이 "진단이 갱신되지 않았습니다"로 뜨고 알림에 `[발생] 라이다…` 가 쌓인다.

원인: `vica_system_monitor` launch 의 `external_diagnostics_node` 가 기동 8초 만에 죽었다.

    InvalidParameterTypeException: Trying to set parameter
    'cmd_vel_req_link.min_publishers' to '1' of type 'INTEGER', expecting type 'DOUBLE'

`probes.yaml:220` 의 `min_publishers: 1`(정수)이 노드 기본값 `1.0`(실수)과 달랐다.
150296d(9/2 19:59, cmd_vel_req 링크 프로브)가 넣은 뒤 이 노드가 정상 기동한 기록이
없다 — 마지막 정상 기동은 9/2 19:32, 커밋 직전. rcl 로그는 비어 있고 launch.log 엔
"died" 한 줄뿐이라 같은 params 로 `ros2 run` 해서 재현했다.

연쇄: 어댑터가 라이다·위치·인지·안내·음성·앱 프로브를 채우는데 그게 비니 집계기가
그 부품들을 Stale 로 발행 → 건강 모니터가 `DIAG_COMPONENT_STALE` 6건(정책 등급으로
승격) → `/robot/health` state 3 → 앱은 "준비 안 됨" + 알림 `[발생]`. 진단은 관측
전용이라 주행은 멀쩡했다.

수리(커밋 `9cce8e8`):
- ② 죽지 않기 — `_read_probe_values` 를 `dynamic_typing` 으로 선언해 정수·실수·문자열
  차이를 타입 오류로 만들지 않고, 선언 예외는 `config_problems` 에 남기고 그 프로브만
  건너뛴다. `_LINK_FIELDS` 기본값을 정수 1 로. YAML 숫자 종류 계약 시험.
- ③ 한 건으로 알리기 — 어댑터가 죽으면 어댑터 진단뿐이던 부품은 결함이 아니라
  관측 불가(UNKNOWN)로 두고 `MONITOR_DIAG_INPUT_STALE` 한 건(DEGRADED)을 낸다.
  lifecycle 진단·TF·Nav2 처럼 다른 근거가 있는 부품은 그것으로 판정. `adapter_grace_sec` 30.
  agg_parser 에 어댑터 자기 진단·어댑터 출신·그룹 항목 판별, `worst_by_component(exclude_adapter)`.
- 곁다리 — 낡은 시험 2건(nvblox 기대·docstring 대문자) 정리. 패키지 시험 256 통과.
- 2회차 실기에서 확인: 어댑터 살아 있고 부품 9개 정상, 초기 위치 전엔 TF·Nav2 2건만.

## 3. 알림에 위치추정이 번갈아 뜬 이유 — 경고의 승격

증상(사용자, 2회차): '알림 및 로그'에 위치추정 `[발생]`/`[해소]` 가 20~40초 간격으로
반복. 로봇은 정상 주행.

실측: `/odom` 은 EKF 명목 30 Hz 인데 CPU 부하(1분 15~24) 아래서 정지 상태에도
24.2~24.9 Hz, 주행 중엔 잠깐씩 허용 하한 16 Hz(min 20×0.8) 아래로. 어댑터는 그때
WARN 을 낸다. 최대 범인은 `yolo_live_view.py`(구경용, 85~94 %·1 GB).

경로 둘:
1. `health_logic._build_fault` 가 진단 등급이 아니라 부품 정책 등급(위치추정=STOP)을
   써서 "주기 조금 처짐"이 "주행 불가"로 승격.
2. 결함이 첫 tick 에 올라가고 2 tick 뒤 내려가(clear_confirm_ticks 2) 16 Hz 언저리에서
   raised/cleared 반복. 앱은 STOP 이상만 알림 목록에 적는다.

수리(커밋 `8f74bfd`, 처음 8883ccd 로 매핑 브랜치에 잘못 얹혔다가 옮김):
- ① `DIAG_COMPONENT_WARN`(신선한 경고)은 READY 유지 + WARN 결함. ERROR·STALE 은 종전대로
  승격. 경고는 진단 화면에 '주의'로만 보이고 전체 상태·알림 목록에는 안 들어간다.
- ② `raise_confirm_ticks` — 발생도 연속 N tick 관측돼야 알리고 활성 목록에 넣는다.
  못 채우고 사라진 후보는 발생·해소 어느 것도 남기지 않는다. 래치 결함(E-stop)은
  기다리지 않는다(규칙 6). 기본 1, yaml 3. 어댑터 주기 프로브 창 5→10 s.
- `/odom` min_hz 20 은 유지 — 낮추면 CPU 부족 신호를 잃는다. 근본은 YOLO 구경 칸.
- 시험 8건 추가, 패키지 264 통과. **⑪-1 monitor 칸 재기동으로 반영.**

## 4. 저장된 장소 수정 (커밋 `3b3716d`)

젯슨에 저장한 장소는 '선택 장소 삭제'만 있었다. 새 메뉴 없이 삭제 옆에 '선택 장소
수정'을 뒀다(사용자 결정). 누르면 원본이 채워진 시트가 열리고, 저장이 수정 모드에서는
'ROS2에 수정 저장'으로 임시 저장 없이 바로 `/save_location` 으로 나간다
(`provider.saveLocation`, 같은 id 는 `storage.upsert` 가 덮어씀). 시트를 닫아도 점과
폼은 남아 지도를 눌러 점을 옮긴 뒤 다시 열 수 있다. `core/location_edit.dart`:
이름이 그대로면 손으로 다듬은 확인·도착 멘트와 id·지도를 지키고, 이름이 바뀌었을
때만 멘트를 새로 만든다. 시험 6건.
