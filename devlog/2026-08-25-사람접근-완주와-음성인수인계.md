
## 2. 음성 파트 인수인계 — 개발해야 할 것

**현재 상태: 음성 없이도 시나리오가 닫힌다** (무응답 8초 → 접근 종료). 8/25 실기의
affirm 은 Claude 가 `/vica/intent` 토픽으로 대신 쏜 것이다. **음성이 이 역할을
넘겨받는 것이 인수 목표다.**

### 2.1 이미 되는 것 — 손대지 말 것

| 기능 | 경로 | 비고 |
| --- | --- | --- |
| 질문 발화 | Mission `Say` → `/vica/tts_request` (`"response:안내가 필요하신가요?"`) | 기존 tts_queue 계약(`priority:text`) 그대로. **음성 쪽 작업 없음** |
| 질문 후 재청취 | `expects_reply=True` → `/vica/listen_request` (Bool) | 기존 재청취 창 그대로. "비카야" 재호출 불필요 |
| 수락/거절 안내 발화 | Mission 이 함 | **음성이 따라 말하면 이중 발화** — 아래 reply="" 규칙의 이유 |

### 2.2 만들어야 할 것 ①: affirm/deny 발행 (필수)

계약 정본: `vica_ros2_ws/src/vica_interfaces/msg/VicaIntent.msg` 의 affirm/deny 절.
요약:

- `intent` 값으로 `"affirm"` / `"deny"` 를 발행한다 — **로봇이 직전에 던진 질문에
  대한 짧은 답("네"/"아니오")**이라는 뜻만 담는다
- **어느 질문의 답인지는 담지 않는다.** 판정은 상태를 가진 Mission 이 한다
  (AWAITING_USER 면 접근 질문의 답으로 소비, 그 외 상태에선 로그만 남기고 무시 —
  아무 때나 보내도 안전하다)
- 필드 규칙: `matched_destination_id=""`, `need_confirm=False`, **`reply=""`**
  (수락/거절 발화는 Mission 몫 — 채우면 두 번 말한다), `safety_flag="normal"`,
  `confidence` 는 분류 확신도
- 취소 확인("취소할까요?")의 긍/부정은 **기존 경로(cancel 재발화) 유지** — 합치지
  않는다 (두 질문은 상태가 배타적이라 겹칠 일 없음)

구현 위치 (vica-voice-llm):

1. `src/schema.py` — `VicaIntentType` Literal 에 `"affirm", "deny"` 추가 (한 줄)
2. **짧은 긍/부정 단축 분류를 접근 질문 뒤에도 걸기** — `src/handle_mode.py` 에
   이미 "짧은 긍정/부정이면 YES/NO" 분류기가 있다. 지금은 직전 AI 발화가 목적지
   `confirm_prompt` 일 때만 걸리므로, **직전 발화가 접근 질문("안내가
   필요하신가요?")일 때도** 이 단축을 타서 affirm/deny 로 발행하게 조건을 넓힌다.
   LLM 왕복 없이 1초 내 응답이 목표다 (STT 1.8 s 가 병목이므로 단축이 핵심)
3. LLM 경로 폴백 — 단축이 못 가른 애매한 답("어… 부탁드려요")은 LLM 이
   affirm/deny/unknown 으로 분류. 프롬프트에 "직전 질문이 안내 제안이면 짧은
   수락/거절을 affirm/deny 로" 규칙 추가

### 2.3 만들어야 할 것 ②: (선택·후순위) TTS 재생 완료 이벤트

Mission 에 `on_approach_question_spoken()` 이 준비돼 있다 — TTS 가 "다 말했다"는
신호를 주면 응답 대기 8초를 **재생이 끝난 시점부터** 정확히 센다. 없어도 동작한다
(질문 생성 시각부터 세며, 오차는 사람에게 불리하지 않은 쪽). 신호 채널은 미정 —
만들 때 Mission 쪽 구독 배선과 함께 정한다 (Mission 쪽은 요청 시 지원).

### 2.4 시험 방법 (마이크 없이도 가능)

1. **회귀 기준**: Mission 이 AWAITING_USER 일 때 아래를 발행하면 "알겠습니다"
   발화 + 180도 회전이 나온다 — 8/25 에 실기로 실증된 기준선이다.

   ```bash
   ros2 topic pub --once /vica/intent vica_interfaces/msg/VicaIntent \
     "{intent: affirm, confidence: 1.0, need_confirm: false, reply: '', safety_flag: normal}"
   ```

2. **음성 구현 검증**: 위 수동 발행 대신, 접근 질문 직후 재청취 창에서 "네"를
   말해 같은 결과가 나오면 인수 완료. "아니오"는 거절 멘트 + 복귀(RETURNING).
3. AWAITING_USER 가 아닐 때 affirm 을 보내면 Mission 로그에
   `affirm/deny 무시: state=... (접근 질문 대기 중이 아님)` 만 남아야 한다.

### 2.5 주의사항

- **8초 안에 도착해야 한다.** 응답 시한(8 s)을 넘기면 접근이 끝난 뒤라 무시된다.
  STT 1.8 s + 분류 시간을 감안하면 단축 경로가 사실상 필수다
- 마이크는 reSpeaker v3.0 (XVF3000·2886:0018) — 현재 **로봇에 미장착** 상태가
  잦으니 시험 전 장착 확인
- 긴급어("멈춰" 등)는 이 경로와 무관하게 기존 필터가 선처리한다 — 건드리지 말 것
