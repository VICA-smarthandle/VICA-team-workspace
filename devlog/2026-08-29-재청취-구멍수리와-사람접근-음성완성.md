## 2. "질문해 놓고 안 듣는" 구멍 2개 수리

재청취 창을 여는 열쇠가 의도 종류(need_confirm·clarify)뿐이라, 갈래 밖 질문은
전부 침묵 구간이었다.

- **LLM 이 자유 생성한 질문** ('굿에이'→unknown→"무엇을 도와드릴까요?" 실측):
  문장 꼴 판정(`expects_answer`: '?' 또는 "말씀해 주세요."로 끝남)을 열쇠에 추가
  — voice `f75305b`.
- **미션의 "다시 말씀해 주세요"**(STALE_CONFIRM)에 `expects_reply` 누락 — ros2
  `d251248`, colcon 빌드 완료.

덤: 청취 창 **안에서** "비카야"를 부르면 LLM 우회 없이 즉시 "네?"(녹음 0초)로
받고 창을 다시 연다 — 오전사 단골 '피카야' 포함 (voice `3ff017c`).

## 3. 사람 접근 음성 완성 (approach-voice-flow.md 의 ⬜ 소진)

  호출어의 **사용 시점**을 알려준다. ⚠️ 재녹음 전까지 이 멘트만 합성으로 나감.

## 4. E-stop 전이 음성 안내 3종 (ros2 `27925d0`)

시각장애인에게 E-stop 이후는 "말없이 안 움직이는 시간"이었다. 기존
`/estop_sources` 구독만으로 해결 — safety 체인 무변경.

| 상황 | 멘트 (사용자 확정 문구) |
| --- | --- |
| 걸림 (사람 개입·주행 중 끊김) | "안전을 위해 멈추겠습니다. **관리자를 호출했습니다.**" |
| 걸림 (통신 원인·정지 중 = 자동 복구 예정) | "연결 문제로 잠시 섰습니다. 곧 자동으로 복구됩니다." |
| 원인 전부 해제·래치만 남음 (reset 대기) | "안전 확인이 필요해서 관리자를 기다리고 있습니다. 잠시만 기다려 주세요." (1회) |

주의: "관리자를 호출했습니다"는 현재 앱 화면 표시일 뿐 푸시 알림이 없다 —
**앱팀에 실제 알림 기능 제안 필요.**

## 6. 계획에 적어둔 것 (미착수)

- 접수 신호를 말 대신 **생각 중 효과음 루프**로 (TTS 노드 안에 넣어 스피커
  쟁탈전 회피 — 설계 합의됨)
- 긴급어 E-stop 의 해제 완화 — **B안**: 정지는 래치 그대로, 음성 원인 래치만
  사용자 확언("다시 가자"→"네")으로 해제. 정책 질문 2개(행인의 "멈춰", 주행 중
  범위)를 주행팀·안전 담당과 합의 후 진행. 견적: 합의 반나절 + 구현 2~3일 +
  실기 1일
- 도착 후 홈 복귀 + 안내 멘트 — 시나리오 문서상 "도착 후 대기"부터 **의도된
  범위 제외**였음을 확인. 사람접근 RETURNING 로직이 발판
