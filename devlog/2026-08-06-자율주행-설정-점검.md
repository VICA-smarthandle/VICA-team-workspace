## 1. 한 줄로 말하면

**Nav2 정석은 "동그란 로봇청소기"를 가정하고 만들어졌다. VICA는 앞뒤 90 cm에
뒤로 손잡이가 29 cm 튀어나온 로봇이고, 그 뒤를 시각장애인이 붙잡고 걷는다.**

그래서 정석과 다른 것이 많은데, **대부분은 반드시 바꿔야 했던 것들이고 실측
근거도 두텁다.** 다만 위치를 파악하는 부분(AMCL)만 손대지 않은 채 남아 있다.

## 2. 왜 다를 수밖에 없나 — 이 로봇의 세 가지 특수성

### 특수성 ① 로봇이 동그랗지 않다

정석 설정에는 이렇게 적혀 있다.

```yaml
robot_radius: 0.22      # 반지름 22 cm 짜리 원
```

원이면 편하다. 어느 방향으로 돌아도 차지하는 공간이 똑같기 때문이다.
**VICA는 원이 아니다.**

```
        앞 30.5 cm
     ┌──────────┐
     │          │  폭 45.5 cm
     │   로봇   │
     └────┐┌────┘
          ││       ← 손잡이가 뒤로 29 cm 더 나옴
          ││
       뒤 59.5 cm
```

- **가장 가까운 벽까지 거리(내접반경) = 27.75 cm** — 옆구리 기준
- **가장 먼 꼭짓점까지 거리(외접반경) = 65.06 cm** — 손잡이 끝 기준
- 둘이 **2.3배** 차이 난다

원이면 이 둘이 같다. 그래서 정석 설정은 "중심점 하나만 보면 된다"고 가정하는데,
VICA는 **중심은 멀쩡한데 손잡이 끝이 벽에 닿는** 상황이 생긴다.

### 특수성 ② 뒤에 사람이 따라온다

시각장애인이 손잡이를 잡고 걷는다. 그래서:

- **후진 금지** — 뒤에 사람이 서 있다
- **급정거 금지** — 넘어질 수 있다
- **큰 유턴 금지** — 사람이 그만큼 많이 움직여야 한다

정석 Nav2에는 이런 개념이 아예 없다. 로봇 혼자 다니는 걸 가정하기 때문이다.

### 특수성 ③ 통로가 로봇보다 좁다

```
제자리에서 한 바퀴 돌려면 필요한 폭 : 1.31 m
실제 건물 통로 폭                   : 1.00 m
```

**못 돈다.** 이건 설정으로 못 고친다.

## 3. 잘한 것 — 근거도 있고 로봇에도 맞다

### 3.1 로봇 모양을 제대로 알려줬다

| | 정석 | VICA |
| --- | --- | --- |
| 모양 | `robot_radius: 0.22` (원) | 육각형 꼭짓점 6개를 직접 지정 |
| 여유 | 없음 | `footprint_padding: 0.05` (5 cm 더 크게 봄) |

**쉽게 말하면**: 원으로 치면 뒤 손잡이 29 cm가 통째로 없는 셈이 된다. 그 상태로
벽 옆을 지나면 손잡이가 긁힌다.

### 3.2 "중심만 보기" → "몸통 전체 보기"로 바꿨다 ⭐

```
정석  BaseObstacle       : 로봇 중심 한 점만 확인
VICA  ObstacleFootprint  : 육각형 테두리를 전부 확인
```

**쉽게 말하면**: 사람이 좁은 문을 지날 때 "내 배꼽이 문틀 안에 있나"만 보는 것과
"어깨와 가방까지 다 들어가나"를 보는 것의 차이다.

실측: 이것만 바꿔서 **느리게 기어가는 시간이 11.0초 → 7.9초**로 줄었다.

### 3.3 길 찾는 방식을 통째로 바꿨다 ⭐

```
정석  NavFn             : 로봇을 '점'으로 보고 길을 그림
VICA  SmacPlannerLattice: 로봇 모양 그대로 놓아보며 길을 그림
```

**왜 바꿨나 (실측)**: 점으로 보면 지도의 74.9 %를 "갈 수 있다"고 했는데, 실제로
몸통을 놓아보면 42.0 %만 갈 수 있었다. **32.9 %p 차이**. 길 찾는 쪽은 "여기 가라"
하고 운전하는 쪽은 "못 갑니다" 하니 통로 한가운데서 20초씩 멈췄다.

덤으로 Lattice는 **제자리 회전 동작을 112개 중 32개** 갖고 있다. 좁은 곳에서
이게 없으면 반경 0.5 m 원을 그리며 돌아야 하는데, 그러려면 통로 폭 1.85 m가
필요해서 우리 건물에서는 어느 통로에서도 불가능하다.

### 3.4 후진을 아예 없앴다 ⭐

복구 동작 목록에서 `BackUp`(뒤로 물러나기)을 뺐다.

**왜**: 2026-07-30 주행에서 로봇이 실제로 **30 cm 후진**했다. 그 뒤에는 사람이
손잡이를 잡고 서 있다.

### 3.5 더 멀리 내다보게 했다

```
정석  sim_time 1.7초  →  앞으로 0.80 m 까지만 검사
VICA  sim_time 2.5초  →  앞으로 1.01 m 까지 검사
```

**왜**: 카메라·라이다는 3 m 앞까지 보는데, 운전하는 쪽은 0.8 m 앞만 확인하고
있었다. 실제 기록에서 **의자가 1.5 m 앞에 나타났는데 4초 동안 감속을 안 했다.**

2.0초로 줄여봤다가 오히려 **"갈 수 있는 길 없음"이 74회 → 168회로 2.3배 악화**돼서
되돌렸다. 짧게 보면 "앞이 막혔다"만 보이고, 돌아나갈 길은 멀리 봐야 보이기 때문이다.

### 3.6 얇은 물건을 놓치지 않게 했다

`observation_persistence: 0.5` (정석에는 없는 설정)

**쉽게 말하면**: 라이다는 딱 한 높이(38 cm)만 보는 레이저다. 의자 다리처럼 얇은
것은 **1 m 거리에서 1.6 cm 폭**밖에 안 맞아서, 점이 1~2개만 찍혔다 사라졌다 한다.

그래서 "한 번 본 것은 0.5초 동안 기억해라"를 넣었다. 안 그러면 지도에서 의자
다리가 깜빡거리고, 로봇은 갈까 말까 망설이며 3.4초씩 기어간다.

### 3.7 부드럽게 멈추게 했다 ⭐

```
정석  max_decel -2.5   (급브레이크)
VICA  max_decel -1.0   (부드럽게)
```

**왜**: 사람이 손잡이를 잡고 걷는다. **급정거하면 넘어진다.** 승차감이 곧 안전이다.

대가도 계산해뒀다 — 멈추는 거리가 2 cm 늘어나는데, footprint에 준 여유 5 cm
안이라 계획한 정지선을 넘지 않는다.

### 3.8 참을성을 늘렸다

```
정석  10초 안에 50 cm 못 가면 실패
VICA  20초 안에 10 cm 못 가면 실패
```

**왜**: 정석 기준은 "평균 초속 5 cm 이상을 계속 유지하라"는 뜻인데, **좁은 곳에서
조심조심 가는 속도가 정확히 그 속도**다. 즉 정상 주행을 실패로 오판하고 있었다.

### 3.9 그 밖에

| 바꾼 것 | 왜 |
| --- | --- |
| `StoppedGoalChecker` | 위치뿐 아니라 **실제로 멈췄는지**까지 확인하고 도착 선언. 사람이 따라오므로 |
| `forward_point_distance 0.1 → 0.325` | 0.1은 로봇 몸통(앞 0.305) **안쪽**이라 방향 정보가 사라진다. 코너를 미리 못 보고 도달해서야 반응했다 |
| `velocity_timeout 1.0 → 0.4` | Safety의 감시 시간(0.5초)보다 짧게 둬서 틈을 없앰 |
| `decel_lim_theta -3.2` 유지 | 회전 브레이크는 승차감이 아니라 **조향 권한**이라 약화 금지. −1.2였을 때 예측 0.125초 vs 실제 0.333초로 어긋나 비틀거렸다 |
| 계약 테스트 7개 | 실제로 났던 사고(충돌·후진·Safety 우회)를 테스트로 못 박아 재발 방지 |

**총평**: 3.2 · 3.3 · 3.4는 이 로봇에서 **반드시 해야 했던** 변경이고 전부
실측으로 뒷받침된다. 3.5 · 3.7 · 3.8은 "정석대로 두면 오히려 위험하거나 손해"인
경우를 실주행으로 찾아낸 것이라 수준이 높다.

## 4. 잘했지만 위험이 남은 것

### 4.1 벽에서 떨어지라는 선이 로봇보다 짧다 ⚠️

```
inflation_radius (벽 주변 "가까이 가지 마" 선)  : 0.55 m
로봇 손잡이 끝까지 거리 (외접반경)              : 0.6506 m
```

`inflation_radius 0.55`는 **정석 기본값 그대로**다. 그런데 로봇 모양만 육각형으로
바꿔서 부등식이 깨졌다.

**무슨 일이 생기나**: 길 찾는 쪽(Smac)은 "중심이 이 선 밖이면 안전"이라고 판단하고
몸통 검사를 건너뛴다. 그런데 손잡이는 0.651 m까지 뻗는다. 즉 **벽에서 0.55~0.651 m
사이 10 cm 띠가 검사 사각지대**다.

**지금 이걸 막는 건 DWB의 `ObstacleFootprint` 하나뿐이다.** DWB는 이 최적화를 안
쓰고 매번 몸통을 검사하기 때문이다. **controller를 MPPI로 바꾸면 이 방벽이 사라진다.**

→ 상세: `devlog/2026-08-05-inflation-외접반경-검증.md`
→ 이번에 `nav2_params.yaml`의 해당 위치에 이 경고를 주석으로 박아 뒀다.

### 4.2 global 지도에서 nvblox를 뺐다

A/B 실험은 **넣으면 3/3 성공, 빼면 1/3**이었는데 사용자 지시로 뺀 상태다.
결과적으로 길 찾는 쪽은 **라이다 높이(38 cm) 아래 사선 책상다리를 못 본다.**
계약 테스트가 "닫히지 않은 실험"으로 기록 중이다.

### 4.3 복구 회전이 생각보다 훨씬 작다

BT 주석에 "6회 재시도에서 최대 100도까지 돈다"고 적혀 있었는데 **틀렸다.**
좌·우가 번갈아 나오므로 각이 누적되지 않는다. 실제로는 **순 회전 17.2도 / 총 쓸린 각
51.6도** — 기본 Nav2의 Spin 한 번(90도)보다도 작다. (이번에 주석을 고쳤다.)

### 4.4 장애물 회피 세기를 조절할 여지가 없다

`ObstacleFootprint.scale`은 0.15에서는 **벽에 파고들고**, 0.6에서는 **궤적이
전멸(152회)**한다. 중간값 0.25도 시험했는데 갇힘이 오히려 최다(28회)였다.
문서가 스스로 "이 축은 소진됐다"고 적고 있다.

## 5. 구멍 — 손대지 않은 곳

### 5.1 위치를 파악하는 부분(AMCL)이 통째로 정석 그대로다 🔴

`nav2_params.yaml`의 AMCL 41줄에 **주석이 단 한 줄도 없다.** git 이력상 마지막
변경은 좌표계 이름 한 줄뿐(2026-07-03)이고 나머지는 Nav2 샘플 그대로다.

**그런데 이 부분이 낸 사고가 기록돼 있다.**

- **실제 로봇이 AMCL이 믿은 곳보다 26~30 cm 멀리 있었다** (`devlog/2026-07-31.md:14-48`)
- **자기잠금** (`:53-64`):

```
자세가 틀림 → 못 움직임 → "25 cm 이상 움직여야 갱신" 조건 미달
   ↑                                              │
   └──────────────  자세가 계속 틀림  ←────────────┘
```

  이래서 20초를 갇혔다.

devlog에 개선안 4건이 이미 적혀 있는데 **아직 반영되지 않았다**:
`update_min_d/a` 0.25/0.2 → 0.10/0.10, `alpha1` 0.2 → 0.4, `max_beams` 60 → 180,
`laser_max_range 100.0` 수정.

**왜 큰 문제인가**: 지도·경로·속도를 아무리 잘 맞춰도 **"내가 어디 있는지"를 틀리면
전부 헛돈다.** costmap과 planner에는 수백 줄의 실측 주석이 붙어 있는데 위치추정만
비어 있다.

### 5.2 최후의 정지 장치가 없다

`nav2_collision_monitor`(장애물 감시 전용 노드)를 안 쓴다. 2026-07-29에 검토 후
기각했는데, 그때 근거는 "속도만 줄이고 방향을 못 바꾼다"였고 당시 목표는
"장애물에서 떨어져 가기"였다. 지금 필요한 건 **최후 정지**라 조건이 달라졌다.

현재 저지선은 둘뿐이다:
1. DWB의 `ObstacleFootprint` — 4.1의 사각지대도 이게 막고 있다
2. `vica_safety`의 E-stop·속도 클램프

### 5.3 기동 시 위치 초기화 코드가 dev에 없다

운영 매뉴얼은 `⑨-1 위치 자동 초기화` 단계를 요구하는데, 그 코드는
`feat/home-return` 브랜치에만 있다. dev로 운용하면 여전히 RViz에서 손으로 찍어야
한다. 5.1의 사고와 직결된다.

### 5.4 각도를 알려주는 센서가 없다

EKF에 들어가는 두 입력이 **모두 각'속도'만** 준다(바퀴 엔코더, 자이로).
각도 자체를 주는 입력이 하나도 없어서 **yaw는 순수 적분**이고, 이를 되돌리는 건
AMCL뿐이다. 5.1과 겹쳐 위험이 배가된다.

### 5.5 안전 속도 상한이 사실상 없는 것과 같다

```
Safety가 막는 상한 : 1.0 m/s, 2.0 rad/s
실제 주행 상한     : 0.26 m/s, 0.4 rad/s
```

**3.8배 / 5배 느슨**하다. 폭주만 막고 일상적인 속도 제한 역할은 못 한다.
근거 주석도 없다.

### 5.6 근거가 없는 값들

이번 점검에서 아래 값들에 **근거 주석이 전혀 없음**을 확인하고, 해당 위치에
`[근거 없음]` 표식을 달았다(값은 그대로).

| 값 | 상태 |
| --- | --- |
| `local_costmap 6×6` (정석 3×3) | 무주석. 셀 수가 정석의 4배 |
| 센서 범위 4종 (`obstacle/raytrace × min/max`) | 무주석 |
| `mark_threshold: 1` (정석 0) | 무주석 |
| `expected_update_rate: 0.2`, `inf_is_valid: true` | 무주석 |
| `rotation_penalty: 5.0` | "Lattice의 주 노브"라 적어 두고 **한 번도 안 돌려봄** |
| `cost_scaling_factor: 3.5` | 정성적 한 줄만, 날짜·실측 없음 |
| `planner tolerance: 0.2` (정석 0.5) | 무주석 |
