## 0. 한 줄 요약

**조사만 했고 코드·설정은 하나도 바꾸지 않았다. 실기 시험도 실행하지 않았다.**

- nvblox는 **객체 인식을 하지 않는다.** static / dynamic / people 세 모드의 차이는
  "두 지도를 무엇을 기준으로 나누느냐"이며, 이름과 달리 dynamic 모드에도 DNN이 없다.
- VICA 가 `mapping_type: dynamic` 에서 3회 실패한 기전이 **nvblox 소스 주석으로 설명된다.**
  같은 약점이 people 모드에는 **구조적으로 없다.** people 모드는 아직 한 번도 시험되지 않았다.
- 2026-08-12 주행에서 동적 장애물 회피 실패 2건이 보고됐다. 관여 파라미터를 전수로
  짚었으나 **원인은 확정하지 않았다.** 원인을 가르는 관찰 하나를 §7 에 남긴다.

## 2. nvblox 세 모드 — 소스 수준 확정

### 2.1 공통 구조: 지도는 항상 두 개다

`MultiMapper` 가 mapper 두 개로 구성된다 (`multi_mapper.h`).

```
background mapper : 정적 물체 (TSDF 또는 occupancy)
foreground mapper : 동적 물체 또는 사람 (occupancy)
```

`ImageMasker` 가 들어온 depth 이미지를 마스크로 쪼개 두 mapper 에 나눠 넣는다.
**모드의 차이는 이 마스크를 누가 만드느냐 하나다.**

### 2.2 `MappingType` 전체 (소스 원문)

```cpp
enum class MappingType {
  kStaticTsdf,               /// only static tsdf
  kStaticOccupancy,          /// only static occupancy
  kDynamic,                  /// static tsdf (incl. freespace) and dynamic occupancy
  kHumanWithStaticTsdf,      /// static tsdf and human occupancy
  kHumanWithStaticOccupancy  /// static occupancy and human occupancy
};
```

ROS 파라미터 문자열 (`mapper_initialization.cpp`):
`static_tsdf` / `static_occupancy` / `dynamic` / `human_with_static_tsdf` /
`human_with_static_occupancy`

### 2.3 세 모드 비교

| | `static_tsdf` | `dynamic` | `human_with_static_tsdf` |
| --- | --- | --- | --- |
| 마스크 생성자 | 없음 | nvblox 자신(`DynamicsDetection`) | 외부 DNN(PeopleSemSegNet) |
| **DNN** | **없음** | **없음** | **필요** |
| background | TSDF | TSDF + **freespace layer** | TSDF |
| foreground | **`kNone` — 꺼짐** | occupancy | occupancy |
| 실행 노드 | `nvblox_node` | `nvblox_node` | **`nvblox_human_node`** |
| 망각 노브 | 1개 | 2개 | 2개 |
| slice 토픽 | `static_map_slice` | `static`+`dynamic`+`combined` | `static`+`combined` |

`findForegroundLayerType(kStaticTsdf)` 가 `ProjectiveLayerType::kNone` 을 돌려준다.
**현재 VICA 는 `static_tsdf` 이므로 `vica_nvblox_overrides.yaml` 의 `dynamic_mapper:`
블록(`occupied_region_decay_probability` 등)은 아무 효과가 없다.** 되돌리기용으로
남겨둔 값이며, 지금 그 값을 만져도 거동은 바뀌지 않는다.

### 2.4 dynamic 모드가 VICA 에서 3회 실패한 기전

`multi_mapper.h` 개발자 주석 원문 요지:

> dynamic mapping 에서는 **전체 depth 이미지가 background mapper 에 통째로 들어간다
> (마스킹 없음).** 그러지 않으면 freespace 를 리셋할 수 없기 때문이다 — freespace 에
> 떨어지는 depth 측정값은 DynamicsDetection 이 항상 dynamic 으로 마스킹해버린다.
> 그 대신 background mapper 의 esdf site 중 freespace 에 떨어지는 것을 무시한다.

**즉 dynamic 모드는 사람을 static 지도에서 빼주지 않는다.** 사람이 foreground 에도
들어가고 background 에도 들어간다. 이것이 `vica_nvblox_overrides.yaml` 주석에 기록된
실측을 설명한다.

| | `static_tsdf` | `dynamic` |
| --- | --- | --- |
| local costmap lethal | 10.7 % | **21.2 %** |
| inscribed | 26.4 % | **46.4 %** |
| 4구간 완주 | **3/3** (145.6 s) | 1/3 |

팀이 실측으로 도달한 결론("static 과 dynamic 이 같은 물체를 각자 잡아 합쳐진다")과
소스가 일치한다.

### 2.5 people 모드는 이 약점이 구조적으로 없다

`integrateDepth(depth_frame, mask, ...)` 오버로드가 `ImageMasker` 로 depth 를 쪼개
각 mapper 에 **따로** 넣는다. 사람은 static 지도에 처음부터 들어가지 않는다.

**people 모드는 VICA 에서 한 번도 시험된 적이 없다.** dynamic 3회 실패를 근거로
people 을 배제하면 안 된다. 실패 기전이 다르다.

단, 도입 시 새로 지는 비용:
- `isaac_ros_unet` + PeopleSemSegNet 이 **주행 중 상시** GPU 를 쓴다. Jetson 은 경량
  `PeopleSemSegNet_ShuffleSeg` 권장.
- launch 의 `executable="nvblox_node"` 를 `nvblox_human_node` 로 바꿔야 한다
  (`vica_nvblox.launch.py:63`).
- **핸들을 잡은 이용자 본인이 상시 검출된다.** `docs/nav2_backlog.md` §9 의
  "후방 Collision Monitor 상시 발동"과 같은 함정이다.

## 3. YOLO 도입 경로 3안

### A. Isaac ROS — 현 스택과 같은 컨테이너

`isaac_ros_object_detection` 이 `isaac_ros_yolov8`, `isaac_ros_rtdetr`,
`isaac_ros_detectnet`, `isaac_ros_grounding_dino` 를 제공한다.
파이프라인은 `encoder → TensorRT → decoder` 3단, 입력은 `/image` + `/camera_info`.

release-3.2 README 의 Orin NX 실측:

| 모델 | 입력 | AGX Orin | **Orin NX** |
| --- | --- | --- | --- |
| RT-DETR | 720p | 56.5 fps | **33.3 fps** |
| DetectNet | 544p | 55.4 fps | **25.7 fps** |

(YOLOv8 수치는 NVIDIA 가 싣지 않았다.)

장점: NITROS zero-copy, 이미 상시 가동 중인 컨테이너 안. 라이선스 부담 없음.

### B. Ultralytics + TensorRT — Hiwonder ROSOrin 방식

Hiwonder ROSOrin 은 **YOLOv11 + MediaPipe + OpenCV** 조합으로 광고한다.
(제품 페이지가 동적 렌더링이라 원문 사양표는 확인하지 못했다. RobotShop 은 403.)

Ultralytics 공식 Jetson 가이드의 **Orin NX 16GB** 벤치마크:

| 포맷 | 추론 시간 | 추정 FPS |
| --- | --- | --- |
| PyTorch | 13.90 ms | ~72 |
| TensorRT FP32 | 7.01 ms | ~143 |
| **TensorRT FP16** | **4.13 ms** | **~242** |
| TensorRT INT8 | 3.49 ms | ~286 (mAP 0.4789→0.4489) |

Orin NX 는 **DLA 코어 2개(614 MHz)** 가 있어 `device="dla:0"` 로 GPU 를 비켜갈 수 있다.
GPU 가 이미 붐비는 VICA 에서 실질적인 카드다.

ROS 2 연동은 `mgonzs13/yolo_ros` 가 가장 활발하고, **depth 로 2D bbox 를 잘라
3D bbox 를 만들어 `/yolo/detections_3d` 로 발행한다.** A 안에는 없는 기능이다.

⚠ **라이선스**: Ultralytics YOLOv8/v11 은 **AGPL-3.0**. 상용 배포 시 소스 공개 의무
또는 상용 라이선스 구매가 필요하다. 사용자 판단은 현재 "아직 모름"이다.

### C. nvblox people segmentation — 목적이 회피라면

§2.5 참고. 이미 완성된 nvblox → Nav2 costmap 배선을 그대로 쓴다.

## 4. YOLO bbox 를 nvblox 에 되먹이는 경로 `[3.2 미확인]`

`MultiMapper` 에 세그멘테이션 마스크 대신 **bounding box 를 받는 오버로드**가 있다.

```cpp
void integrateDepth(const DepthImage& depth_frame,
                    const std::vector<ImageBoundingBox>& detection_boxes,
                    const Transform& T_L_CD, const Transform& T_CM_CD,
                    const Camera& depth_camera,
                    const Camera& detection_boxes_camera);
```

`nvblox/semantics/mask_from_detections.h` 가 bbox 를 마스크로 바꾼다. 즉 YOLO 검출
결과를 foreground mapper 에 직접 먹일 수 있고, 사람만이 아니라 YOLO 가 아는 클래스라면
무엇이든 동적 취급이 가능해진다.

단서 두 개:
- **컬러 쪽 오버로드에는 "현재 detection box 는 무시되고 컬러 프레임 전체가 static map 에
  들어간다"는 주석이 있다.** 유효한 것은 depth 경로다.
- **이 API 가 release-3.2 에 있는지 Jetson 에서 확인해야 한다.**

## 6. 2026-08-12 주행 증상 2건 — 파라미터 관여 지도

### 6.1 증상 (사용자 보고)

1. **약 1.5~2 m 밖 원거리**에서 동적 장애물을 발견하면 서서 못 움직인다.
2. 동적 장애물이 **사라져도 약 10초 이상** 서 있다가 다시 출발한다.

동영상 2건이 있으나 노트북에 `ffmpeg` 가 없어 이번 세션에서는 열지 못했다.

### 6.2 범위를 좁히는 사실

`nav2_params.yaml:415` 주석의 계산:

> DWB 가 실제로 검사하는 거리 = `sim_time` 2.5 × `max_vel_x` 0.26 + footprint 앞단 0.355
> = **1.01 m**

**DWB 의 시야는 약 1 m다. 1.5~2 m 밖에서 멈춘다면 DWB(지역 컨트롤러)가 아니라
global planner / costmap / BT 쪽이다.**

### 6.3 증상 1 관여 파라미터

**nvblox — 무엇을 장애물로 올리나**

| 파라미터 | 현재값 |
| --- | --- |
| `mapping_type` | `static_tsdf` (사람이 정적 지도에 쌓인다) |
| `esdf_slice_min_height` | 0.05 |
| `esdf_slice_max_height` | 0.9 (사람 전신이 밴드에 들어온다) |

**costmap — 얼마나 넓게 막나** ← 1.5~2 m 를 만드는 유력 지점

| 파라미터 | 현재값 | 위치 |
| --- | --- | --- |
| `nvblox_layer.convert_to_binary_costmap` | **True** | `nav2_params.yaml:662` |
| `inflation_radius` | **0.55** | `:907`(local), `:1076`(global) |
| `cost_scaling_factor` | 3.5 | `:795`, `:1039` |
| `footprint` | 0.9 × 0.455 m (외접반경 ≈ 0.637) | `:487` |
| `footprint_padding` | 0.05 | `:621` |
| global 의 `nvblox_layer` | 있음 (2026-07-30 투입) | `:927` |

거리 합산:

```
사람 LETHAL 셀
  + inflation_radius            0.55
  + 로봇 외접반경 0.637 + padding 0.05
  ≈ 1.24 m   (로봇 중심 기준 진입 불가 반경)
```

**통로 폭 1.0 m** 와 겹치면 planner 가 물리적으로 경로를 만들 수 없다.

**BT — 경로 실패 후 무엇이 도나**
`RateController hz="1.0"`, `RecoveryNode number_of_retries="6"`

### 6.4 증상 2 관여 파라미터 — 두 개가 겹친다

**A. BT 복구 시퀀스 ← 가장 유력**

현재 launch 가 쓰는 트리는 `vica_navigate_to_pose_no_backup.xml`
(`nav2_map_test.launch.py:49`). RoundRobin 이 자식 4개를 순환한다.

```
ClearingActions → SpinLeft(+0.30) → SpinRight(-0.30) → Wait(5초)
```

- `<Wait wait_duration="5"/>` — `no_backup.xml:98`. **5초 통째로 정지**
- `Spin spin_dist="0.30"` — 각 0.75초 (`max_rotational_vel: 0.4`)
- 6회 순환 시 Spin 3회 + Wait 1회

같은 저장소 `vica_navigate_to_pose_clearing_only.xml` 주석의 **실측**:

> 최장정지 **19.4 s** — Spin 3회가 만든 시간이다
> `<Wait/>` 실패를 시간으로 덮는다. **종전 복구 시간의 79 %가 이것이었다.**

**장애물이 사라진 것과 무관하게 Wait 는 5초를 채운다.**

**B. nvblox 망각 — 겹쳐서 작용**

| 파라미터 | 현재값 |
| --- | --- |
| `decay_tsdf_rate_hz` | 2.5 |
| `tsdf_decay_factor` | 0.95 |
| `esdf_integrator_min_weight` | 0.1 |
| `exclude_last_view_from_decay` | false (2026-07-30 수정 완료) |

```
5.0 × 0.95ⁿ ≤ 0.1  →  n = 76 tick  →  76 / 2.5 Hz = 30.6 초
```

LiDAR 는 raytrace 로 즉시 지우지만 **nvblox slice 는 최대 30.6초를 기다린다.**

**C. costmap 갱신**: local `update_frequency: 5.0`, `publish_frequency: 2.0` (최대 0.5초 추가)

### 6.5 선행 문서와의 연결 — 중요

`devlog/2026-07-30-nvblox-ghost-obstacle.md` §4.1 의 기하 계산이 증상 1 에 직접 걸린다.

```
카메라 높이 0.320 m, 틸트 없음(rpy "0 0 0")
D455 수직 FOV 58° → 반각 29°, tan = 0.554
거리 d 에서 보는 높이 = 0.320 ± 0.554 × d
```

**가까이 갈수록 사람의 상체가 시야에서 빠진다.** 그 문서는 `inflation_radius` 0.45 로
계산했다. 현재 값 0.55 로 다시 계산하면:

```
정지 시 로봇 중심~장애물 = footprint 전방 0.305 + inflation 0.55 = 0.855 m
카메라는 중심보다 0.287 m 앞  →  카메라~장애물 ≈ 0.568 m
0.568 m 에서 관측 가능 높이 = 0.320 ± 0.315 = 0.005 ~ 0.635 m
→ slice 밴드 0.05~0.9 중 0.635~0.9 (약 30 %)가 사각지대
```

즉 **로봇이 멈춘 위치에서는 사람 상체 높이를 카메라로 볼 수 없어, 이미 쌓인 것을
관측으로 덮어쓸 수 없다.** 지우는 길은 decay(30.6초)만 남는다.

`exclude_last_view_from_decay: false` 수정 이후에도 증상이 보고됐다는 점이
이 문서의 새 정보다. 그 수정은 "시야 안 유령이 영구히 남는 것"을 30.6초로 바꾼
것이지 없앤 것이 아니다.

## 8. ⚠️ 하지 말 것

- **원인 확정 전에 값을 바꾸지 말 것.** `mapping_type` 을 4회 왕복한 이력이 있고, 그때
  원인이 아니었던 값을 바꾸느라 시간을 썼다. 진짜 원인은
  `exclude_last_view_from_decay` 였다.
- **한 번에 하나만 바꿀 것.** 두 개를 같이 바꾸면 무엇이 들었는지 가릴 수 없다.
- `inflation_radius` 를 **0.50 이하로 내리지 말 것** — `nav2_backlog.md` §9, 사용자 판정.
- **baseline 을 잃지 말 것** — 유일하게 3/3 완주한 조합은
  `static_tsdf` + 두 costmap 모두 `static_map_slice` + scale 0.15 + decay 2.5 (145.6 s).
- dynamic 3회 실패를 근거로 **people 모드를 배제하지 말 것** (§2.5).

원인이 갈린 뒤의 첫 후보만 적어 둔다.

| 확정된 원인 | 첫 후보 | 파일 |
| --- | --- | --- |
| BT Wait/Spin 이 시간을 만듦 | `wait_duration="5"` | `behavior_trees/vica_navigate_to_pose_no_backup.xml:98` |
| planner 가 경로를 못 만듦 | `inflation_radius: 0.55` | `nav2_params.yaml:907`, `:1076` |
| 사라진 사람이 안 지워짐 | `decay_tsdf_rate_hz: 2.5` | `vica_nvblox_overrides.yaml` |

## 9. 미결 — 다음 세션이 판단할 것

1. **증상 1·2 의 원인** — §7 관찰 결과 대기. 미확정.
2. **people 모드를 시험할 것인가** — 미시험. 구조적으로 dynamic 과 다르다(§2.5).
   비용은 unet 상시 GPU + 이용자 오검출.
3. **YOLO 도입 경로 A/B/C** — 라이선스 판단("아직 모름")이 A/B 를 가른다.

5. **E-stop 후 상황 설명 기능** — 브레인스토밍 §범위까지만 합의됐다.
   "설명 계층만 설계하고 근접 긴급정지는 후속 방향으로만 남긴다"가 사용자 결정.
   발화 내용(원인 포함 여부 / 거리 포함 여부)은 미결. 설계 미착수.
   - 확인된 배선: `/estop_state`(Bool, 구독 전용 패턴 확립),
     `/vica/tts_request`(String, `"{priority}:{text}"`, emergency/response/narration)
   - 공백: `EmergencyLatch.active_sources` 가 원인을 구분하지만 밖으로 나가는 것은
     `/emergency_stop`·`/estop_state` **Bool 둘뿐**이다. 원인을 말하려면 인터페이스가 필요하다.
   - **근접 사람 감지로 인한 긴급정지는 현재 존재하지 않는다.** `vica_safety` 에 거리·
     `scan` 판정 코드가 없다. E-stop 원인은 물리 버튼·앱·STT 긴급어·motor CAN 넷뿐이다.
     도입하려면 `NAV2-B5`(collision_monitor)와 §9 의 이용자 상시 발동 문제를 함께 풀어야 한다.
