## 1. 왜 기우는가, 왜 yaml 로는 못 고치나

- Cartographer 는 '매핑 시작' 순간 로봇(`tracking_frame = base_footprint`, `config/vica_2d.lua`)이
  본 방향을 map +x 로 잡는다. 시작한 뒤 어디로 가든 축은 그대로다.
- 저장된 지도 6장 실측(이 코드가 내는 값, 반시계 양수): map_1006_150446 +5.4° · vica_map_0910 −5.4° ·
  vica_map_0903_d −4.5° · vica_map_0630 +1.6° · map_1002_150946 +0.9° · vica_map_0817 −0.9°.
- yaml `origin` 의 yaw 는 Nav2 costmap static_layer 가 버린다(humble `processMap` 은 x·y 만 읽음).
  Cartographer `StartTrajectory` 의 `initial_pose` 는 기존 궤적 기준이라 첫 궤적에 못 쓴다.
  → 그림 자체를 돌리고 origin x·y 를 다시 계산한다.

## 4. 회전이 안전한지 — 숫자

지도 6장을 실제 코드로 돌려 원본과 비교했다(내접 반경 0.277 m 기준 '지나갈 수 있는 칸').

| 지도 | 기울기 | 돌린 뒤 남은 | 통과 면적 변화 | 큰 구역 | 벽까지 거리 변화 중앙 / p5 / 최소 |
|---|---|---|---|---|---|
| map_1002_150946 | +0.95° | −0.32° | −0.13 % | 1→1 | 0 / −3.2 / −5.0 cm |
| map_1006_150446 | +5.37° | +0.13° | −0.13 % | 1→1 | −0.4 / −3.9 / −7.1 cm |
| vica_map_0630 | +1.55° | −0.17° | −0.14 % | 1→1 | 0 / −2.4 / −7.1 cm |
| vica_map_0817 | −0.95° | +0.05° | −0.11 % | 1→1 | 0 / −2.9 / −5.0 cm |
| vica_map_0903_d | −4.45° | +0.10° | −0.30 % | 1→1 | 0 / −4.0 / −7.1 cm |
| vica_map_0910 | −5.40° | 0.00° | −0.37 % | 2→2 | 0 / −3.9 / −7.1 cm |

(2° 문턱이 있으므로 실제로 돌아가는 것은 1006·0903_d·0910 셋뿐이다. 표는 비교를 위해 전부 돌린 값.)

- **같은 벽이 같은 실제 좌표에 남는다.** 원본 벽칸을 새 좌표로 옮긴 자리에서 새 지도의 가장
  가까운 벽까지 거리 중앙값 0 cm(1006·0903_d 검산, scipy 거리변환). origin 계산이 맞다는 뜻이다.
- 최소 −7.1 cm 는 칸 중심끼리 잰 대각선 한 칸이다. 실제 벽 이동은 이론상 칸 대각선의 절반
  (3.5 cm) 이하다.
- **원본 벽칸 찍기(splat)를 넣은 이유:** 역매핑만 하면 0903_d 의 한 칸짜리 외딴 장애물 94개 중
  1개가 사라졌다. 찍기를 넣은 뒤 통과 면적 감소가 −0.1~0.2 % → −0.1~0.4 % 로 조금 늘었지만,
  장애물을 잃는 것보다 낫다고 판단했다.
- **closing 은 두 칸(10 cm) 이하 틈까지 메우고 지도 전체에 걸린다**(처음엔 '한 칸 틈'이라고 적었다가
  검토에서 바로잡음). 10 cm 틈은 내접 반경 안이라 원래도 inflation 이 막던 자리이고, 빈칸 감소는
  −0.02~−0.05 % 다. 찍기 때문에 벽이 군데군데 한 칸 두꺼워진다(벽칸 약 +1.5 %).
- 벽 1칸 팽창은 쓰지 않았다(10-07 시뮬레이션: 벽 5~6 cm 다가옴, 통과 −2~7 %, 0903_d 통로 닫힘).
- 측정: 저장된 지도의 '가장 잘 맞는 각도 점수 / 전체 중앙값' 은 2.7~5.1, 무작위 점 1.06~1.11,
  원 1.00. 문턱 1.5 아래면 '못 잼'. 벽칸 150개(7.5 m) 미만도 '못 잼'.
- 젯슨 계산 시간: 측정 한 번 7~27 ms(여러 번 잰 범위)(미리보기 2초마다 → 코어 1 % 남짓), 회전 저장은 가장 큰
  0903_d(1 MB)도 0.3 s(파이썬 기동 포함).
- 큰 지도 대비(검토 중간 2건): 측정은 벽칸 8000개 상한(0910 을 3배로 키운 5.7만 칸: 144 → 45 ms,
  각도 −5.40 → −5.38°), 회전은 줄 묶음 계산(0910 최대 메모리 68.8 → 16.1 MB, 1100만 칸 그림 120 MB·0.5 s).
- 평평한 꼭대기 처리: 짧은 벽은 ±0.4° 안에서 점수가 같아, 첫 값을 고르면 반듯한 방도 −0.4° 로
  읽혔다(시험이 잡음). 꼭대기 가운데를 쓰도록 고쳤다.

## 7. 실기 전 할 일·남은 것

1. **세 곳을 같이 올린다**: `vica_interfaces`(align 칸)·매핑 감독 노드·루트 `scripts/vica_map_save.sh`.
   interfaces 만 옛 빌드면 '정렬해서 저장'이 rosbridge 오류로 거부되고, 감독 노드나 스크립트만 옛것이면
   오류 없이 정렬만 안 되거나(옛 스크립트는 `--align` 을 무시) 결과 줄이 안 뜬다.
   젯슨: `colcon build --packages-select vica_interfaces vica_cartographer` (이번에 해 둠) →
   매핑 감독·미리보기·rosbridge(⑪ app 칸)·`map_list_node` 재기동. 인터페이스가 바뀌어 rosbridge 도
   다시 띄워야 새 칸을 안다.
2. 앱 다시 굽기(폰 APK·웹).
3. 확인 항목 [미검증]:
   - 매핑 시작 직후 로봇 화살표가 화면 **오른쪽**을 가리키는가(시작 방향 안내가 맞는지)
   - 팝업 '지금 기울기' 값과 완료 결과 값이 비슷한가
   - 돌린 지도로 Nav2 를 띄워 AMCL 레이저가 벽에 겹치는가, 좁은 곳 경로·global costmap 띠
   - 장소 4방향(정면 90°·우측 0°…)이 복도와 나란한가
4. 이미 등록을 마친 지도(map_1006_150446 등)는 **건드리지 않는다(사용자 결정)**. 변환 도구도 만들지
   않는다. 이번 기능은 앞으로 새로 저장하는 지도에만 쓴다.
5. `maps/.original/` 은 커밋하지 않는다(사용자 결정). `vica_ros2_ws/.gitignore` 에 넣었다.
6. 터미네이터의 지도 저장 칸 명령(`vica_map_save.sh vica_map_$(date +%m%d)`)은 `--align` 없이
   그대로라 예전처럼 저장하고 기울기만 출력한다.
