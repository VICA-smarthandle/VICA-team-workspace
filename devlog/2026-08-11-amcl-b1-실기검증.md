## 1. 무엇을 바꿨나

| 파라미터 | 이전 | 이후 | 한 줄 |
| --- | --- | --- | --- |
| `update_min_d` | 0.25 | **0.10** | 갱신에 필요한 이동 거리 |
| `update_min_a` | 0.2 | **0.10** | 갱신에 필요한 회전각 (11.5° → 5.7°) |
| `max_beams` | 60 | **180** | 한 스캔에서 쓰는 표본 수 (14.5 % → 43 %) |
| `alpha1` | 0.2 | **0.4** | 회전 → 회전 잡음 |

손대지 않은 것: `transform_tolerance`(1.0), `laser_max_range`(100.0),
`recovery_alpha_slow/fast`(0.0). 이유는 `nav2_params.yaml` 해당 자리 주석에 있다.

### 고치려는 사고

`devlog/2026-07-31.md:52-64`. AMCL 추정이 t+77.6 ~ 85.6 동안 `(1.837, 3.848, 94.4°)`로
**소수점까지 고정**됐고 20초를 갇혔다. 그때 실제 로봇은 26~30 cm 떨어진 곳에 있었다.

```
자세가 틀림 → 못 움직임 → 갱신 문턱 미달 → 자세가 계속 틀림
```

문턱(25 cm)이 고쳐야 할 오차(30 cm)보다 컸다. **갇힐수록 눈을 감는 구조**였다.

## 2. 이 검증은 2026-08-09 검증과 성격이 다르다

`2026-08-09-nav2-생존판정-실기검증.md`는 *"이 노드는 모터를 세우지 않는다"*를 전제로
로봇을 주행시키지 않았다. **이번은 다르다.**

- AMCL은 `map → odom` 변환의 소유자다. 이 변환이 costmap 정렬과 planner 경로를 정한다.
- 갱신이 잦아지면 **보정도 잦아진다.** 큰 보정이 가끔 오던 것이 작은 보정이 자주 오는
  쪽으로 바뀌는 것이 의도지만, **그 반대가 나올 가능성을 배제한 상태가 아니다.**
- `max_beams` 3배는 CPU 3배다. 제어주기를 놓치면 그 자체가 주행 품질 저하다.

그래서 **정지 → 바퀴 띄움 → 통제 구역 주행** 순으로 나눠 올라간다. 앞 단계가 통과하지
못하면 다음으로 가지 않는다.

### 부수 기회 — D4를 처음 잴 수 있다

`docs/nav2_backlog.md` §8 **D4**(정지 상태 AMCL 점프 15 cm / 10.8°)는 *빈도와 크기가
미측정*이라 미해결로 남아 있다. 갱신이 잦아지면 이 현상이 더 자주 드러난다.
**이번 시험이 D4를 처음 정량화할 기회**다(6절 A-3, 8절 C-3).

## 5. 관찰 창

터미널 넷을 띄워 두고 시험 내내 지켜본다.

```bash
# 창 1 — 위치추정 갱신이 실제로 일어나는가
ros2 topic hz /amcl_pose

# 창 2 — 추정 위치. 이 값이 얼어붙는 것이 사고의 모양이다
ros2 topic echo /amcl_pose --field pose.pose.position.x

# 창 3 — CPU. max_beams 3배의 대가가 여기 나온다
top -d 1 -p $(pgrep -d, -f "amcl|controller_server|nvblox")

# 창 4 — 로그
ros2 run rqt_console rqt_console
```

**얼어붙음을 세는 한 줄.** 60초를 보고 같은 값이 연속으로 몇 번 이어졌는지 센다.

```bash
timeout 60 ros2 topic echo /amcl_pose --field pose.pose.position.x 2>/dev/null \
  | awk '{ if ($1==p) n++; else { if (n>m) { m=n; v=p }; n=1; p=$1 } }
         END { print "최장 연속 동일값:", m, "회   값:", v }'
```

창 1의 Hz로 나누면 초가 된다. 예: 20 Hz에서 160회 = 8초.

> 얼어붙음은 **두 가지 모양**으로 나온다 — 같은 값이 반복되거나, 발행이 아예 끊기거나.
> 창 1과 창 2를 함께 봐야 둘 다 잡힌다.

## 6. 단계 A — 바퀴를 띄우지 않는다 (로봇 정지)

여기서 걸리면 8절로 가지 않는다.

### A-1. 값이 실제로 로드됐는가

```bash
ros2 param get /amcl update_min_d      # 0.1
ros2 param get /amcl update_min_a      # 0.1
ros2 param get /amcl max_beams         # 180
ros2 param get /amcl alpha1            # 0.4
ros2 param get /amcl transform_tolerance   # 1.0 (안 바꿨다)
```

**하나라도 옛 값이면 여기서 멈춘다.** launch가 다른 params 파일을 읽고 있다는 뜻이고,
그 상태로 아래를 재면 전부 무의미하다.

### A-2. `/scan`의 실제 `range_max` — 1줄, 비용 없음

```bash
ros2 topic echo /scan --field range_max --once
```

백로그 §1이 오래 `[미확인]`으로 달고 있던 값이다. **이 값을 10절 표에 적는 것이 이번
검증의 부수 산출물이다.**

판정:

| 결과 | 조치 |
| --- | --- |
| 8~16 m 정도 (RPLIDAR 정상) | `laser_max_range: 100.0` 그대로 둔다. `min()` clamp로 이 값이 쓰인다 |
| 0 이거나 비정상적으로 큼 | 드라이버가 필드를 안 채운다. **이때는 `laser_max_range`를 실측 유효 거리로 내려야 한다** |

### A-3. 정지 상태에서 갱신이 걸리는가 — D4 1차 관측

로봇을 세워 둔 채 정지 상태 갱신을 강제한다.

```bash
# 강제 전 자세
ros2 topic echo /amcl_pose --once > /tmp/before.yaml

ros2 service call /request_nomotion_update std_srvs/srv/Empty

# 강제 후 자세
ros2 topic echo /amcl_pose --once > /tmp/after.yaml
diff /tmp/before.yaml /tmp/after.yaml
```

- **공분산이 줄었는가** — `covariance[0]`, `[7]`, `[35]`가 작아지면 측정이 반영됐다
- **위치가 얼마나 튀었는가** — 이것이 D4다. 정지해 있는데 15 cm 튀면 그 크기를 적는다

5회 반복해 **점프 크기의 최대·중앙값**을 10절에 적는다. 미측정으로 남아 있던
D4의 첫 수치가 된다.

### A-4. CPU 1차 — 정지 상태 바닥값

`max_beams` 180이 얹힌 상태에서 AMCL 프로세스의 CPU를 창 3에서 읽는다. 주행 중이 아니므로
이건 **바닥값**이고, 7절과 비교할 기준선이다.

| 관측 | 기록할 것 |
| --- | --- |
| `amcl` %CPU | 정지 시 바닥값 |
| `nvblox` %CPU | 경합 상대. 함께 적어야 해석이 된다 |

## 8. 단계 C — 통제 구역 주행 (핵심)

3절 안전 조건을 다시 확인한다. 이 단계가 이 검증의 본체다.

### C-1. 기록 시작

```bash
ros2 bag record -o ~/vica_data/bags/amcl_b1_$(date +%m%d_%H%M) \
  /amcl_pose /scan /odom /wheel/odom /cmd_vel_nav /cmd_vel_req /cmd_vel_safe \

```

`/wheel/odom`을 반드시 넣는다. **"바퀴가 한 번도 안 돌았는데 값만 나온" 사고**가 있었다
(`devlog/2026-07-30-gpu-nvblox-stt-contention.md:171-172`).

왕복 주행은 기존 스크립트를 쓴다.

```bash
python3 ~/vica_data/analysis/run_test.py amcl_b1_<날짜> 화장실 방2 화장실 안내소
```

### C-2. 자기잠금 재현 시험 — **이것이 판정이다**

성공을 재는 것이 아니라 **사고가 재현되지 않는지**를 잰다.

1. 로봇을 **일부러 20~30 cm 어긋난 자세**로 둔다 (RViz로 `2D Pose Estimate`를 실제
   위치에서 그만큼 밀어서 지정)
2. 좁은 구간(최협 통로 폭 1.0 m)으로 진입시킨다
3. 창 2와 5절의 awk 한 줄로 `/amcl_pose`를 지켜본다

| | 고치기 전 (2026-07-31 실측) | 고친 뒤 (기대) |
| --- | --- | --- |
| `/amcl_pose` 최장 동결 | **8.0 초** (소수점까지 동일) | **3초 미만** |
| 갇힘 지속 | 20 초 | 짧아지거나 없음 |
| 어긋남이 줄어드는가 | 안 줄어듦 | 주행하며 수렴 |

> **판정 기준을 "완주했는가"로 두지 않는 이유.** 완주는 복구 동작(Spin·Wait·costmap
> 초기화)이 흡수해 줄 수 있다. 7월 31일 기록이 "8초간 소수점까지 동일"이라는 형태로
> 남아 있으므로, 같은 형태로 재야 전후 비교가 성립한다.

### C-3. D4 빈도 — 주행 중

bag에서 **정지 구간**(`/cmd_vel_safe`의 vx·wz가 0인 구간)을 골라 그 안에서 `/amcl_pose`가
얼마나 튀는지 센다. A-3이 강제 갱신 1회의 크기라면, 이쪽은 **자연 빈도**다.

### C-4. 주행 품질이 나빠지지 않았는가

AMCL 보정이 잦아지면 costmap이 더 자주 미끄러진다. 그 부작용이 나오는지 본다.

| 볼 것 | 나쁜 신호 |

| `/cmd_vel_nav`의 흔들림 | 이전 주행보다 좌우 진동이 늘었다 |
| DWB `No valid trajectories` | 횟수가 늘었다 |

## 11. 되돌리는 순서

전부 되돌리지 않는다. **CPU가 원인이면 `max_beams`부터**, 거동이 불안하면 `alpha1`부터다.
갱신 문턱은 유일하게 사고 기록이 있는 항목이라 마지막까지 지킨다.

| 순서 | 값 | 되돌릴 조건 |
| --- | --- | --- |
| 1 | `max_beams` 180 → **120** → 60 | 제어주기 놓침이 늘었다 |
| 2 | `alpha1` 0.4 → **0.3** → 0.2 | 입자가 과도하게 퍼져 위치가 튄다 |
| 3 | `update_min_a` 0.10 → 0.15 | 위 둘로 안 풀린다 |
| 4 | `update_min_d` 0.10 → 0.15 | 〃 |

**계약 테스트가 함께 깨진다.** `test_amcl_contract.py`가 실측 수치를 상한으로 박아 뒀기
때문이다(`OBSERVED_POSE_ERROR_M`, `OBSERVED_YAW_JUMP_DEG`, `SCAN_VALID_RETURNS`).
1·2번은 상한 안이라 통과하지만 3·4번은 깨진다 — **그때 무엇을 포기하는지 시험이
말해 주는 것이 의도한 동작이다.** 되돌린다면 그 사유를 시험 주석에 함께 적는다.

전부 되돌리려면:

```bash
git checkout dev -- src/vica_nav2/config/nav2_params.yaml
colcon build --packages-select vica_nav2 --symlink-install
```

## 12. 이 검증으로 덮지 않는 것

- **`transform_tolerance` 1.0.** 이번에 손대지 않았다. 갱신이 잦아진 효과를 본 뒤
  0.3~0.5로 낮출지 판단한다(NAV2-B1 4순위). C-2 결과가 나와야 근거가 생긴다.
- **NAV2-B2 `pose_bootstrap`.** 이 변경이 B2보다 먼저인 이유는 `pose_bootstrap`이
  `/request_nomotion_update`를 5회 호출하는데, `update_min_d/a`를 낮추면 정지 상태에서도
  AMCL이 스캔을 반영하기 시작해 **그 호출의 필요성과 횟수가 달라지기 때문**이다.
  A-3이 그 답을 준다 — 강제 갱신 없이도 공분산이 수축하면 5회는 과하다.
- **NAV2-B5 Collision Monitor.** 아직 노드 자체가 없다. 설계만
  `docs/handoff_nav2_collision_monitor_and_amcl.md`에 있다.
- **`laser_max_range`.** A-2 결과가 정상 범위면 손대지 않는다.
- **D1·D2·D3·D5·D6.** 백로그 §8의 다른 미해결 항목은 이 변경과 독립이다.
