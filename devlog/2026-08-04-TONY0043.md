### 1. TTS 재생 신호 토픽 이름이 갈려 있었다 — 안전

`feat/wakeword-integration` 은 `/vica/tts_active`, `dev` 는 `/vica/tts_state` 로
**같은 일을 하는 다른 이름**을 쓰고 있었다. 병합하면 발행자와 구독자가 서로 다른
토픽을 보게 되어 **TTS 재생 중 자기 목소리 억제가 죽는다.**

로봇이 "행정지원실로 안내하겠습니다"라고 말하면 그 안의 "정지"를 자기 긴급어로
듣고 스스로 멈출 수 있다.

**결정: `/vica/tts_state` 를 정본으로 한다.** 계약 문서(`docs/ros2-interface.md`)에
등재된 이름이고, dev 구현이 모든 면에서 낫다 — 문장 단위 발행(감시 사각지대 축소),
`TAIL_SEC=0.4` 잔향 처리, 워커 스레드 + 우선순위 큐, 기동 시 상태 명시 발행.

부수 효과로 인수인계 문서의 *"dev 의 새 ros_tts_node 에 `/vica/tts_active` 발행을
재이식하라"* 는 지시가 **불필요**해졌다. dev 판을 통째로 채택하면 끝난다.
이걸로 인수인계 문서 "다음 작업 우선순위 2번(TTS 동기 재생 병목)"도 함께 해소.

### 2. SIM 도착 안내가 무음이 된다

`ros_robot_sim` 은 도착 안내를 `/vica/intent` 로 발행하고 구 TTS 노드가 그걸 읽어
재생하는 구조였다. dev 에서 TTS 입구가 `/vica/tts_request` 로 바뀌면서 **아무도 듣지
않는 경로**가 된다.

실기 Mission Manager 와 같은 입구·같은 우선순위(`narration` — `mission_logic.py` 의
`Say(text)` 와 동일)로 옮겼다. "자기 수신 루프를 막으려 intent 필드를 비우던" 우회도
불필요해져 함께 정리.

### 3. baseline 의 TTS 지표가 통째로 빈다

`ros_metrics_node` 가 `/vica/intent` 로 재생 시각을 재고 있었다. dev 에서
`/vica/intent` 는 Mission Manager 전용이 되어 TTS 와 무관해진다.

**P1-c 의 목적이 baseline 수치 확보라는 점에서 이게 가장 아팠다.** 고치지 않으면
그 칸이 비거나 틀린 값으로 채워지고, 그 위에서 병목을 판단하면 개선 방향 자체가
어긋난다.

- 요청 시각 = `/vica/tts_request`, 실제 소리 = `/vica/tts_state`
- 둘의 차이를 **큐 대기 시간(`tts_wait_sec`)** 으로 새로 잰다

추가 발견: `SpanTracker` 가 `tts_end` 하나로 상호작용을 닫고 있었는데, dev 의
문장 단위 재생에서는 **첫 문장에서 끊긴다**. 짧은 공백(≤1.5초)은 같은 재생으로 잇고
긴 공백에서만 끊도록 고쳤다 (`TTS_GAP_SEC`). 한참 뒤의 도착 안내가 앞 상호작용에
섞이지 않는 것까지 시험으로 고정했다.

### 4. 목적지 파일이 노드마다 달랐다

`vica_sim.launch.py` 가 `destinations_yaml` 을 배선하지 않아, `ros_node` 는
`~/vica_data/destinations/<map_id>/` 를, `ros_robot_sim` 은 `config/destinations.yaml`
을 읽는다. **LLM 이 고른 목적지 id 를 가상 로봇이 모르는 상태**가 되어 확인까지 해
놓고 이동이 시작되지 않는다. 시뮬레이션에서는 양쪽을 같은 파일로 맞췄다.

## 새로 발견한 저장소 간 계약 불일치

병합과 별개로 **로봇 팀과 합의가 필요한 항목**이다.

### C1. TTS 우선순위 순서가 두 저장소에서 반대다

| 위치 | 서술 |
| --- | --- |
| `vica-voice-llm/src/tts_queue.py:27` (구현) | 긴급 > **응답 > 내레이션** |
| `vica_ros2_ws/.../mission_logic.py:115` (주석) | 긴급 > **내레이션 > 응답** |

`Say()` 의 narration 사용이 6건 실재하므로 실제 영향이 있다. 안내가 대기 중일 때
사용자가 말을 걸면 구현은 답변을 먼저 내보내고, 로봇 쪽 주석은 안내가 먼저라고
기대한다. **구현 쪽이 UX상 타당해 보여 주석 정정을 제안한다.**

### C2. 안전 관련 멘트가 폐기 가능한 등급에 있다 — 안전

`MSG_NAV_FAILED`(주행 실패), `MSG_ESTOP_RELEASED`(E-stop 해제)가 `narration`
기본값으로 나간다. 큐 정원(8) 초과 시 **가장 먼저 버려지는 등급**이고 폐기 로그도
`debug` 뿐이다. 거리 안내가 밀린 상황에서 주행이 실패하면 실패 안내가 조용히
사라질 수 있다 — 눈으로 확인할 수 없는 사용자에게는 상태 오해로 직결된다.

**최소 `response` 승격을 제안한다.** 결정은 로봇 팀.

### C3. `cancel`/`pause`/`resume` 미지원

정본 `VicaIntent` 에 2026-07-27 추가됐는데 음성 파서는 여전히 4종
(`navigate`/`question`/`clarify`/`unknown`)만 만든다. `RobotState.is_paused` 도
음성 저장소는 만들지도 읽지도 않는다. 둘 다 `docs/ros2-interface.md` 에 `[GAP]`
으로 명시했다. **로봇 팀이 이미 이 값을 기대하고 있는지 확인 필요.**

### (참고) `/vica/tts_state` 의미 변경 예고

`vica_system_monitor/README.md` 에 *"`/vica/tts_state` 는 edge 에서 heartbeat 로
의미가 바뀐다"* 고 적혀 있다. 감시 억제용(재생 중 여부)과 생존 신호는 요구가 달라
용도가 갈리면 토픽을 나눠야 할 수 있다. 로봇 팀 일정 확인 필요.

   `vica_ros2_ws` 에 있다"고 문서화한 그 패키지다. 없으면 ROS 노드가 뜨지 않는다.

## 실기 발화 버그 — `vica_ros2_ws` 의 "(으)로" (오늘 수정·push)

**증상**: 안내를 시작할 때마다 "별빛관 1층 화장실**으로** 안내를 시작합니다" 로
들린다 (2026-08-04 사용자 실기 확인). 받침 없는 이름에 `으로` 가 붙는다.

**원인**: `mission_logic.py` 의 멘트가 `(으)로` 표기를 그대로 두고 `.format(name=)`
만 했다. TTS 는 괄호를 무시하고 읽는다.

```python
MSG_START   = "{name}(으)로 안내를 시작합니다."
MSG_RESUMED = "{name}(으)로 다시 출발합니다."
```

**조치**: `josa_euro()` 로 받침을 보고 `로/으로` 를 정한다. `vica-voice-llm` 의
`destination_loader._josa_euro` 와 같은 로직이며, **저장소 간 의존을 만들지 않으려고
사본을 뒀다** (`freshness.py` 사본과 같은 판단, 초안 5.1절).

호출부가 조사를 빠뜨릴 자리를 없애려고 `say_destination(template, name)` 을 거치게
했다. `.format(name=)` 만 하면 이제 `KeyError` 로 즉시 드러난다.

**회귀 검사 3건** 추가 (`test_spoken_text.py`):

- 멘트에 미해결 조사 표기(`(으)`·`(이)`·`(과)`·`(를)`)가 남아 있으면 실패
- `josa_euro` 가 받침으로 고르는지 (ㄹ 받침·받침 없음·그 밖의 받침·빈 문자열·비한글)
- 실제 목적지 이름으로 완성된 문장 고정
  ("화장실**로**", "식당**으로**", "안내센터**로**")

**검증**: `vica_mission_manager` 테스트 138개 통과. 토픽·메시지 계약 변경 없음.

**로봇 팀에 알릴 것** (승인 사항은 아니지만 같은 파일 동시 작업 시 충돌 방지용):
`mission_logic.py` 의 멘트 상수 2개와 호출부 2곳이 바뀌었다.
