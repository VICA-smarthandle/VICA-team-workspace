## 2. 확인한 것

- V자 시험은 모양으로 판정한다. 벌점 없는 옛 0903_d 레일 → 27곳 실패, 벌점 넣은 레일 → 통과.
- 0903_d 현 레일을 스케치로 되돌리면 노드 4·선 3. 다시 다듬으면 원래 레일과 **0.00 m** 차이,
  노드 59·벌점 엣지 10, 계약 시험 5종 통과. 앱에서 처음 편집을 열어도 레일이 바뀌지 않는다.
- 자동 초안(0903_d) 6.5 s, 나무형, 오류 0, 학과사무실까지 이어짐(노드 75).
- 0630 현 레일은 검사 오류 6건(벽 0.45~0.65 m, 뾰족 2) — 원래 알던 좁은 곳(repair 주석).

## 3. 실기 전 해야 할 것 (순서대로)

1. **스택을 내린다**(터미네이터 전부). 떠 있는 채로 빌드하면 쓰는 중인 라이브러리를 덮는다.
2. 빌드: `colcon build --packages-select vica_interfaces vica_nav2`
   (서비스 타입 + `PenaltyScorer` 설정·레일 파일은 설치본이 복사본).
3. 앱 APK 재빌드(노트북 x86). 브랜치 `feat/app-route-editor`.
4. 주행 레이아웃을 띄우고 ⑨ nav2 칸은 `use_route:=true` 를 붙여 실행(아래 4절).
5. ⑪ app bridge 칸 기동 로그에 `vica_route_graph 시작`·`/vica/route/draft · save · get 준비 완료`.
6. `ros2 service list | grep route` 에 `/route_server/set_route_graph`·`/vica/route/*` 가 보이는지.

## 4. 실기 판정 (미리 정한 숫자)

## 5. [미검증]

- `route_graph_node` 실행 자체(빌드 전이라 한 번도 안 띄움), `set_route_graph` 실제 응답.
- 적용 직후 BT 가 쥔 옛 경로·tracking 상태(주행 중 적용은 막으므로 위험 낮음).
- 앱 벽 판정은 지도 설정의 x/y offset·flip 을 반영하지 않는다(기본값 0 전제).

## 6. 10-01 빌드·실기 전 점검

- 스택 내린 상태에서 `colcon build --packages-select vica_interfaces vica_nav2` 완료.
- `route_graph_node` 단독 기동 → **즉시 사망**: 콜백 그룹을 `self._services` 에 넣어 rclpy Node 내부
  목록을 덮음. `_service_group` 으로 수리(앱 `2e09ffc`). 이후 GetRoute 0.03 s · 미리보기 0.18 s ·
  DraftRoute 6.6 s(나무형·오류 0), 파일 쓰기 없음.
- 터미네이터 ⑨ nav2 칸 명령에 `use_route:=true` 기본(루트 `36c4cfe`, rc 재생성).
- 그 전제로 launch 수리(ros2 `83f41da`): 종전엔 플래그만 보고 레일 트리를 골라, 레일 파일 없는 지도에서
  route_server 가 없으면 공식 BtActionNode 가 트리 생성 때 예외 → 주행 불가. 이제 파일이 있을 때만.
- ros2 `feat/app-route-editor` 에 다른 세션의 VCC 커밋 `8621e82`(U턴 반지름)가 함께 있다 — 빌드에 포함됨.
- 머지 확인(실행 안 함): ros2 → VCC 빨리감기·충돌 없음, 루트 일반 머지·충돌 없음, 앱은 VCC 브랜치 없음.
- 흐름·실기 기록 페이지: https://claude.ai/artifact/8J8GjvpLg1aG4tj2hLDpTc (실기 수정은 여기 '실기 수정 기록' 표에 이어 적는다).
