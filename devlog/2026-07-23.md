## Nav2 Goal 조건부 취소 정책

- 공개 reset 시작 시 fresh Nav2 Action status에서 accepted, executing, canceling Goal 유무를
  먼저 확인한다.
- 활성 Goal이 없으면 cancel 서비스를 호출하지 않고 중앙 E-stop latch reset 단계로 진행한다.
- 활성 Goal이 있으면 전체 취소를 요청하고 terminal 상태를 확인한 뒤에만 다음 단계로
  진행한다.
- Nav2 status 수신 이력과 action server가 모두 없으면 처음부터 미실행으로 판정해 Goal
  검사를 생략한다.
- action server가 있는데 status가 없거나 이전 status가 stale이면 reset을 거부한다.
- Goal 유무와 관계없이 Safety Supervisor의 `/cmd_vel_req=0` 또는 stale 검사는 유지한다.
- 코드·단위 테스트에는 반영했으며 실제 Nav2·CAN·motor 종단 동작은 `[미검증]`이다.

## Motor CAN 시작 전 차단

- `mdrobot_can_control`은 CAN 객체 생성과 송신 전에 `/sys/class/net/<can_iface>/flags`의
  `IFF_UP` 비트를 읽기 전용으로 확인한다.
- 인터페이스가 없거나 DOWN이면 `[MOTOR START BLOCKED]` 오류를 출력하고 motor node 시작을
  거부한다.
- motor node는 공유 `can1`을 자동으로 UP하거나 bitrate를 변경하지 않는다.
- UP/DOWN/미존재 단위 테스트는 반영했으며 실제 장치에서의 시작 차단은 `[미검증]`이다.

## ROS 2 Humble Safety 상태 로그 종료 오류

- reset 성공 뒤 `emergency_stop_node`와 `safety_supervisor_node`가 종료된 직접 원인은
  동일한 소스 호출 위치에서 로그 심각도를 `ERROR/WARN`에서 `INFO`로 변경한 것이다.
- ROS 2 Humble `RcutilsLogger`는 호출 위치별 심각도를 고정하므로 기존 동적
  `getattr(logger, severity)` 호출에서
  `ValueError: Logger severity cannot be changed between calls.`가 발생했다.
- 심각도별 `error()`, `warning()`, `info()` 호출 위치를 분리한 공통 함수를 추가하고
  `vica_safety`의 동적 심각도 호출 네 곳을 교체했다.
- 실제 Humble logger의 `ERROR → WARN → INFO` 전환 회귀 테스트를 추가했으며
  `vica_safety` 53개 테스트와 단독 build/test가 통과했다.
- 이후 실기에서 CAN F1 물리 E-stop, motor 정지와 `/safety_reset`을 다시 확인했고,
  성공 INFO 로그 뒤 Safety 노드가 종료되지 않고 정상 동작함을 확인했다.
- Nav2 Goal부터 Safety·CAN motor까지의 주행 종단 동작은 별도 `[미검증]`이다.
