## 대시보드 오류 표시 깜빡임 원인과 수정

앱 대시보드의 '오류/긴급 정지' 값이 비상정지 reset 이후 0과 1 사이로 계속 뒤집혔다.
원인은 앱이 아니라 `VICA_Supervisor/ros2/vica_status_app_node.py`의 진단 처리였다.

`/diagnostics`는 여러 노드가 함께 쓰는 공용 topic이고 각 메시지는 그 발행자의 상태만
담는다. 그런데 이 노드는 마지막에 도착한 메시지 하나만 보관했다가 그 안에서만 ERROR를
찾았다. ERROR를 가진 발행자와 정상 발행자가 번갈아 도착하면 `error_reason`이 채워졌다
지워지기를 반복했고, 10 Hz 발행과 겹쳐 화면에서 깜빡임으로 보였다.

진단 항목을 발행자별(`status.name`)로 누적하고 만료를 적용해 원인을 없앴다. 사유 선택은
key 사전순으로 고정해 도착 순서에 따라 문구가 바뀌지 않게 했다. 확정과 해제에 지연을
두어 짧은 떨림을 한 번 더 걸렀다.

발행자 2개가 0.1초 간격으로 번갈아 도착하는 조건을 재현해 5초간 표시 전환이 49회에서
1회로 줄어드는 것을 확인했다.

### 같은 형태의 문제 2건 추가 발견

`/odom`과 `/vica_goal_event`도 마지막 값만 보관하고 만료가 없었다. 구독 입력 5개 중
만료 검사가 있는 것은 TF 하나뿐이었다.

- `/odom`: 발행이 끊겨도 마지막 twist를 계속 써서 로봇이 멈춘 뒤에도 `moving`으로 남을 수
  있었다. 만료 시 속도 0으로 보고 fallback pose도 쓰지 않게 했다.
- `/vica_goal_event`: `navigation_active`에 타임아웃이 없어 종료 이벤트를 놓치면 `moving`에
  영원히 갇혔다. 만료 안전망을 넣었다.
- map yaml 자동 감지가 첫 성공 후 조회를 멈춰 지도를 바꿔도 `map_id`가 갱신되지 않았다.
  조회를 계속하도록 바꿨다.
- 만료 판정 기준을 monotonic clock으로 통일했다. 시스템 시계가 바뀌어도 흔들리지 않는다.

### Mission Manager 레이스 조사 결과

`_poll_nav_status()`가 `logic.active_destination`을 `_nav_lock` 밖에서 읽고, E-stop 콜백은
별도 callback group이라 병렬로 실행된다. 이론상 `goal_succeeded`가 유실될 수 있는 창이
있다. 다만 E-stop 경로가 `_enter_estopped()` 직전에 목적지를 액션으로 캡처해
`CancelNav`를 함께 발행하므로, `goal_canceled`가 대신 종료를 알려 실질적 유실은 없다.

우연한 순서에 기대는 구조라 견고하지는 않지만, 실제 버그가 아니고 Safety 인접 코드라
이번에는 수정하지 않았다. 위 `goal_event_timeout_sec` 안전망이 이 경로까지 덮는다.

## 앱 UI 정리와 기능 추가

### 화면 이름과 상단 바

- '지도별 장소 보기'를 '원격 주행'으로 바꾸고 아이콘도 주행 계열로 교체했다.
- 상단 바 비상정지 버튼을 라벨 붙은 긴 타원형에서 빨간 원형으로 바꿨다. 라벨이 사라지므로
  Tooltip과 `semanticLabel`로 의미를 남겼다.
- 어느 화면에서든 장소 저장으로 갈 수 있는 버튼을 상단 바에 추가했다. 기존 대시보드·설정
  아이콘과 달리 좁은 화면에서도 보이게 두었다.
- 대시보드 '오류/긴급 정지' 카드가 한 줄로 잘렸다. `maxLines`는 이미 2였지만 Flutter가
  공백에서만 줄을 나눠 '오류/긴급'과 '정지'로 갈라졌다. 개행 위치를 직접 지정하고,
  좁은 화면(카드 폭 158px)에서 두 줄로 렌더링되는지 확인하는 위젯 테스트를 추가했다.

### 장소 저장 화면

- 화면 안 '목적지' 표현을 '장소'로 통일했다(9곳). '다른 이름'은 '별칭'으로 바꿨다.
  `destinations.yaml` 스키마와 ROS 계약, 코드 식별자는 그대로 두었다.
- 임시 저장한 장소를 다시 고칠 수 있게 했다. 입력 폼이 임시 저장 직후 비워지므로 시트를
  열기 전에 이전 값을 되돌리는 함수를 만들었다. 수정 중에는 기존 `locationId`를 유지한다.
  저장할 때마다 새 UUID를 만들면 같은 장소가 둘로 늘어나기 때문이다.

### 연결 해제 상태와 반복 알림

- `disconnect()`가 데이터를 전혀 정리하지 않아 연결이 끊긴 뒤에도 직전 로봇 상태가 현재
  상태처럼 남아 있었다. 연결이 끊기는 모든 경로에서 로봇 실시간 상태를 비우도록 했다.
  지도와 장소는 정적 데이터라 유지하고, E-stop 상태는 안전 표시이므로 앱이 지우지 않는다.
- 연결 상태를 참조하는 화면이 대시보드뿐이었다. 현재 위치와 로봇 관리에도 연결 안 됨
  안내를 띄워 값이 비어 있는 이유를 알 수 있게 했다.
- '알림 및 로그'에 `No events recorded`가 초당 한 건씩 쌓였다. 판정이 완전 일치라서
  발행 노드가 앞뒤에 다른 문구를 붙이면 긴급 정지 알림으로 잘못 분류됐고, 더 근본적으로는
  같은 사유가 반복돼도 매번 기록하고 있었다. 사유가 실제로 바뀔 때만 남기도록 바꿨다.
  특정 문구에 기대지 않으므로 다른 반복 사유에도 동작한다.

### 연결 시 장소 동기화

재연결 때 지도 목록만 다시 요청하고 장소는 요청하지 않았다. 연결이 끊긴 사이 VICA에서
장소가 바뀌면 예전 목록이 그대로 남는다. 지도와 장소를 함께 요청하도록 했고, 첫 연결처럼
선택된 지도가 없을 때는 지도가 정해지는 시점에 장소를 요청한다.

## 원격 주행 판정을 Mission Manager로 위임

앱의 `requestDestination()`이 권한과 접근 가능 여부를 먼저 판정하고 있었다. 앱이 가진
장소 정보는 마지막으로 받아온 사본이라 최신이 아닐 수 있고, 그러면 Mission Manager가
허용할 요청을 앱이 막게 된다.

`vica_goto_goal.py`가 명시한 원칙("지도·접근 권한·Safety·Nav2 검증과 Goal 생성은 Mission
Manager가 맡는다")에 맞춰 앱의 사전 판정을 걷어냈다. 앱은 요청만 보내고 `accepted`와
`message`를 표시한다. Mission Manager는 거부 사유를 `GateReason` 코드로 돌려주므로,
판정은 그대로 두고 화면에 보일 문구만 한국어로 옮겼다.

실제 로봇이 움직이므로 요청 전 확인 대화상자를 거치도록 했고, 주행 중에는 버튼이
'주행 중'으로 바뀐다. 주행 여부는 `/robot_status.current_goal`로 판단하며 앱이 따로
추적하지 않는다.

## 안내 취소·일시정지·재개 신설

주행 중 로봇을 멈추는 방법이 비상정지뿐이었다. 비상정지는 중앙 래치가 걸려 관리자 reset이
필요하므로, 단순히 목표를 바꾸는 상황에는 과하다. 안전 사건이 아닌 목표 조작을 위한 경로를
별도로 만들었다.

### 인터페이스

- `vica_interfaces/srv/MissionCommand.srv` 신규. 취소·일시정지·재개가 공용으로 쓴다.
  처음에는 `bool pause` 하나로 정지와 재개를 겸하려 했으나, `pause: false`가 재개를 뜻해
  읽기 어렵고 E-stop 계열에서 `false`가 이미 다른 의미를 갖고 있어 혼동 위험이 있었다.
  service를 셋으로 나눠 이름이 곧 동작이 되게 했다.
- `RobotState.msg`에 `bool is_paused` 추가. 기존 필드를 유지하는 추가라 LLM 코드를
  고치지 않아도 동작한다.
- `VicaIntent.msg`는 구조를 바꾸지 않았다. `intent` 필드가 받는 값에 `cancel`, `pause`,
  `resume` 세 개를 추가하고 주석으로 계약을 명시했다.

### Mission Manager

- `State.PAUSED` 추가. 게이트 함수 3개(`check_cancel_gate`, `check_pause_gate`,
  `check_resume_gate`)를 신설했다. 기존 `check_gate`는 건드리지 않아 주행 요청 판정이
  흔들리지 않는다.
- 일시정지는 Nav2 goal을 취소하되 목적지를 `paused_destination`에 보관하고, 재개 시 그
  목적지로 새 goal을 만든다.
- E-stop이 활성화되면 보관분을 폐기한다. 남겨두면 해제 후 "다시 출발"이 통해 이전 goal
  자동 재개 금지 원칙이 깨진다. 단위 테스트로 못박았다.
- 일시정지도 Nav2 goal을 취소하지만 취소와 구분해야 앱이 "주행 끝"으로 오해하지 않는다.
  `CancelNav`에 이벤트 이름을 담아 `goal_paused`를 발행한다.
- 음성 취소는 되물어 확인한 뒤에만 실제로 취소한다. 확인을 기다리는 동안 주행은 계속한다.
  미리 멈추면 사용자가 부정했을 때 되돌릴 수 없기 때문이다.

### 상태를 받는 노드 점검

- `vica_goto_goal.py`가 `goal_paused`를 몰라 일시정지 시 무한 대기했다. terminal 이벤트로
  처리하고 종료하도록 고쳤다. 재개는 앱·음성이 담당하는 별도 행위다.
- `vica_status_app_node.py`에 `goal_paused` 처리를 추가했다. `current_goal`은 유지해야
  앱이 재개할 목적지를 보여줄 수 있다. `waiting_reason="일시정지"`로 표현해
  `/robot_status` 스키마는 바꾸지 않았다.
- `vica-voice-llm`은 `/vica/robot_state`를 구독하지만 `is_moving`을 프롬프트 컨텍스트로만
  쓴다. 판정에 쓰이지 않아 지금 코드로도 깨지지 않는다. 다만 "그냥 정지"와 "일시정지"가
  구분되지 않아 `is_paused` 필드를 열어 두었다. LLM 저장소는 변경하지 않았다.

### 검증

`mission_logic`은 rclpy에 의존하지 않아 단위 테스트로 검증했다. 취소·일시정지·재개
게이트와 E-stop 시 보관분 폐기, 음성 취소 재확인 흐름까지 13개 테스트를 추가했다.
로컬에 pytest가 없어 같은 규칙을 검증하는 스크립트로 32건을 먼저 확인한 뒤 저장소
테스트로 옮겼다. Jetson에서 `colcon test`로 실행해야 한다.

`flutter analyze` 무결함, `flutter test` 18건 통과, 변경한 Python 5개 파일 `py_compile` 통과.

## LLM 담당자 인수인계 문서

`docs/llm_handoff_cancel_pause_resume.md`를 작성했다. 오늘 변경의 목적과 비상정지와의
차이, LLM이 채워야 할 `VicaIntent.intent` 값과 나머지 필드 채우는 법, 확인 명령까지
담았다. 담당자가 오해하기 쉬운 세 가지(확인 대화를 직접 만들려는 것, 주행 여부를 먼저

## 남은 사항

- 취소·일시정지·재개 실기 검증 `[미검증]`. 인터페이스가 새로 생겼으므로
  `colcon build --packages-select vica_interfaces vica_mission_manager`가 먼저 필요하다.
- LLM이 `cancel`/`pause`/`resume`을 발행하기 전까지 음성 경로는 동작하지 않는다.
  앱 버튼으로만 쓸 수 있다.
- status 노드의 오류 확정·해제 지연(1초/2초) 기본값은 실기 로그를 보고 조정한다.
- Mission Manager 거부 응답 문자열이 앱의 `GateReason` 매핑과 맞는지 실기 확인 필요.
- `VICA_Supervisor`에 자체 `.gitattributes`가 없어 `flutter pub get`이 만드는 생성 파일
  4개가 줄바꿈만으로 변경 표시된다. 최상위 `.gitattributes`는 별도 저장소인 앱에 적용되지
  않는다. 별도 정리 필요.
