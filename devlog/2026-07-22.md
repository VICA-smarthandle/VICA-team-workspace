# 개발 로그 2026-07-22

## 요약

VICA를 팀 workspace로 배포하기 위한 거버넌스와 guideline 기준을 정리했다. 제품 코드는
세 Git 저장소로 분리하고, 루트 조정 저장소는 문서·참고자료·manifest를 관리한다.

## 확정한 협업 구조

- `vica_ros2_ws/`, `vica-voice-llm/`, `VICA_Supervisor/`는 별도 저장소를 유지한다.
- 루트 저장소는 `AGENTS.md`, `GOVERNANCE.md`, guideline, devlog와
  `workspace.repos`를 배포한다. `source_file/` 원본은 로컬에만 유지한다.
- 제품 저장소는 embedded repository로 추가하지 않고 `vcs import`로 구성한다.
- 공용 ROS 메시지 정본은 `vica_ros2_ws/src/vica_interfaces/`다.
- 앱 저장소의 로봇 측 `ros2/` 보조 노드는 장기적으로 ROS workspace의 bridge 패키지로
  이동하는 목표를 두되 현재 파일은 이동하지 않았다.

## E-stop·주행 안전 결정

```text
물리 버튼(CAN F1) · 앱 · STT 긴급어
→ emergency_stop_node 입력 통합 + 중앙 래치
→ /emergency_stop
→ Mission Manager + Safety Supervisor
→ /cmd_vel_safe=0
→ motor node
```

- motor node에는 E-stop 래치, `/estop_state`, `/estop_reset`을 두지 않는다.
- 앱·STT의 `false`는 입력 원인의 해제이며 중앙 래치 reset이 아니다.
- LLM과 STT에는 reset 권한이 없다.
- 모든 원인이 해제된 뒤 로그인한 관리자가 앱 확인 팝업에서만 reset을 요청한다.
- reset 뒤 이전 Nav2 Goal을 자동 재개하지 않는다.
- 물리 전원·토크 차단 E-stop은 소프트웨어 E-stop과 별도로 유지한다.

## 코드와 문서 대조 결과

- motor node는 현재 `/cmd_vel_safe`를 구독하고 command/knob timeout 시 0 RPM을 만든다.
- Safety Supervisor는 `/cmd_vel_req`와 `/emergency_stop`을 구독해 `/cmd_vel_safe`를 발행한다.
- Nav2 기본 출력 `/cmd_vel`을 `/cmd_vel_req`로 연결하는 remap은 없다.
- `emergency_stop_node`는 물리 CAN F1·앱·음성·시험 입력을 OR하지만 중앙 latch/reset은 없다.
- 기본 motor safety launch는 `input_mode=test_topic`이라 물리 CAN F1 입력을 활성화하지 않는다.
- `app_emergency_node`가 호출하는 `/estop_reset` server는 현재 없다.
- Mission Manager의 `/estop_state` 구독은 producer가 없는 이전 계약이다.

따라서 중앙 E-stop 래치, 관리자 앱 단일 reset과 Nav2 안전 입력 연결은 구현 완료가 아닌
`[GAP]/[TARGET]`으로 문서화했다.

## Localization 계약 정합화

```text
encoder_feedback /wheel/odom ─┐
                              ├→ robot_localization EKF → /odom
D455 adapter /imu/base_link ──┘                         └→ odom → base_footprint
```

- `vica_localization` 패키지를 wheel odometry와 EKF 설정·bringup의 정본으로 추가했다.
- 기존 `ekf.yaml`의 활성 형식과 주석 처리된 VSLAM 대안 블록을 유지하고 `odom0`을
  `/wheel/odom`으로 정합화했다.
- `encoder_feedback`는 raw `/wheel/odom`만 발행하고 TF를 발행하지 않도록 했다.
- EKF의 `odometry/filtered`는 표준 `/odom`으로 remap하며 EKF만
  `odom → base_footprint`를 발행한다.
- Cartographer와 Nav2 launch는 `vica_localization` bringup을 포함하고 `/odom`을 사용한다.
- 관련 4개 패키지 격리 빌드, EKF 계약 테스트 2건, EKF 노드의 실제 파라미터 로드와
  `/odom` publisher 생성을 확인했다.
- 개발 PC 시스템에는 `robot_localization`과 `python3-can`이 아직 설치되어 있지 않다.
  임시 추출 패키지로 수행한 기동 확인과 별도로 깨끗한 팀 환경에서 재검증해야 한다.
- C5와 D455를 동시에 사용한 실기 융합, 드리프트, 입력 단절과 TF 단일 authority 검증은
  아직 완료하지 않았다.

## Scan adapter 정리

- 사용하지 않는 `scan_rear_filter` 노드를 폐기했다.
- Nav2와 Cartographer의 현재 scan 입력은 필터를 거치지 않는 `/scan`이다.
- 삭제된 모듈을 가리키던 `vica_sensor_adapters`의 console entry point도 함께 제거했다.
- `vica_sensor_adapters` 격리 빌드는 성공했고 설치된 실행 항목은
  `imu_base_link_adapter`, `vslam_covariance_adapter` 두 개만 남은 것을 확인했다.
- 패키지 테스트는 기존 adapter 파일의 flake8 스타일 오류 46건 때문에 실패했다. 기능
  오류와 구분해 후속 정리하되 테스트 통과로 기록하지 않는다.

## 배포 전 남은 항목

1. release manifest는 branch 대신 검증된 tag 또는 commit SHA로 고정한다.
2. `source_file/` 원본을 받을 권한이 확인된 팀 공유 위치를 정한다.
3. GitHub branch protection과 필수 reviewer 정책을 팀 권한에 맞게 설정한다.
4. 실제 CI를 추가하기 전 변경기록 자동화를 구현 완료로 표시하지 않는다.
