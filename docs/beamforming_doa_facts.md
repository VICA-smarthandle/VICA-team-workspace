# 빔포밍·DOA 확정 사실 (2026-09-10)

"비카야" 호출 방향으로 로봇을 돌리는 기능(`SEEKING`)이 기대는 **소리 방향(DOA)**에
대한 확정 사실을 한곳에 모은다. 마이크 칩 일반 성능은
`vica-voice-llm/docs/respeaker-v3-capabilities.md` 가 정본이고, 이 문서는 **그 방향을
로봇 회전에 쓰는 부분**만 다룬다.

관련: 설계 `docs/superpowers/specs/2026-09-10-voice-call-approach-design.md` ·
실기 기록 `devlog/2026-09-10-비카야-호출-접근.md`

---

## 1. 한 줄

**DOA 는 나침반이지 줄자가 아니다.** 방향은 알고 거리는 모른다. 그래서 소리로
**목표점을 만들지 않고, 고개만 돌린다.** 다가갈지는 카메라가 정한다.

## 2. 장비

| | |
| --- | --- |
| 모델 | reSpeaker USB 4-Mic Array **v3.0** · 칩 XVF3000 · USB `2886:0018` |
| 채널 | 6ch — ch0 처리음(AEC·잡음억제·빔포밍 완료) / ch1~4 원음 / ch5 재생참조 |
| DOA 읽기 | `DspState.doa_angle()` — USB vendor control transfer, 파라미터 id21 `DOAANGLE`, **0~359 정수** |
| 권한 | `/etc/udev/rules.d/99-respeaker.rules`(`MODE=0666`) 적용됨. 읽기 확인 완료 |
| 쓰기 | **금지(D7 동결).** DOA 는 읽기 전용이라 저촉되지 않는다 |

## 3. 빔 방향은 고정할 수 없다

**칩이 가장 큰 소리로 자동 조준한다.** 우리가 할 수 있는 것은 칩이 알려주는 방향을
**들은 뒤에 보고** 채택 여부를 정하는 소프트웨어 관문뿐이다.

- "전면 180도만 수음" 같은 것은 **하드웨어로 불가능**하다.
- 버린 방향의 소리도 **녹음에는 이미 섞여 있다.**
- 포커스 빔 2개·빔별 방위는 XVF3800(상위 제품, 미보유)의 기능이다.

## 4. 좌표 기준

```
        0° (로봇 정면 · 카메라가 보는 쪽)
             ↑
   270° ←  로봇  → 90°       각도는 반시계로 증가
             ↓
       180° (핸들 · 사용자가 서는 쪽)
```

- **핸들 = 180°** — 2026-09-01 `doa_probe` 실측(표본 33, 범위 172~180)
- **정면 ≈ 0°** — 2026-09-10 재확인(정면 발화 평균 **11.8°**, 표본 31)

마이크를 한 번 고정하면 **돌리지 않는다.** 이 기준이 장착 각도에 묶여 있고,
barge-in 방향 관문(`VICA_USER_DOA_CENTER=180±60`)도 같은 기준을 쓴다.

## 5. 회전 부호 = **`wake_doa_sign = +1.0`** (2026-09-10 실측 확정)

마이크 각도는 **반시계로 증가**하며, Nav2 `SpinInPlace`(양수 = 반시계)와 **같은 부호**다.
따라서 변환은 부호 반전 없이 그대로 쓴다.

```python
yaw_rad = wrap_to_pi(radians(doa_deg * wake_doa_sign))   # sign = +1.0
```

**틀리면 로봇이 정확히 반대로 돈다.** 장비를 바꾸거나 마이크를 다시 달면 재측정한다.

### 측정 방법 — 지점을 찍지 말고 걸어라

**실패한 방법(3지점 측정).** 정면·좌 90°·우 90° 세 자리에서 각각 부르는 방식.
결과가 정면 11.8° / 327.0° / 311.7° 로, **좌우 두 지점이 15° 밖에 안 벌어졌다**
(로봇 양옆이면 약 180° 벌어져야 한다). 서는 위치 오차 하나에 측정이 통째로 무너진다.

**성공한 방법(걷기 관찰).** 로봇에서 약 1 m 떨어져 **한 방향으로 천천히 돌면서**
계속 부르고, 각도가 **커지는지 작아지는지**를 본다.

- 로봇을 마주 보고 **사용자 기준 오른쪽**으로 이동 → 0° → 119° (**증가**)
- 사용자 기준 **왼쪽**으로 이동 → 210~359° 대역
- 12구역 중 **8구역**에 표본 → 마이크 정상

마주 본 사람이 자기 오른쪽으로 가면 거울처럼 **로봇의 왼쪽**이고, 그때 각도가
커졌다 → 반시계 증가 → `+1.0`.

> **교훈: 방향 센서의 회전 방향은 두 지점을 비교하지 말고 한 방향으로 걸으며
> 흐름을 보라.** 지점 비교는 "어디에 있었나"만 말하고 "어느 쪽으로 도는가"를
> 말하지 않는다.

## 6. 정밀도와 사각지대

| | |
| --- | --- |
| 퍼짐(조용할 때) | **±4°** |
| 퍼짐(로봇 발화·옆사람 섞일 때) | **±16°** |
| 사각지대 | **10° 미만이면 회전하지 않는다**(`SEEK_MIN_YAW_RAD`) — 이미 그쪽을 보고 있고, 퍼짐 안이라 잡음이다 |

## 7. 회전 규약

- **항상 짧은 쪽으로 접는다**(`wrap_to_pi`). 270° 호출은 왼쪽 270° 가 아니라
  **오른쪽 90°**(−π/2)다.
- **최대 회전각은 180°.** 그보다 큰 회전은 나올 수 없다.
- **회전 속도 실측 약 0.38 rad/s**(2026-09-10 실기: −2.18 rad 에 5.8 초).
  → 180° 는 **약 8.3 초**.
- **한 번 부르면 두 번 돈다** — 찾으러 한 번, 못 찾으면 원위치로 한 번.
  180° 에서 못 찾으면 **왕복 약 16 초** 움직인다. 실기의 "왜 자꾸 도나"는 대부분
  이 두 번째(원위치) 회전이다.
- 회전은 Nav2 `SpinInPlace`(behavior server) → `/cmd_vel_req` → Safety →
  `/cmd_vel_safe`. **`cmd_vel` 직접 발행은 없다.**

### 실기 1회차 검증 (2026-09-10, 8회)

| 부른 방향(DOA) | 회전량 | |
| --- | --- | --- |
| 24° / 19° / 21° | +24° / +19° / +21° | 정면 근처 |
| **235°** | **−125°** | 짧은 쪽으로 접힘 |
| 258° | −102° | |
| 248° | −112° | |
| 162° | +162° | 관측된 최대 |
| 342° | −18° | |

**8/8 전부 부른 쪽으로 돌았다.** 270° 계열이 전부 음수로 접힌 것이 `wrap_to_pi` 와
`+1.0` 을 함께 증명한다.

## 8. DOA 를 쓰는 곳과 안 쓰는 곳

| 쓰는 곳 | |
| --- | --- |
| **호출 방향 회전**(`SEEKING`) | 이 문서의 주제. `/vica/wake_doa` |
| **barge-in 방향 관문** | 질문 재생 중 끼어든 발화가 사용자 쪽인지 |
| **"비카야" 방향 잠금** | 호출 순간 방향을 ±15°·120초 잠가 barge-in 에 쓴다 |

| 안 쓰는 곳 | 이유 |
| --- | --- |
| **긴급어("멈춰")** | 방향을 걸면 행인이 외친 "멈춰"가 죽는다. **안전 경로에 방향을 걸지 않는다** |
| **목표점 생성** | 거리를 모른다. 소리로 좌표를 만들지 않는다 |
| **호출·명령 일반** | 방향 무관으로 받는다 |

## 9. 토픽 계약 (저장소를 건넌다)

```
/vica/wake_doa    std_msgs/Float32    0~359 (마이크 좌표계, 정면 0 · 핸들 180)
```

- 발행: 음성 `vica_wakeword_node` — **호출 1회당 1회**. DOA 를 못 읽으면 **발행하지 않는다**
- 구독: ROS2 `vica_mission_manager` — **대기 상태에서만** 받는다

`/vica/wake` 의 payload 를 넓히지 않고 별도 토픽을 낸 이유: 그 토픽에는 이미 안내 중
각성·복귀 브레이크·옛 질문 접기가 걸려 있어, 동작 중인 대화 경로를 건드리는 것보다
토픽을 하나 더 내는 쪽이 싸다.

### 발행 순서에 주의 — 잠금과 통보는 한 자리에서

`run()` 에서 `process_frame()` 이 **`on_wake` 콜백을 먼저** 부르고 `"wake"` 를 반환하며,
방향 잠금은 그 **뒤**에 일어난다. 그래서 노드가 나중에 잠긴 값을 읽으면
**직전 대화의 방향**을 내보낸다. `note_wake_direction` 이 잠금과 통보를 한 자리에
묶어 이것을 막는다 — **분리하지 말 것.**

## 10. 알려진 한계

- **DOA 는 "부른 순간"이 아니라 "웨이크워드가 판정된 직후" 값이다.** 말이 끝난 뒤
  빔이 다른 소리(발소리·환풍)로 옮겨 갔으면 그쪽 각도가 나간다. 측정 도구는 6초
  연속 발화의 원형 평균이라 **이 오차를 드러내지 못한다** — 실기에서는 짧게 한 번만
  부르고, 음성 로그의 `🧭 호출 방향 N°` 와 실제 위치를 회차마다 대조한다.
- **웨이크워드는 소리 모델만으로 발동한다(STT 확인 없음).** 점수 0.6 이상 연속
  2프레임(0.16초), 쿨다운 1.5초. 비슷한 소리에 반응할 수 있고, 그러면 **엉뚱한
  방향으로 돈다.** 오탐이 잦으면 문턱 0.6 을 올리는 것이 다음 수순.
- **방향 관문은 상황을 안 따라간다** — barge-in 의 고정 부채꼴 `180±60` 은 접근 질문
  구간(사용자가 로봇 앞 ≈0°)에 맞지 않는다. 정본은
  `vica-voice-llm/docs/voice-improvement-backlog.md` **7호**.

## 11. 재측정이 필요한 때

- 마이크를 떼거나 돌렸을 때
- 다른 로봇·다른 기체에 올릴 때
- 정면 발화가 0° 근처에서 크게 벗어날 때(기준선이 깨진 신호 — barge-in 부채꼴도 함께 틀어져 있다)

절차는 §5 "걷기 관찰". 도구는 음성 저장소 `tools/wake_doa_bearing.py`(3지점, 보조)와
걷기 관찰기(스크래치패드 `doa_walk.py`, 시간 흐름으로 부호를 직접 판정).
