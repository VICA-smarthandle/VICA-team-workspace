## 1. 무엇을 바꾸나

**로봇은 사용자의 어떤 요청에도 꼭 한마디 하고, LLM은 로봇이 할 일을 혼자 약속하지 않는다.**

10-08 반응표 판독(미션 상태 18개 × 음성 요청 11종 = 198칸)에서 말을 듣고도 아무 말 없이 넘기는 칸이 17개,
상황과 다른 말을 하는 칸이 18개였다. 사용자 관찰은 "LLM 할루시네이션보다 미션 에러가 압도적으로 많다"였다.
뿌리는 둘이다.

| 뿌리 | 내용 |
| --- | --- |
| 아무도 말하지 않는다 | "기다려"·"다 됐어"·"네"·"아니요"는 미션이 결과를 말하기로 정해 두어 LLM 대답을 코드가 지운다(`langchain_intent_parser.py` _finalize). 미션이 그 칸을 처리하지 못하면 둘 다 말이 없다. 사용자는 생각 중 소리만 듣는다 |
| LLM이 혼자 약속한다 | 어느 요청에도 맞지 않는 말은 LLM이 질문으로 분류하고 자기 말로 답한다. 이때는 막지 않아 "알겠습니다"·"안내해드릴까요?"가 나가고, 미션은 그 약속을 모른다 |

비유: 식당에서 종업원은 "주방장님이 알려 드릴 거예요" 하고 주문서를 넘겼는데, 주방장은 없는 메뉴라서
주문서를 버렸다. 손님은 아무 말도 못 듣는다. 반대로 종업원이 주방에 묻지도 않고 "네, 해 드릴게요"라고
약속하기도 한다. 주방장은 모든 주문서에 꼭 답하고, 종업원은 주방에 묻기 전에 약속하지 않으면 된다.

## 2. 규칙

| 규칙 | 내용 |
| --- | --- |
| 규칙 1 · 미션 | 어떤 요청에도 꼭 한마디 한다. 받기, 이유를 대고 거절하기, 되묻기 가운데 하나다. 이유는 사실이어야 한다. 알아듣고서 "잘 듣지 못했습니다"라고 하지 않는다 |
| 규칙 2 · LLM | 자유 대답은 정보까지만 한다. "알겠습니다"·"할게요" 같은 약속과 "안내해드릴까요?"·"계속 안내할까요?" 같은 혼자 권하기를 하지 않는다. 목적지를 권하려면 목적지 제안(navigate, need_confirm=true)으로 내서 미션이 확인 질문으로 기억하게 한다 |
| 다시 묻기 | 로봇이 물었는데 대답이 없거나 이상한 답이 오면 같은 질문을 다시 한다. 질문마다 **한 번**이다. 그다음은 그 질문의 지금 끝맺음을 따른다 |

- 규칙 1의 범위는 미션에 닿은 요청이다. 10-07 호출 반응표에서 듣지 않기로 정한 상태(빗금 칸)와, 물은 것이 없는 "네·아니요"(해당 없음)는 그대로 둔다.
- "이상한 답"은 못 알아들은 말, 질문과 상관없는 말, 옆사람 말이다. "화장실 어디야?" 같은 정보 질문은 LLM이 답하고 로봇의 질문은 그대로 둔다.
- 다시 묻기를 한 번으로 묶는 이유: 청취 창에 옆사람 말이 섞이면(10-08 판독) 같은 질문이 끝없이 되풀이될 수 있다.
- 규칙 2와 다시 묻기는 짝이다. 미션이 질문 중일 때 이상한 답에는 LLM이 말하지 않고 미션이 다시 묻는다. 목소리가 하나로 모인다.

## 3. 같은 말은 어디서나 같은 뜻으로

| 말 | 바뀐 뒤 |
| --- | --- |
| 잠깐 | 안내 주행 중이면 멈추고 “잠시 멈추겠습니다…”, 일시정지 중이면 같은 말을 다시 합니다. 홈 복귀 중이면 서서 “네?”, 질문 중이거나 손 놓기를 기다리는 중이면 “네?” 하고 듣습니다. |
| 기다려 | 안내 주행 중에는 “잠깐”과 같습니다. 대기 중이면 시간을 바꿔 M2를 다시 말합니다. 확인 질문에서는 “아니요”와 같습니다. |
| 다 됐어 · 그만 | 안내 주행·일시정지 중이면 “안내를 취소할까요?”로 묻습니다. 도착 뒤와 대기 중은 지금처럼 끝내기입니다. |
| 다시 가자 | 멈춘 안내가 있으면 다시 출발합니다. 가는 중이면 “지금 OO로 가는 중이에요.”, 도착 뒤와 대기 중이면 “네, 어디로 모실까요?”입니다. |
| 아니 · 기다리지 마 | 시간 질문이나 M2 바로 뒤라면 “여기까지 안내를 마칠까요?”로 한 번 확인합니다. |

## 6. 결정 5개 (2026-10-08 저녁 사용자)

1. **홈 가는 중의 “기다려”는 어디서 기다릴까요** — 정함: 직전 목적지의 대기 장소로 가서 기다립니다. “비카야”로 세운 뒤든 늦은 답이든 같습니다. 덧붙임: 대기 장소가 없는 목적지면 그 입구 앞으로 가서, 직전 목적지가 없으면 그 자리에서 기다립니다.
2. **시간 질문에 “네”라고만 하면** — 정함: “몇 분쯤 걸리실까요?”를 다시 묻습니다. 덧붙임: 두 번째도 “네”면 기다려 달라는 뜻이 분명하니 기본 30분을 기다립니다.
3. **대기 중 “취소”** — 정함: “안내가 필요 없으신가요?”라고 묻습니다. 네면 “안내를 종료합니다” 하고 홈, 아니요면 “안내를 계속하겠습니다.” 하고 계속 기다립니다. 덧붙임: 부정으로 묻는 질문이라 “아니, 필요 없어”는 “아니”로 시작해도 끝내자는 뜻입니다. LLM이 네·아니요 글자가 아니라 뜻으로 판단하게 규칙을 넣어야 합니다.
4. **확인 질문 중 다른 목적지** — 정함: “네, XX로 안내해드릴까요?”로 묻습니다. 덧붙임: 목적지마다 새 문장이 생기니 미리 구워 두어야 지연 없이 나옵니다.
5. **LLM이 정보 답 끝에 목적지를 권할 때** — 정함: 목적지 제안으로 냅니다. 일단 해 봅니다.

## 8. 음성(LLM) 쪽 바뀌는 것

1. 자유 대답의 약속·혼자 권하기 금지(규칙 2). 목적지를 권하려면 목적지 제안으로 낸다(결정 5).
2. 미션이 질문 중일 때(확인 질문, 도착 질문, 시간 질문, 접근 질문, 미션의 질문 뒤 듣기 창) unknown·clarify 대답을 지운다. 미션이 다시 묻는다.
3. 대기를 묻는 질문 뒤 "기다리지 마"·"대기 안 해도 돼"는 아니요(deny)로 낸다.
4. 접근 질문 "…안내를 받으시겠어요?"에 목적지로 답하면 목적지(navigate)로 낸다. 지금 지시문의 "여기서는 네/아니요만" 막음을 푼다.
5. "안내가 필요 없으신가요?"는 부정 질문이라 뜻으로 판정한다. 필요 없다는 뜻("네", "응", "필요 없어", "아니, 필요 없어", "괜찮아")은 affirm, 필요하다는 뜻("아니요", "필요해", "기다려 줘")은 deny다.
6. 음성이 쥐고 있는 "다시 출발할까요?"는 대답이 없거나 이상하면 한 번 다시 묻는다.

## 9. 구조

- **판단은 미션 로직 한곳에 둔다.** 음성 요청의 갈래(지금 `mission_manager_node.py` `_on_intent`와 도우미들)를 `MissionLogic`의 함수 하나로 옮긴다. 노드는 요청을 로직에 넘기고 나온 동작을 실행·기록만 한다. 10-07 호출 반응표(`on_wake_call`)와 같은 방식이다. 이렇게 해야 198칸을 ROS 없이 순수 시험으로 전수 확인할 수 있다.
- 미션이 "지금 무엇을 묻고 있는지, 다시 물었는지"를 질문마다 기억한다. 다시 묻기 한 번은 대답 없음과 이상한 답이 함께 쓴다.
- 홈 가는 중의 "기다려"를 직전 목적지 대기 장소로 보내려면, 복귀 중·복귀를 세운 뒤에도 미션이 직전 목적지와 그 대기 장소를 기억해야 한다.
- 공용 메시지(`vica_interfaces`)·토픽·서비스는 바꾸지 않는다. 음성은 지금 받는 `RobotState.dialog_state`와 미션 질문 뒤 듣기 창으로 "미션이 질문 중"을 안다. 새 노드도 없다.

## 10. 하지 않는 것

- 앱 명령(관리자 취소·홈 복귀·가보기), 손잡이 잡기·놓기, 긴급어("멈춰")의 반응은 바꾸지 않는다.
- 비상 멈춤 중 목적지 제안의 두 목소리(규칙 밖 1칸)는 그대로 둔다. 듣지 않는 상태라 드물다.
- 청취 창에 옆사람 말이 섞이는 문제(10-08 판독)는 별건이다. 다시 묻기를 한 번으로 묶어 영향만 줄인다.
- 다중 목적지 여정(10-07 설계)은 시연 뒤다.

## 11. 시험

- **반응표 전수 시험(미션)**: 18상태 × 11요청 198칸을 순수 로직 시험으로 만든다. 먼저 지금 동작을 그대로 고정하고(구조 옮기기 전후가 같은지), 그다음 칸마다 바뀐 뒤 동작으로 기대값을 고친다.
- **다시 묻기 시험(미션)**: 질문 9종마다 대답 없음 → 다시 묻기 → 끝맺음, 이상한 답 → 다시 묻기 → 끝맺음, 다시 묻기는 한 번만.
- **LLM 시험(음성)**: 지시문 규칙 문구, 미션 질문 중 reply 지우기, 부정 질문 판정 예시, "기다리지 마" 판정, 접근 질문 목적지 답.
- **실기**: 계획이 끝난 뒤 사용자가 정한 때에만 한다. 결정 5개와 말별 공통 규칙을 한 번씩 밟는 시나리오 표로 판정한다.

## 12. 위험

- 시연(≈10-27) 3주 전에 대화 경로를 넓게 건드린다. 구조 옮기기 → 미션 규칙 1 → 결정 → 다시 묻기·LLM 규칙 순으로 단계마다 시험을 통과시키고, 사용자가 어느 단계까지 시연 전에 넣을지 정한다.
- 다른 세션의 미커밋 변경이 같은 파일에 있다(미션 `mission_logic.py`·`mission_manager_node.py`의 홈 알림, 음성 `mission_phrases.py`·호출 노드의 "비카야" 오감지 대책). 그 변경이 먼저 커밋된 뒤 시작한다.
- 부정 질문 "안내가 필요 없으신가요?"는 "아니, 필요 없어"처럼 겉과 뜻이 갈린다. LLM 규칙과 판정 예시 시험으로 막고, 실기에서 따로 확인한다.
