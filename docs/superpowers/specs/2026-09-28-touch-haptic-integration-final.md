## 1. 한눈에 보기

손잡이는 **"사람이 쥐고 있는 동안만 로봇이 걷는 줄"**이다. 비유하면 아이 손을 잡고
걷는 어른과 같다 — 손이 빠지면 그 자리에 서서 손을 내밀고(진동), 다시 잡으면
걷는다. 처음 만날 때 손을 내밀었는데 안 잡는 사람은 손잡이 없이 따라오는 사람으로
보고(비활성) 그냥 안내한다.

```text
감지·"비카야" → 다가감 → "안내를 받으시겠어요?" → "네"
  → 손잡이가 사용자 쪽을 향하게 회전(가까우면 회전 생략)
  → [잡기 대기 시작] 진동 반복 + "손잡이가 진동하고 있습니다. 잡아주세요."
      ├ 2초 중 80 % 잡음 → 진동 멈춤 + 짧게 ×1 → 활성 모드
      └ 15초 안에 못 잡음 → 진동 멈춤            → 비활성 모드
  → 온보딩 "안녕하세요? 반갑습니다! … 어디로 가고 싶으신가요?"
  → 목적지 → "○○로 안내해드릴까요?" → "네" → 출발

[활성 모드 주행 중]
  손 놓음 0.5초 → 서기(goal 취소·목적지 보관)
               → "안전을 위해 손잡이를 다시 잡아주세요" + 긴 진동
               → 15초마다 반복
      ├ 1초 중 80 % 다시 잡음 → 짧게 ×1 + "○○로 다시 출발합니다" → 재출발
      ├ "다시 가자"(안 잡은 채) → 비활성으로 재출발
      └ 3분 동안 안 잡음 → 안내 종료(기존 취소 흐름)

[도착] 짧게 ×3 → 활성 모드 끝
[비상정지] 길게 ×1 (펌웨어가 상태 진입 순간에 스스로 울림)
```

## 2. 하드웨어

### 2.1 핀 (ESP32U, 2026-09-22 이식)

| 기능 | GPIO | 방식 |
| --- | --- | --- |
| 터치 | **14** | `INPUT_PULLUP`, **active-low**(잡으면 LOW). 선이 빠지면 HIGH = 놓음(fail-safe) |
| 진동 | **4** | MOSFET 게이트 구동. 시프터 없이 **3.3 V** |

### 2.2 실기 전 반드시 확인할 것

1. **터치 모듈 급전 — 3.3 V 로 확정(D8).** ESP32 입력은 3.3 V 한계다. 5 V 급전에
   push-pull 출력이면 평소(HIGH) 내내 GPIO14 에 5 V 가 들어가 보드가 상한다. 3.3 V
   급전이면 출력 방식과 무관하게 안전하다. 실기 전에 VCC 선이 3.3 V 핀에 꽂혔는지만
   눈으로 확인한다.
2. **터치 극성 — 잡으면 LOW 로 확정(D8).** 펌웨어 가정과 같다. 그래도 판정 로직을 켜기
   전에 `~/touch_monitor.py` 로 원시값을 한 번 찍는다(가만히 30초 → LOW 0회, 잡고
   30초 → LOW 다수). 09-05 에는 배선 문제로 한 번도 LOW 가 안 떴다.
3. **진동모터 장착 여부와 게이트 전압.** 나노 시절 IRF540N 은 문턱이 2~4 V 이고
   10 V 기준 부품이라, **3.3 V 게이트로는 거의 안 켜질 수 있다**(나노 5 V 때도 "약하다"였다).
   다음 중 하나로 고친다.
   - 로직레벨 MOSFET 으로 교체(예: IRLZ44N, AO3400 — 3.3 V 에서 완전히 켜짐)
   - NPN(2N2222) + 1 kΩ 베이스 저항 (아티팩트 "ADT19PDA 터치 배선"의 회로)
   - 5 V 레벨시프터의 빈 채널(a3 로 보임 — 실물 확인)로 게이트를 5 V 구동
   플라이백 다이오드는 어느 경우든 필수다.

## 3. 신호 계층 — 이미 있는 것 (1단계, 변경 최소)

1단계 설계서(09-04)가 그대로 유효하다. 요지만 적는다.

- 펌웨어가 20 Hz 로 `AA 56 seq flags xor` 를 보낸다. bit0 = 그 순간 잡음.
  터치 중 튐은 **시간 브리지 200 ms**로 정리한다(판정 아님).
- `user_guidance_driver_node` 가 `/vica/smart_handle_state` 의 `user_contact`·
  `uplink_fresh` 로 올린다. 주기 2 Hz + **바뀐 순간 즉시**(최소 간격 0.1 s).
- `uplink_fresh=false` 면 `user_contact` 는 강제로 false 다.
- 진동은 `/vica/haptic_request`(String)로 요청하고, 드라이버가 바이트로 바꿔 보낸다.

### 3.1 진동 패턴

| 이름 | 바이트 | 모양 | 쓰는 때 | 상태 |
| --- | --- | --- | --- | --- |
| `long` | 0x11 | 1200 ms ×1 | 손잡이 찾기(힌트·놓침), 비상정지 | 있음 |
| `short` | 0x10 | 300 ms ×3 (150 ms 쉼) | 도착 | 있음 |
| **`tick`** | **0x12** | **300 ms ×1** | **잡음 확인(D5)** | **신설** |

새 명령은 진행 중인 패턴을 **덮어쓴다**(`hapticStart` 기존 규칙). 그래서 "반복 진동
중에 잡으면 `tick` 을 보내는 것"만으로 긴 진동이 즉시 끊기고 짧은 확인이 한 번 온다.
따로 '멈춤' 명령은 필요 없다.

### 3.2 펌웨어가 스스로 울리는 것 (상태 진입 순간 1회)

`applyState()` 는 **상태가 바뀔 때만** 실행된다(같은 코드가 10 Hz 로 반복 와도 1회).
07-28 계획서 6.2절의 edge 트리거가 이미 성립한다.

| 상태 | 추가 |
| --- | --- |
| `STATE_ESTOP`(3) | `hapticStart(1, HAPTIC_LONG_ON_MS, 0)` |
| `STATE_ARRIVED`(5) | `hapticStart(HAPTIC_SHORT_COUNT, HAPTIC_SHORT_ON_MS, HAPTIC_SHORT_OFF_MS)` |

부작용으로 알아둘 것: 부팅 래치로 켜자마자 ESTOP 이면 전원 투입 때 한 번 떨리고,
홈 복귀 도착에도 짧게 ×3 이 울린다. 둘 다 해롭지 않아 그대로 둔다.
**진동은 알림일 뿐 정지 보증이 아니다** — 정지는 Safety·E-stop 경로가 맡는다.

## 4. 판정 계층 — 신설 (mission_manager)

판정은 전부 `mission_manager` 가 한다. 펌웨어·드라이버는 사실만 말한다.
새 노드는 만들지 않는다. `/vica/handle_mode` 토픽도 이번에는 만들지 않는다(4.6절).

### 4.1 입력

`/vica/smart_handle_state` 를 구독한다(공용 계약 변경 없음 — 소비자만 늘어난다).

미션 쪽에도 신선도 시한을 둔다. 메시지가 **1.0 s** 넘게 안 오면(주기 2 Hz 의 두 배)
`fresh=false` 로 본다. 드라이버가 죽으면 마지막 메시지가 붙들린 채 남기 때문이다.

### 4.2 잡음 비율은 "시간"으로 잰다 — 표본 개수로 세면 틀린다

메시지는 바뀐 순간과 2 Hz 주기에만 온다. 잡고 있는 2초 동안 메시지는 4개뿐이고,
손을 두드리면 수십 개가 온다. 그래서 개수로 80 % 를 세면 안 된다.

**값이 바뀐 시각들을 기록하고, 창 안에서 `true` 였던 시간의 합 ÷ 창 길이**로 잰다.

```text
GripMeter (순수 로직, ROS 모름)
  update(t, contact, fresh)          # 메시지마다
  ratio(now, window) -> 0.0~1.0      # 창 안 true 시간 비율
  released_for(now) -> 초            # 마지막으로 false 가 된 뒤 계속 false 인 시간
  fresh(now) -> bool                 # 1.0 s 시한
```

- 창이 관측 시작보다 길면(방금 대기를 시작함) 모자란 앞부분은 **false** 로 친다 —
  대기 시작 전부터 잡고 있었어도 최소 2초는 지켜본다.
- `fresh=false` 인 구간은 false 로 친다.

### 4.3 상태와 전이

모드 표시는 상태기계 안의 값 두 개로 둔다. 새 `State` 는 만들지 않는다.

```text
handle_active: bool         # 활성 모드인가
_grip_wait: 없음 | 대기중(시작시각, 마지막 진동시각)
_handle_pause: bool         # PAUSED 의 원인이 손 놓침인가
```

#### (가) 잡기 대기 — 회전 완료(또는 회전 생략) 직후

지금 `MSG_HANDLE_HINT` 와 `MSG_APPROACH_ONBOARDING` 을 연달아 말하는 세 자리
(회전 성공 · 회전 실패 · 근접 호출 회전 생략)를 모두 바꾼다.

| 순간 | 행동 |
| --- | --- |
| 진입 | `Haptic("long")` + `Say(MSG_HANDLE_HINT)`. 온보딩은 **아직 말하지 않는다**. 대기 시작 시각 기록 |
| 대기 중 매 tick | 마지막 진동에서 **2.0 s** 지났으면 `Haptic("long")` (1.2 s 켜짐 · 0.8 s 쉼으로 "계속 떨리는" 느낌) |
| `ratio(2.0) ≥ 0.8` | `Haptic("tick")` · `handle_active=True` · 온보딩 · 빈손 되묻기 사다리 시작(`_arm_dest_prompt`) |
| **15 s** 초과 | 진동 반복 멈춤 · `handle_active=False` · 온보딩 · 사다리 시작 |
| 대기 중 목적지 발화 도착 | 대기를 접고 평소처럼 처리한다. 모드는 출발 순간에 정한다(아래 (나)) |
| E-stop · 취소 | 대기를 접는다 |

회전 **중**에 손을 대는 것은 세지 않는다 — 대기는 회전이 끝난 뒤에야 시작한다.

기존 `on_handle_hint_spoken`(힌트 재생이 끝난 뒤 진동, I-2)은 **폐기한다.**
I-2 는 "진동이 나는 곳을 잡아주세요"라는 말보다 진동이 먼저 끝나면 거짓말이 되는
문제였다. 새 문구는 "진동하고 있습니다"이고 진동이 잡을 때까지 이어지므로 그 문제가
사라진다. `/vica/tts_done` 의 힌트 대조와 `_pending_handle_hint` 도 함께 걷어낸다.

#### (나) 출발 순간의 모드

잡기 대기를 거친 안내는 (가)의 결과를 따른다. 그 밖의 출발에서는:

| 출발 | 모드 |
| --- | --- |
| 대기를 건너뛰고 목적지가 먼저 온 경우 | 출발 순간 `ratio(0.5) ≥ 0.8` 이면 활성, 아니면 비활성 |
| 도착 뒤 "다른 곳도 가요"(ASKING_NEXT → 출발) | 위와 같음 |
| 관리자 앱 목적지 · 배송 · 홈 복귀 | **항상 비활성** |

#### (다) 활성 주행 중 손 놓음

`handle_active` 이고 `NAVIGATING` 일 때만 본다. 비활성에서는 손을 놓아도 아무 일도
없다.

| 순간 | 행동 |
| --- | --- |
| `released_for ≥ 0.5 s` (fresh 인 채) | 기존 `on_pause_request` 경로로 goal 취소·목적지 보관. **단 `MSG_PAUSED`("다시 출발하려면 말씀해 주세요") 대신** `MSG_HANDLE_LOST` + `Haptic("long")`. `_handle_pause=True` |
| 대기 중 15 s 마다 | `MSG_HANDLE_LOST` + `Haptic("long")` 반복 |
| `ratio(1.0) ≥ 0.8` | `Haptic("tick")` + 기존 `on_resume_request`(→ `MSG_RESUMED` "○○로 다시 출발합니다") |
| "다시 가자"(안 잡은 채) | 재출발하되 `handle_active=False` — 곧바로 다시 서는 반복을 막는다 |
| 180 s 무접촉 | 기존 취소 흐름(`on_cancel`)으로 안내를 끝낸다 |
| E-stop | 기존 규칙대로 보관 목적지를 버린다(자동 재개 안 함) |

**"잠깐"으로 멈춘 경우와 섞지 않는다.** 사용자가 손을 쥔 채 "잠깐"이라고 하면
`_handle_pause=False` 인 PAUSED 다. 이때는 잡고 있어도 자동 출발하지 않고
"다시 가자"를 기다린다. 자동 재출발은 `_handle_pause=True` 일 때만이다.

0.5 s 는 현재 최고속도 0.408 m/s 에서 약 0.2 m 다. Nav2 `progress_checker`
(10 s)보다 한참 먼저 goal 을 취소하므로 Nav2 가 스스로 실패 처리할 틈이 없다.

#### (라) 상향 두절 (활성 주행 중 `fresh=false`)

"손을 놓음"과 "통신이 끊김"은 다른 사건이다(vica_scenario 2-1.3). 끊긴 상태에서
놓침처럼 세우면 다시 잡아도 알 길이 없어 영원히 못 간다. 그래서 **비활성으로 내리고
계속 간다.** 멘트는 `MSG_HANDLE_UNAVAILABLE` 1회. 속도는 손잡이 당김(knob)이 여전히
제한하므로(CAN 경로, ESP32 와 무관) 사용자가 당기면 느려진다.

잡기 대기 중에 두절되면 대기를 접고 비활성으로 온보딩한다.

#### (마) 도착·종료

`ARRIVED` 진입에서 `handle_active=False`. 도착 진동은 펌웨어가 낸다(3.2절).
IDLE 로 돌아가는 모든 경로(`_to_idle`, 취소, E-stop)에서도 `handle_active` 와
`_handle_pause` 를 지운다.

### 4.4 60초 자물쇠 보강

`USER_ATTACHED_SUPPRESS_SEC`(60 s)는 "방금 안내한 사람을 새 호출로 오인하지 않기"
위한 임시 시계다. 코드 주석이 이미 예고한 대로 지우지 않고 **조건을 덧댄다**:
60 s 가 지나도 `user_contact` 가 true 인 동안은 억제를 유지한다.

### 4.5 멘트

새로 만드는 문구는 없다. 전부 사용자가 이미 말한 문구이거나 확정본이다.

| 상수(미션) | 문구 | 출처 | 구운 음성 |
| --- | --- | --- | --- |
| `MSG_HANDLE_HINT` (변경) | 손잡이가 진동하고 있습니다. 잡아주세요. | 09-28 사용자 | ❌ **새로 굽는다** |
| `MSG_HANDLE_LOST` (신설) | 안전을 위해 손잡이를 다시 잡아주세요 | 09-03 사용자 | ✅ `handle_grip_lost.wav` |
| `MSG_HANDLE_UNAVAILABLE` (신설) | 손잡이 연결에 문제가 있어 일반 안내로 진행합니다. | 음성 `replies.HANDLE_UNAVAILABLE` | ✅ `reply_handle_unavailable.wav` |
| `MSG_RESUMED` (기존) | ○○로 다시 출발합니다. | 기존 | 기존 |
| `MSG_CANCELED` (기존, 3분 포기) | 안내를 취소했습니다. | 기존 | 기존 |

**구운 음성은 글자가 한 글자라도 다르면 안 쓰인다.** TTS 의 `ment_cache.lookup` 은
앞뒤 공백만 떼고 문장 전체를 대조한다. 그래서 `MSG_HANDLE_LOST` 는 구운 판처럼
**마침표 없이** 적는다. 굽지 않은 문장도 소리는 나지만 그 자리에서 합성해 목소리가
다른 멘트와 달라지고 조금 늦다.

일부러 멘트를 두지 않은 자리: 15초 안에 못 잡았을 때(말없이 온보딩으로), 잡았을 때
(진동 `tick` 만). 실기에서 사용자가 헷갈려하면 그때 문구를 정한다(새 문구는 선승인).

세 문구 모두 '정지'·'멈춰'가 없다 — 로봇 목소리가 긴급어 감시를 스스로 켜는 사고를
피한다. 문구를 바꿀 때 이 규칙을 지킨다.

### 4.6 만들지 않는 것

- `/vica/handle_mode` 토픽 — 공용 계약 신설이라 승인 대상이다. LLM 에 필요한 사정은
  `dialog_state` 두 값(4.7)으로 충분하고, 나머지는 로그로 본다. 앱에 모드를 보여줘야
  하면 그때 `RobotState` 에 필드를 더한다(별도 승인).
- 모드 질문 — `MODE_ASK`·`MODE_ENTER_REQUEST`·`MODE_READY` 는 쓰지 않는다(D2).
  `handle_mode.py` 는 지우지 않고 문서 주석만 "D2 로 대체됨"으로 고친다.
- 좌우회전 진동, 예고/실제 회전 구분(펌웨어 코드 8·9).
- Safety·E-stop 경로 변경 — 손 놓침은 **미션 일시정지**이지 E-stop 이 아니다.
  래치를 걸면 관리자 앱 reset 없이는 못 가 사용자가 혼자 쓸 수 없다.

### 4.7 LLM 이 손잡이 사정을 알게 한다 (D10)

LLM 은 미션이 `/vica/robot_state` 로 방송하는 상황판(`dialog_state`)을 지시문 맨 뒤
`[지금 상황]` 에 붙여 받는다(`vica-voice-llm/src/ledger_view.py`). 그리고 지시문에는
손잡이·터치·진동에 관한 사실이 **한 줄도 없다**(09-28 확인). 이대로면 두 가지가 틀린다.

1. **왜 섰는지 모른다.** 손 놓침으로 선 것과 "잠깐"으로 선 것이 둘 다 `paused` 로
   보인다. 손을 놓쳐 선 사용자가 "왜 안 가요?"라고 물으면 LLM 이 "'다시 가자'라고
   말씀해 주세요"라고 답할 수 있다. 맞는 답은 "손잡이를 잡으시면 출발합니다"다.
2. **잡기 대기를 모른다.** 대기 중 미션 상태는 `idle` 이라 LLM 은 "아무 일도 없음"으로 안다.

#### (가) 상황판 값 2개 추가

`RobotState.dialog_state` 는 자유 문자열이라 **메시지 정의는 바뀌지 않는다.** 미션이
보내는 값과 음성 쪽 번역표만 늘린다.

| 값 | 미션이 내는 때 | `DIALOG_KO` 번역 |
| --- | --- | --- |
| `grip_wait` | 잡기 대기 중(4.3 (가)) — `idle` 대신 | 손잡이 잡기를 기다리는 중(잡으면 안내 시작) |
| `paused_handle` | `_handle_pause=True` 인 PAUSED — `paused` 대신 | 손잡이를 놓쳐 멈춤(다시 잡으면 출발) |

`is_paused` 는 `paused_handle` 에서도 true 다(기존 의미 유지). 음성 쪽에서 `is_paused`
를 보는 곳(`llm_backend.on_robot_state`)은 손대지 않는다.

`dialog_state` 에 값을 더하는 것도 LLM 저장소가 읽는 약속을 늘리는 일이다. 두 저장소를
**같은 날 함께** 바꾸고, 음성 쪽이 모르는 값이 와도 번역표에 없으면 원문 그대로
보여주므로(`DIALOG_KO.get(v, v)`) 순서가 어긋나도 깨지지는 않는다.

#### (나) 손잡이 사용법 사실

지시문은 두 벌이다 — 소리 모드(Realtime 직행) `build_audio_prompt`, 글자 모드(STT →
LangChain·로컬 폴백) `_build_system_prompt`. 둘 다 `langchain_intent_parser.py` 에 있다.
사실은 상수 하나(`HANDLE_FACTS`)로 두고 **두 지시문 모두에** 넣는다. 소리 모드에서는
매 호출 같은 **앞부분**(역할·규칙·목적지 뒤, 상황판 앞)에 둔다 — 앞부분이 같아야
Realtime 캐시 할인이 유지된다. 말투를 지시하지 않고 LLM 이 자기 말로 답하게 둔다
(09-20 사용자 선호: 자유 대사).

```text
[손잡이]
- 로봇 뒤쪽에 손잡이가 있다. 안내를 시작할 때 손잡이가 진동해 자리를 알려 준다.
- 손잡이를 잡으면 손잡이 모드로 안내한다. 이때 손을 놓으면 로봇이 그 자리에 서고
  손잡이가 진동한다. 다시 잡으면 이어서 간다.
- 손잡이를 잡지 않고 따라와도 안내한다. 이때는 손을 놓아도 서지 않는다.
- 손잡이 줄을 당기면 로봇이 느려진다. 끝까지 당기면 선다.
- 도착하면 손잡이가 짧게 세 번 떨린다.
```

넣지 않는 것: 수치(0.5초·2초·80 %). 바뀔 값이고 사용자에게 필요 없다.

"천천히 가 주세요" 같은 요청에 LLM 이 속도를 바꾸는 기능은 없다 — 사실 3번째 줄로
**당기는 법을 알려주는 것**까지다.

## 7. 실기 순서와 합격선

**펌웨어·노드 재기동 전에 서 있는 로봇에서 1~3을 끝낸다.** 주행 명령 전에는 바퀴
상태를 확인한다.

1. **원시값** — 노드를 내리고 `~/touch_monitor.py 60`. 가만히 LOW 0회, 잡으면 LOW.
2. **진동 세기** — 노드를 내리고 `bench_test.py --haptic long|short|tick`. 손바닥으로
   셋이 구별되는가. 약하면 2.2절 3번(게이트)부터.
3. **토픽** — `touch_enabled: true` 로 드라이버만 띄우고 `/vica/smart_handle_state`
   에서 잡고 떼기가 0.2 s 안에 따라오는가.
4. **고쳐 잡기 공백 실측** — 손잡이를 쥐고 복도를 2분 걸으며(로봇은 비활성으로 주행)
   bag 을 뜬다. 가장 긴 "false 구간"이 **0.5 s 보다 충분히 짧은지** 본다. 길면
   `grip_release_grace_sec` 를 그 값 위로 올린다. **이 측정 전에는 활성 주행을 하지 않는다.**
5. 장면 시험:

| 장면 | 합격선 |
| --- | --- |
| A 접근 → 회전 → 진동 + 힌트 → 잡기 | 잡고 2~2.5 s 안에 짧은 진동 1회 → 온보딩 |
| B 안 잡음 | 15 s 뒤 진동 멈춤 → 온보딩, 주행 중 손 안 대도 계속 감 |
| C 활성 주행 중 손 떼기 | 1 s 안에 섬 · 멘트 + 긴 진동 · 다시 잡으면 1~1.5 s 뒤 짧은 진동 + 재출발 |
| D 걸으며 손 고쳐 잡기 10회 | 오정지 0회 |
| E 쥔 채 "잠깐" | 서 있고 자동 출발 안 함 → "다시 가자"로 출발 |
| F 도착 | 짧게 ×3 |
| G 비상정지 버튼 | 긴 진동 1회 (래치 해제·재정지 때마다 1회) |
| H 좌우회전 | 진동 없음 |
| I 터치 선 뽑기(활성 주행 중) | 놓침과 같이 섬(단선 = 놓음) |
| J 핸들 USB 뽑기(활성 주행 중) | "손잡이 연결에 문제가…" 1회 후 비활성으로 계속 감 |
| K 손 놓쳐 선 채 "비카야, 왜 안 가요?" | 답에 "손잡이를 잡으면 출발"의 뜻이 있다. "다시 가자라고 말하라"만 답하면 실패 |
| L 잡기 대기 중 "비카야, 손잡이 어디 있어요?" | "진동하는 곳"의 뜻이 있다 |
| M 주행 중 "좀 천천히 가 주세요" | 손잡이 줄을 당기면 느려진다고 알려준다 |
| N 힌트 멘트 목소리 | 다른 멘트와 같은 목소리(구운 판이 쓰였다) |

## 8. 알려진 위험

- **터치 프레임 폭주**(09-23 1회, `AA 56 01 00 01` 만 초당 8.8 kB, 초음파 0). 원인
  미확정. 보이면 포트를 다시 연다(DTR 리셋). 이때 접촉값이 한쪽에 굳을 수 있어
  시험 J 와 비슷한 상황이 된다.
- **체감 지연.** 놓침 판정 0.5 s + 취소·감속까지 합쳐 사람이 느끼는 건 1 s 안팎이다.
  시험 C 에서 사용자가 "너무 늦다"고 느끼면 먼저 4번 실측값을 보고 줄인다.
- **진동 과다.** 잡기 대기 15 s 동안 진동이 7번 이어진다. 사용자가 불쾌해하면
  `grip_hint_pulse_sec` 를 늘린다.
