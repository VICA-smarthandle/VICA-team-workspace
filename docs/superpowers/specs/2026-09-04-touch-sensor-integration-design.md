# 스마트핸들 터치센서 연동 설계 (1단계)

2026-09-04 · 대상 저장소 `vica_ros2_ws`

## 1. 무엇을 만드나

손잡이 D10 에 붙은 터치센서를 읽어 **ROS 가 "지금 사용자가 손잡이를 잡고 있다"를
알게 하는 것**까지다. 그 신호로 무엇을 할지(모드 진입·손 놓음 정지)는 2단계다.

이 순서인 이유는 상위 계약이 이미 확정돼 있기 때문이다. `vica-voice-llm` 의
`src/handle_mode.py` 가 전체 흐름을 그려두고, 마지막에 이렇게 적어 두었다.

> **지금 구현하지 않는 것** — 터치센서가 미장착이라(`SmartHandleState.msg` 의
> `user_contact` 는 항상 false) 3초를 감지할 수단이 없다. (…) 이 모듈과 문구는
> 그때를 위해 미리 갖춰 둔 것이다.

**음성 쪽은 다 만들어져 있고 신호만 없다.** 이 문서는 그 신호를 만든다.

### 확정된 상위 흐름 (건드리지 않는다)

```text
목적지 확정
  ├─ 상향 통신 두절 ──▶ HANDLE_UNAVAILABLE ──▶ 비활성 모드로 출발
  ▼
MODE_ASK "손잡이를 잡고 스마트핸들 모드를 시작하시겠어요?"
  ├─ "아니요" ──▶ MODE_DECLINED ──▶ 비활성 모드로 출발
  └─ "네"    ──▶ MODE_ENTER_REQUEST "손잡이를 3초간 잡아 주세요."
                    │ 터치 3초  ← mission_manager 가 판정
                    ▼
                 MODE_READY "스마트핸들 모드입니다." ──▶ 출발

주행 중 손을 놓음 (0.5초 유예) ──▶ HANDLE_LOST "손잡이를 잡아 주세요."
```

멘트는 전부 확정본이 있다(`vica-voice-llm/src/replies.py`). **새로 만들지 않는다.**
문구에 '정지'·'멈춰'가 없는 것은 의도된 것이다 — 상시 긴급어 감시가 로봇 자기
목소리를 E-stop 으로 인식하는 자가 트리거를 피하려고 "섭니다"로 고른 결과다.

### 범위

## 2. 하드웨어 사실

| | |
| --- | --- |
| 핀 | D10 |
| 종류 | 정전식 터치 모듈 |
| 극성 | **잡으면 HIGH** (사용자 확인, 2026-09-04) |

## 3. 상향 프레임 — 터치 전용을 새로 판다

초음파가 이미 상향 프레임을 쓴다.

```text
AA 55 seq d0L d0H d1L d1H xor      8B · 약 4.8 Hz
```

**여기에 터치를 얹지 않는다.** 두 가지 이유다.

- **주기가 다르다.** 초음파 4.8 Hz 는 측정 시간이 정하는 물리 한계다. 그런데 손
  놓음 판정 유예는 0.5초라, 4.8 Hz 면 그 사이 2~3 샘플뿐이다. 한 프레임만 놓쳐도
  판정이 흔들린다.
- **옛 펌웨어와 섞이면 조용히 죽는다.** 8B 프레임을 9B 로 늘리면 헤더는 같은데
  길이가 달라, 파서가 체크섬 실패 → 1바이트 밀기를 반복하며 **초음파까지 함께**
  멈춘다. 로그에는 아무것도 안 남는다.

그래서 헤더가 다른 짧은 프레임을 따로 보낸다.

```text
AA 56 seq flags xor                5B · 20 Hz
        │     │     └ seq ^ flags
        │     └ bit0 = 터치(1=잡음). bit1~7 예약(0)
        └ 0~255 순환. 누락 감지용
```

- 두 번째 바이트 `0x56` 이 초음파의 `0x55` 와 다르므로 파서가 헤더로 분기한다.
- 5 B × 20 Hz = 100 B/s. 115200 bps 에서 무시할 수준이고 초음파와 섞여도 여유롭다.
- **옛 젯슨 + 새 펌웨어**: 옛 파서는 `AA 56` 을 못 알아보고 1바이트씩 밀며 버린다.
  초음파 프레임은 그대로 통과한다 — 조용히 무시될 뿐 깨지지 않는다.
- **새 젯슨 + 옛 펌웨어**: 터치 프레임이 안 와서 상향 신선도가 stale 로 남는다.
  상위는 `HANDLE_UNAVAILABLE` 로 처리하므로 **아예 묻지 않는다.** fail-safe 다.

### 펌웨어가 하는 일과 하지 않는 일

- **한다**: D10 을 읽어 20 Hz 로 그 순간의 값을 보낸다. 하드웨어 잡음만 짧게
  누른다(20 ms 디바운스).
- **하지 않는다**: 3초 진입 판정, 0.5초 놓침 판정, 상태 기억. 전부 위에서 한다.

초음파와 같은 원칙이다 — 펌웨어는 사실만 보내고 해석은 노드가 한다
(`ultrasonic_frame.py`: "펌웨어 원시값 그대로 … 해석은 노드 쪽 책임이다").
20 ms 디바운스는 판정이 아니라 접점 잡음 제거다. 사람 손의 3초·0.5초와는
두 자릿수 차이라 판정에 영향을 주지 않는다.

## 4. ROS 계층

### 파서 (`ultrasonic_frame.py` → 이름 유지)

`FrameAccumulator` 가 이미 스트림 누적·재동기를 한다. 여기에 헤더 분기를 더한다.
초음파 파싱 경로는 손대지 않는다.

```python
UltrasonicFrame   # 기존
TouchFrame        # 신설: seq, touched: bool
```

동기가 깨졌을 때 1바이트씩 미는 기존 동작이 그대로 두 프레임 모두를 회복시킨다.

### `SmartHandleState.msg` — 공용 계약 변경

```
bool user_contact          # 터치센서 미장착 확정. 항상 false   ← 현재
```

두 곳을 바꾼다.

| 필드 | 변경 |
| --- | --- |
| `user_contact` | 실제 터치 상태. 주석의 "미장착 확정" 삭제 |
| `uplink_fresh` | **신설.** 상향 프레임이 최근에 왔는가 |

`uplink_fresh` 가 필요한 이유는 상위 계약이 그걸 보고 갈라지기 때문이다 — 상향이
끊겼으면 모드를 **묻지도 않는다**. 이 필드가 없으면 음성은 `user_contact=false` 를
"손을 안 잡았다"와 "센서가 죽었다" 중 무엇인지 구분할 수 없다.

`user_contact` 는 `uplink_fresh` 가 false 일 때 **항상 false** 로 낸다. 마지막
값을 붙들고 있으면 죽은 센서가 "잡고 있다"고 말하게 된다.

### 발행 주기 — 변화 시 즉시 + 주기 유지

`SmartHandleState` 는 지금 `diag_rate_hz` 2 Hz 다. 그대로 두면 0.5초 판정에
샘플이 1개뿐이라 부족하다. 그렇다고 20 Hz 로 올리면 진단 메시지가 10배가 된다.

**터치 상태가 바뀐 순간에만 추가로 발행한다.** 주기 발행 2 Hz 는 그대로 두고,
`user_contact` 나 `uplink_fresh` 가 뒤집히면 그 자리에서 한 번 더 낸다. 그러면
상위가 겪는 지연은 상향 프레임 주기(50 ms)뿐이고 평소 대역폭은 안 늘어난다.

## 5. 실패 처리

| 상황 | 동작 |
| --- | --- |
| 상향 프레임 두절 | `uplink_fresh=false`, `user_contact=false`. 상위가 `HANDLE_UNAVAILABLE` |
| 시리얼 포트 끊김 | 기존 `FAULT_WRITE_FAIL` 경로 그대로. 재연결도 기존 로직 |
| 쓰레기 바이트 | 파서가 1바이트씩 밀며 재동기 (기존 동작) |
| 체크섬 불일치 | 그 프레임만 버린다. 카운터로 세어 진단에 남긴다 |

`uplink_fresh` 의 시한은 `ultrasonic_stale_warn_sec`(2.0)과 따로 둔다. 터치는
20 Hz 라 훨씬 짧아도 되고, 길게 잡으면 죽은 센서를 오래 살아 있다고 말한다.
**0.5초**로 시작한다 — 프레임 10개 분량이며, 손 놓음 유예와 같은 값이라 상위가
겪는 최악 지연이 두 배를 넘지 않는다.

## 7. 하지 않는 것

- **3초·0.5초 판정** — 소유자는 `mission_manager_node` 다(2단계).
- **`/vica/handle_mode` 신설** — 공용 계약 신설이라 별도 승인 대상.
- **LED·서보 변경** — 표 8번에서 "현행 유지 0" 으로 확정됐다.
- **멘트 추가** — 확정본이 이미 있다. 새 문구는 만들지 않는다.
- **음성 쪽 모드 질문 활성화** — 신호가 올라온 뒤 별도로 켠다.
