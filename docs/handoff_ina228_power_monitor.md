# INA228 배터리 적산계 핸드오프 — I2C 통신 성공, 칩 불량 판정

작성 2026-09-10 (Jetson 세션). 대상은 배터리 전력 적산 기능을 이어받는 사람 또는
에이전트다.

## 결론 (먼저 읽는다)

**I2C 통신은 해결됐다. 칩의 측정부(ADC)가 죽어 있어 모듈 교체가 필요하다.**

| 항목 | 상태 |
| --- | --- |
| I2C 배선·통신 | ✅ **해결** — `/dev/i2c-7` 주소 `0x40`, 2000회 무오류 |
| 칩 신분 확인 | ✅ INA228 rev 1 (`MFG 0x5449` / `DEV 0x2281`) |
| 측정 기능 | ❌ **사망** — 전압·전류·온도 전부 `0`, 변환이 한 번도 안 일어남 |
| 전원 품질 조치 | ❌ 디커플링 0.1 µF + 물리 전원 사이클로도 복구 안 됨 (3-2절) |
| 젯슨 쪽 결함 | 없음 — 커널 에러 0줄, 버스 정상 |
| 션트 저항값 | ✅ **0.00075 Ω** (외부 분류기 100 A/75 mV, 내부 션트 제거됨) |

소프트웨어로 고칠 수 있는 종류가 아니다. **다음 사람의 할 일은 모듈 교체이며,
교체 후에는 이 문서 5-4절 절차만 밟으면 된다.**

## 1. 하드웨어 사실 (2026-09-03·09-10 실측)

캐리어보드는 **Seeed reComputer Robotics J401** 이다. NVIDIA 데브킷이 아니고
**40핀 헤더가 없다.** GH1.25 4핀 I2C 커넥터 두 개가 전부다.

| 커넥터 | 장치 노드 | 하드웨어 | 비고 |
| --- | --- | --- | --- |
| IIC0 (J7) | `/dev/i2c-1` | `c240000.i2c` | 보드 자체 INA3221 이 `0x40` 을 이미 쓴다 |
| IIC1 (J6) | `/dev/i2c-7` | `c250000.i2c` | **INA228 은 여기 꽂는다.** 현재 결선 위치 |

- 핀 순서는 두 커넥터 모두 **1 GND · 2 SDA · 3 SCL · 4 VDD** 다. 신호 3.3 V.
  모듈 쪽 순서가 다르면(STEMMA QT 는 `GND·V+·SDA·SCL`) 케이블에서 바꿔 꽂는다.
  **2026-09-10 에 이 핀 순서를 바로잡은 뒤 검출에 성공했다.**
- `/dev/i2c-5`(31b0000) 는 미배선이다. 스캔하면 dmesg 에
  `tegra-i2c 31b0000.i2c: I2C transfer timed out` 이 쌓인다. **고장이 아니다.**
- 커널 `ina2xx.ko` 는 INA231 까지만 지원하고 INA228 드라이버가 없다. `/sys/class/hwmon`
  에 저절로 나타나지 않으므로 사용자 공간에서 `smbus2` 로 직접 읽는다.

## 2. 증상 — 통신은 완벽한데 측정만 0

### 2-1. 정상인 것

| 검사 | 결과 |
| --- | --- |
| 신분증 | `MANUFACTURER_ID 0x5449`("TI") · `DEVICE_ID 0x2281` (INA228 rev 1) |
| 통신 스트레스 2000회 | **성공 2000 / 오류 0**, 초당 4,846회 |
| 레지스터 쓰기·되읽기·원복 | `SHUNT_CAL`·`ADC_CONFIG` 모두 정상 |
| 리셋 기본값 12개 | **11개 완벽 일치** (`SOVL 0x7FFF`·`PWR_LIMIT 0xFFFF` 등 포함) |
| 커널 에러 (`c250000`) | **0줄** |

### 2-2. 죽은 것

| 레지스터 | 관측값 | 정상값 |
| --- | --- | --- |
| `DIETEMP` (0x06) | `0x0000` = **0.00 °C**, 반복 읽어도 미동 | 실온이면 `0x0C80` 부근 |
| `DIAG_ALRT` (0x0B) | `0x0000` | `0x0001` |
| └ `MEMSTAT` (bit0) | **0 = 트림 메모리 체크섬 오류** | 1 |
| └ `CNVRF` (bit1) | **0 = 변환 완료가 한 번도 안 됨** | 1 |
| `VSHUNT`·`VBUS`·`CURRENT` | 24비트 전부 `00 00 00` | — |

**핵심은 `DIETEMP` 가 정확히 0 이라는 점이다.** 전압·전류는 부하가 없으면 진짜 0 일
수 있지만, 칩 자기 온도가 0.00 °C 일 수는 없다. 즉 **"0 을 측정한 것" 이 아니라
"측정이라는 일 자체가 한 번도 일어나지 않은 것"** 이다. `CNVRF=0` 이 이를 뒷받침한다.

### 2-3. 재확인 이력 (2026-09-10)

검출 성공 이후 조건을 바꿔가며 **4회 재확인했고 결과는 매번 동일했다.**

| 시점 | 조치 | 결과 |
| --- | --- | --- |
| 최초 검출 | 핀 순서 교정 | 통신 ✅ / 측정 ❌ |
| 2회 | 소프트 리셋 | 변화 없음 |
| 3회 | 물리적 전원 사이클 | 변화 없음 |
| 4회 | USB 포트 재연결 | 변화 없음 (아래 4-1 참고) |

**칩 온도 0.00 °C 는 바깥 배선으로 바뀌지 않는 값이다.** 측정 대상(배터리)이 물려
있든 없든, USB 가 꽂혀 있든 아니든, 칩에 전원이 들어와 있으면 실온이 나와야 한다.
증상 판정에서 이 값을 기준으로 삼는다.

## 3. 칩 불량으로 판정한 근거

전압 실측 없이 소프트웨어만으로 도달한 결론이다. 근거는 셋이다.

1. **통신 2000회 무오류 (초당 4,846회).** VS 가 부족하면 이 속도에서 반드시 흔들린다.
2. **리셋 기본값 12개 중 11개 완벽 일치.** 디지털 코어와 리셋 로직은 정상이다.
3. **ADC 를 5가지 설정으로 달래도 전부 `CNVRF=0`.**
   (연속 all / 트리거 all / 트리거 온도만 / `ADCRANGE=1` / 변환시간·평균 최대)

**결정 논리:** INA228 데이터시트의 **동작 하한 2.7 V 는 칩 전체에 적용된다.** 디지털부와
아날로그부가 따로 노는 전압 구간이 아니다. 디지털이 이만큼 완벽하면 VS 는 하한 위이고,
그런데도 ADC 가 안 돈다면 원인은 전원이 아니라 칩이다. `MEMSTAT` 은 공장에서 구운
트림 메모리의 CRC 검사 결과이며 **소프트웨어로 다시 쓸 수 없다.**

### 3-1. 전원·배선도 배제됐다 (2026-09-14)

| 축 | 확인 | 결과 |
| --- | --- | --- |
| 전원 공급 | 모듈 **전원 LED 점등**, 사용자 실물 확인 | ✅ 정상 |
| 배선 단선·접촉 | 사용자 실물 확인 | ✅ 정상 |
| GND·SDA·SCL | 통신 500/500 무오류가 증명 | ✅ 정상 |
| 읽기 방식·코드 | **raw I2C 대조군** — 같은 순간 같은 방식으로 `MFG_ID`는 `54 49` 가 읽히는데 `DIETEMP`·`VBUS` 만 0 | ✅ 무관 |
| 커널 드라이버 부재 | `ina2xx.ko` 는 INA231 까지, `ina238` 은 이 커널에 없음. 그러나 **애초에 드라이버를 안 쓰고 직접 읽는다** | ✅ 무관 |
| CONFIG 비트 | RST·RSTACC·CONVDLY(0)·TEMPCOMP·ADCRANGE 전수 확인 | ✅ 막는 설정 없음 |
| shutdown→continuous 전환 | 1.5 초간 0.25 초 간격 감시 | ✅ `CNVRF` 끝내 0 |

**전원 LED 점등이 "기생 급전" 가설을 닫았다.** I2C 풀업으로 새어 드는 전류(0.3 mA 남짓)로는
LED 를 켤 수 없다. 즉 VS 에 실제 전원이 공급되는데도 ADC 가 안 도는 것이다.

### 3-2. 전원 품질 축도 닫혔다 (2026-09-14 저녁)

TI 는 이 체크섬 오류의 원인으로 **전원 품질**을 지목한다(E2E 스레드 1083239, 데이터시트 9.2:
*"Place the required power-supply bypass capacitors as close as possible... typical value 0.1 µF.
Applications with **noisy or high-impedance power supplies** may require additional decoupling"*).
젯슨 GH1.25 커넥터에서 가는 케이블로 받는 이 구성은 정확히 "고임피던스 전원"에 해당하므로
실제로 조치해 시험했다.

| 시도 | 결과 |
| --- | --- |
| 소프트 리셋 50회 이상 (`CONFIG` bit15) | 전부 실패 |
| **0.1 µF 디커플링 커패시터를 VS–GND 에 장착** | **실패** |
| **커패시터 장착 상태에서 실제 물리 전원 사이클** (분리 확인 후 재결선) | **실패** |
| 사용자 제공 진단 스크립트 `ina228_diag.py`(다른 ADC 설정 0xF922·평균 16회·보정 우회) | 전부 `0x000000` |

**`RST` 비트는 데이터시트상 파워온 리셋과 동일하다**(*"generates a system reset that is the same
as power-on reset"*). 다만 소프트 리셋에는 **VS 가 0 V 에서 올라오는 구간이 없어** 커패시터가
일할 기회가 없다. 그래서 물리 전원 사이클을 따로 했고, 그것도 실패했다.

→ **전원 축은 완전히 닫혔다. 칩 트림 메모리 손상으로 확정한다.**

> **커패시터는 새 모듈에도 그대로 둔다.** 원인이 무엇이었든 전원 품질을 받쳐 주는 것은 손해가
> 아니고, 이 고장이 전원 때문이었다면 재발을 막는다.

## 4. 이미 해봤고 실패한 것 — **다시 시도하지 말 것**

| 시도 | 결과 |
| --- | --- |
| 소프트 리셋 (`CONFIG` bit15 `RST`) | `MEMSTAT` 그대로 0. 무효 |
| **물리적 전원 사이클** (커넥터 분리 후 재결선) | 무효. 트림 CRC 는 POR 에서 재검사되는데 그것도 통과 못 했다 |
| ADC 모드 5종 강제 변환 | 전부 `CNVRF=0` |
| `ADCRANGE` 변경 | 무효 |
| 전 버스(0·1·2·4·5·7·9) 전 주소 스캔 | INA228 은 `i2c-7 0x40` 하나뿐 |

**소프트웨어로 짜낼 수 있는 검사는 전부 소진했다.** 젯슨에서 커넥터 전압을 읽을 방법도
없다 — 보드 INA3221 은 `VDD_IN`·`VDD_CPU_GPU_CV`·`VDD_SOC` 세 레일만 재고,
I2C 커넥터 전용 regulator 도 없다.

### 4-1. 헛다리 — 오해하지 말 것

| 관측 | 진실 |
| --- | --- |
| `/sys/bus/i2c/devices/7-0021` (pca9535) | **device-tree 선언만 있고 드라이버 미바인딩·실제 무응답.** 스캔에 안 잡히는 게 정상이다. "있던 장치가 사라졌다" 는 단서가 아니다 |
| `/sys/bus/i2c/devices/1-0025` (fusb301) | 위와 같다 |
| `i2c-0` 의 `0x42` | INA228 가능 주소지만 신분증 레지스터가 전부 `0x0000` 인 모듈 내부 장치다 |
| `i2c-1` 의 `0x40` 이 `UU` | 커널이 점유한 **진짜 보드 INA3221** 이다. hwmon 값(11.96 V·856 mA)이 정상이라 주소 충돌 흔적은 없다 |
| `i2c-5` 타임아웃 | 미배선 버스라 정상이다 |
| `i2c-9` "detection commands 미지원" | SOC 내부 어댑터다. 커넥터가 아니다 |
| **USB 포트를 바꿔 꽂기** | INA228 은 USB 가 아니라 **J6 커넥터(GH1.25 4핀) 직결**이다. 서로 다른 경로이므로 USB 포트와는 무관하다. 2026-09-10 에 시도했으나 dmesg 에 USB 이벤트조차 남지 않았고 증상도 그대로였다 |

## 5. 다음 사람이 할 일

### 5-1. 교체 전 — 공짜 확인 (선택)

모듈을 **IIC0(J7)** 로 옮겨 꽂아본다. 도구도 배선 작업도 필요 없다. J6 커넥터나
케이블 자체의 접촉 불량이라면 여기서 갈린다.
단 J7 은 보드 INA3221 이 `0x40` 을 쓰고 있어 주소가 겹친다. **확인만 하고 즉시 뺀다.**
잠깐 값이 깨질 뿐 고장나지 않는다.

### 5-2. 전원(VS) 을 확인하는 수단은 셋뿐이다

| 방법 | 가능 |
| --- | --- |
| 멀티미터로 모듈 `VCC`–`GND` 측정 | ✅ 가장 확실 |
| Arduino Nano `3V3` 핀으로 급전해보기 | ✅ 점퍼선 2개 (아래 절차) |
| 젯슨 소프트웨어로 읽기 | ❌ **불가능** — 커넥터 4번 핀에 연결된 ADC 가 없다 |

### 5-3. 전원 문제를 완전히 배제하고 싶다면

로봇의 **Arduino Nano**(`/dev/ttyUSB0`, CP2102)를 전원으로 쓴다. **펌웨어는 건드리지
않는다** — Nano 는 USB 만 꽂혀 있으면 스케치와 무관하게 `3V3` 핀에서 전압이 나온다.

- 젯슨 커넥터의 **4번(VDD) 선만 분리**하고 GND·SDA·SCL 은 그대로 둔다
- 모듈 `VCC` ← Nano **`3V3`** 핀 (D13 옆, AREF 사이)
- 모듈 `GND` ← Nano `GND`

> ⚠️ **`5V` 핀은 절대 쓰지 않는다.** INA228 모듈 대부분이 I2C 신호선을 전원에
> 풀업시켜 두는데, 5 V 로 급전하면 그 5 V 가 젯슨의 3.3 V I2C 라인에 실려
> **젯슨이 상할 수 있다. USB 포트에서 5 V 를 따는 것도 같은 이유로 금지다.**

살아나면 커넥터 급전 문제, 그대로면 칩 불량 확정이다.

### 5-4. 교체 후 절차

```bash
python3 scripts/vica_ina228_probe.py scan              # i2c-7·1 에서 INA228 찾기 (읽기 전용)
python3 scripts/vica_ina228_probe.py check --bus 7     # 신분증·설정·진단 비트 (읽기 전용)
```

`check` 출력에서 **다음 둘을 반드시 확인한다.**

| 항목 | 합격 기준 |
| --- | --- |
| `MEMSTAT` | **1** (0 이면 또 불량품이다) |
| 칩 온도 | **실온 근처** (0.00 °C 면 ADC 가 안 도는 것) |

둘 다 통과하면 션트값을 넣어 실측에 들어간다.

```bash
python3 scripts/vica_ina228_probe.py read --bus 7 --shunt 0.00075 --max-current 20
python3 scripts/vica_ina228_probe.py read --bus 7 --shunt 0.00075 --max-current 20 \
    --csv ~/vica_power_logs/run1.csv
python3 scripts/vica_ina228_probe.py reset-acc --bus 7   # ENERGY·CHARGE 를 0 으로
```

### 5-5. 션트 저항값을 반드시 확보할 것

**`SHUNT_CAL` 이 0 이거나 션트값을 모르면 전류·전력·적산이 전부 0 이다**(데이터시트 8.1.2).
전압(`VBUS`)만 션트값 없이 읽힌다. 모듈 기판의 저항 실크(`R010`=0.01 Ω, `R015`=0.015 Ω 등)
또는 판매 페이지에서 확인하고 이 문서에 적어 둔다.

- **현재값: 외부 분류기 100 A / 75 mV → `0.00075 Ω`(0.75 mΩ)** (2026-09-14 확인).
  모듈 내부 션트는 **제거했다.** 외부 분류기와 병렬로 걸리면 측정이 엉키기 때문이며,
  외부 션트를 쓰는 이상 새 모듈에서도 같은 작업이 필요하다.
- **`ADCRANGE=1` 이 스크립트 기본값이다**(2026-09-14). 0.75 mΩ 기준 측정 상한은 ADCRANGE=0 이 218 A, 1 이 54 A 인데
  로봇은 수 A 수준이라(보드 INA3221 의 `VDD_IN` 이 856 mA) 54 A 로도 넉넉하고 분해능이 4배다.
  `SHUNT_CAL` 계산 시 ×4 를 잊지 말 것.
- 실측 명령: `read --bus 7 --shunt 0.00075 --max-current 20`
  (`--max-current` 는 모터 가속 구간까지 감안한 값. 실측 후 조정한다)

## 6. 도구

`scripts/vica_ina228_probe.py` — **2026-09-14 dev 에 들어갔다**(그 전에는
`docs/carto-cm8-cm9` 계열에만 있었다). ROS 노드가 아닌 진단 도구다. 토픽을 만들지 않고
어떤 launch·rc 도 이 파일을 참조하지 않으며 운영 경로(Mission·Safety·CAN)와 무관하다. `[TEST ONLY]`

**`--adcrange` 기본값은 1 이다**(2026-09-14 변경). 이 로봇의 0.75 mΩ 외부 분류기에 맞춘 값이며,
큰 션트를 쓸 일이 생기면 `--adcrange 0` 을 명시한다.

| 하위 명령 | 하는 일 |
| --- | --- |
| `scan` | i2c-7·1 에서 INA228 신분증 탐색 (읽기 전용) |
| `check --bus 7` | 신분증·설정·진단 비트 출력 (읽기 전용) |
| `read --bus 7 --shunt <Ω> --max-current <A>` | 실측. `--csv` 로 기록 |
| `reset-acc --bus 7` | `ENERGY`·`CHARGE` 를 0 으로 |
| `selftest` | 하드웨어 없이 변환 수식 검증 |

INA228 요점(데이터시트 SLYS021A):

- 주소 `0x40~0x4F`, A1/A0 핀 조합. 기본(둘 다 GND) `0x40`
- `VSHUNT`/`VBUS`/`CURRENT` 는 24비트 중 상위 20비트(`>>4`), 2의 보수
- `CURRENT_LSB = 최대 예상 전류 / 2^19`,
  `SHUNT_CAL = 13107.2e6 × CURRENT_LSB × R_SHUNT` (`ADCRANGE=1` 이면 ×4)
- `Power[W] = 3.2 × CURRENT_LSB × POWER`
- **적산 레지스터는 휘발성이다.** 전원이 끊기면 0 이 되고 40비트를 넘치면 0 부터 다시 센다
- 전류가 음수면 `IN+`/`IN–` 가 뒤집힌 것이다. 공통 GND 필수. `VBUS` 상한 85 V

## 7. 현재 상태

- 진단 중 쓴 레지스터(`CONFIG`·`ADC_CONFIG`·`SHUNT_CAL`)는 **전부 원복했다.**
  칩 설정은 공장 기본값 상태다.
- 젯슨 쪽 설정은 아무것도 바꾸지 않았다. ROS 노드도 만들지 않았다.
- 이 기능은 아직 어떤 launch 에도 들어가 있지 않다. 운영 경로에 영향이 없다.
