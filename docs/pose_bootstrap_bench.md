# 초기 위치 확인 속도 — 기준값

앱에서 Nav2 초기 위치를 잡을 때 "여기가 맞는지 확인" 버튼이 얼마나 걸리는지다.
사람이 버튼을 누르고 기다리는 동작이라 체감이 바로 걸린다.

재는 도구는 `vica_ros2_ws/scripts/vica_pose_score_bench.py` 하나다. 개발 PC 와
젯슨에서 **같은 것을 같은 방식으로** 재려고 만들었다.

```bash
cd vica_ros2_ws
python3 scripts/vica_pose_score_bench.py --repeat 7
```

---

## 1. 왜 개발 PC 값을 그대로 믿으면 안 되는가

젯슨은 이 계산을 혼자 돌리지 않는다. 같은 시간에 Nav2 · 카메라 · rosbridge ·
motor 가 같은 CPU 를 쓴다. 2026-08-01 실측이 이렇다.

```
전체 CPU   346 % / 800 %
load avg   최대 13.8      <- 코어 8개를 넘는다. 실행 대기 큐가 쌓였다는 뜻
```

그래서 아래 표는 **한가한 값 하나가 아니라 경합을 걸어 가며 잰 띠**로 남긴다.
젯슨에서 나올 값은 이 띠의 어딘가다.

## 2. 개발 PC 기준값 (2026-08-25)

```
machine    myw x86_64
cpu        Intel Core Ultra 7 155H · 22 스레드 · 최대 4.80 GHz
mem        30 GB
numpy      1.21.5      scipy 1.8.0
map        maps/vica_map_0630.yaml   572 x 443 = 253,396 칸 · 0.05 m
scan       원본 721 빔 -> 필터·솎기 뒤 180 빔 (상한)
자세        (-2.67, -5.21)   빔이 가장 많이 잡히는 자리를 골랐다 = 가장 느린 경우
```

중앙값(ms). `--busy N` 은 같은 코어를 N 개의 프로세스가 함께 쓰게 만든 것이다.

| 재는 상황 | 거리표 만들기<br>(노드 시작 시 1회) | **확인 · 방향 지정**<br>후보 2,299 | 확인 · 방향 모름<br>후보 8,712 |
| --- | ---: | ---: | ---: |
| 코어 22개 자유 | 6.7 | 8.0 | 21.1 |
| 1코어 고정, 경합 없음 | 6.9 | 8.1 | 22.2 |
| 1코어 고정 + 경합 1 | 15.7 | 17.8 | 47.4 |
| **1코어 고정 + 경합 3** | **26.3** | **32.6** | **83.8** |

읽는 법 세 가지.

1. **코어를 늘려도 안 빨라진다.** 22개 자유와 1코어 고정이 같다. numpy 한 덩어리
   계산이라 한 코어에서 돈다. 젯슨 코어 8개 중 1개만 있으면 되는 것이고, 뒤집으면
   **여유 코어가 있어도 도움이 안 된다.**
2. **경합에는 선형으로 느려진다.** 경합 3이면 4배다. 젯슨의 load 13.8 은 코어당
   1.7 개가 대기하는 상태라 이 표의 "경합 1~3" 칸 사이다.
3. **방향을 지정하면 2.6배 빠르다.** 후보가 8,712 -> 2,299 로 주는 만큼 그대로다.
   4방향 버튼이 정확도만이 아니라 속도에도 값을 한다.

## 3. 젯슨에서 예상되는 값과 판정선

젯슨 Orin NX 의 Cortex-A78AE 는 이 PC 의 P 코어보다 대략 3~4배 느리다. 위 표의
"경합 1~3" 칸에 그 배수를 곱하면:

```
확인 · 방향 지정   32.6 ms x 3~4  =  약 100 ~ 130 ms   [TARGET]
확인 · 방향 모름   83.8 ms x 3~4  =  약 250 ~ 340 ms   [TARGET]
```

**[미검증]** 실기에서 재기 전까지는 추정이다. 젯슨에서 잴 때는 **평소 주행하듯
스택을 다 띄운 상태**에서 돌려야 의미가 있다. 스크립트가 load average 를 같이
찍으므로 그때 얼마나 바빴는지가 결과에 남는다.

판정선:

| 확인 1회 | 판정 |
| --- | --- |
| 1초 미만 | 그대로 간다. 앱에 진행 표시도 필요 없다 |
| 1 ~ 3초 | 앱에 진행 표시(spinner)를 붙인다 |
| 3초 초과 | `pose_score.COARSE_YAW_STEP` 을 5도 -> 10도 로 올린다. 후보가 절반이 된다 |

거리표 만들기는 노드가 켜질 때와 지도가 바뀔 때만 도는 1회성이라 판정선이 없다.
다만 1초를 넘으면 첫 확인이 그만큼 늦어지므로 로그로 확인한다.

## 4. scipy 가 없을 때

`build_likelihood_field` 는 scipy 의 정확한 EDT 를 쓰고, 없으면 numpy 만으로 하는
chamfer 대비책으로 내려간다. 대비책은 거리를 최대 4% 크게 잡는데, `sigma_hit` 이
0.2 m 라 점수 차이가 1%p 안이다(`test_chamfer_fallback_is_close_enough_to_scipy`).

젯슨에 scipy 가 있는지 먼저 본다. 스크립트 머리에 찍힌다.

```bash
python3 -c "import scipy; print(scipy.__version__)"
sudo apt install python3-scipy   # 없으면
```
