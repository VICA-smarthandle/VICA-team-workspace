# "비카야" 호출 — 상황별 시나리오와 멘트 (2026-09-10)

호출 접근 기능이 **어떤 상황에서 무엇을 하고 무슨 말을 하는지**를 한곳에 모은다.
실기 중 곁에 두고 보는 용도다. 멘트는 코드의 원문 그대로이며(`mission_logic.py`
`MSG_*`, 음성 `replies.py`), 바뀌면 이 문서도 함께 고친다.

기준: ROS2 `feat/handle-side-call` (`affb594`), 음성 dev (`ffeb436`). 뒤쪽 호출·
손잡이 안내는 **실기 미검증**이다.

관련: 설계 `docs/superpowers/specs/2026-09-10-voice-call-approach-design.md` ·
마이크 사실 `docs/beamforming_doa_facts.md` · 실기 기록 `devlog/2026-09-10-비카야-호출-접근.md`

---

## 0. 한눈에

```
"비카야"  →  로봇: "네?"
    │
    ├─ 대기 중이 아니면 ────────────────────▶  회전 없음. 기존 대화로 처리 (§3)
    │
    ├─ 뒤(핸들 쪽 180°±45°)에서 ────────────▶  회전 없음. 곧바로 질문 (§1-C)
    │
    ├─ 정면 10° 이내 ───────────────────────▶  회전 없음. 8초 찾기 (§1-A)
    │
    └─ 그 밖(측면·앞쪽) ─────────────────────▶  소리 쪽으로 회전 → 8초 찾기 (§1-B)
                                                   │
                                          사람이 보이면 ──▶  §2 접근·질문
                                          안 보이면  ──▶  조용히 원위치 복귀
```

**세 가지 원칙**

1. **로봇이 혼자 서 있을 때만 돈다.** 누군가를 상대하는 중이면 절대 안 돈다.
2. **돌아서 본다는 것은 앞쪽 사람에게만 맞다.** 핸들이 뒤에 있어서, 뒤에서 부른
   사람을 보려고 돌면 핸들을 빼앗는다. 그래서 뒤쪽은 돌지 않는다.
3. **되돌릴 수 없는 회전은 하지 않는다.** 1 m 안이면 180° 회전이 손잡이로 사람을
   칠 수 있어 생략한다.

---

## 1. 부른 방향과 거리에 따라

마이크는 **방향만** 알고 **거리는 모른다.** 거리는 회전한 뒤 카메라가 잰다.

### 1-A. 정면 (±10° 이내)

이미 그쪽을 보고 있다. **돌지 않고** 8초 동안 카메라로 찾는다.

| 결과 | 로봇 |
| --- | --- |
| 사람이 보임 | §2 로 |
| 안 보임 | 아무 말 없이 대기로 |

### 1-B. 측면·앞쪽 (10° ~ 135°)

소리 쪽으로 **짧은 쪽으로** 제자리 회전한다(최대 180°, 약 0.38 rad/s → 180° 에 약 8초).
회전이 끝나면 8초 동안 찾는다.

| 결과 | 로봇 |
| --- | --- |
| 사람이 보임 | §2 로 |
| 안 보임 | **아무 말 없이** 원래 각도로 되돌아 돈다 |

**한 번 부르면 두 번 돈다** — 찾으러 한 번, 못 찾으면 원위치로 한 번. 180° 면
왕복 약 16초. 실기의 "왜 자꾸 도나"는 대부분 이 두 번째 회전이다.

**못 찾았을 때 조용한 것은 사용자 결정**(2026-09-10) — 복도 소음 오인에 로봇이
말을 걸면 주변을 놀래킨다.

### 1-C. 뒤 — 핸들 쪽 (180° ± 45°) `[실기 미검증]`

부른 사람이 **이미 핸들 옆에 있다.** 돌면 핸들을 빼앗으므로 **돌지 않는다.**
카메라 확인 없이 곧바로 §2 의 질문을 한다 — 소리가 핸들 쪽에서 왔다는 것 자체가
증거다. 수락해도 회전하지 않는다.

**한계**: 5 m 뒤에서 불러도 같은 처리다(거리를 모르니까). 그 사람은 걸어와서
잡아야 한다. 라이다로 뒤쪽 거리를 재면 가를 수 있으나 아직 안 했다.

### 1-D. 가까이 (1.5 m 이내) — 근접 호출

회전(1-A/B) 뒤 카메라가 **1.5 m 안**의 사람을 보면 **걸어가지 않고** 그 자리에서
질문한다. 접근 목표(사람 앞 1.1 m)가 이미 지나간 자리라 갈 곳이 없다.

| 거리 | 수락 후 회전 |
| --- | --- |
| 1.0 ~ 1.5 m | 180° 회전해 핸들을 내준다 |
| **1.0 m 미만** | **회전 없음** — 손잡이가 사람을 칠 수 있다 |

### 1-E. 멀리 (1.5 ~ 8 m)

사람 앞 1.1 m 까지 걸어가서 질문한다. 8 m 를 넘으면 카메라가 못 믿는다(2026-09-09 실측).

## 2. 접근 질문 이후 — 대답에 따라

### 질문

> **"안녕하세요? 저는 시각장애인 안내로봇 비카입니다! 저와 함께 목적지까지
> 동행해보시는건 어떠세요? 안내를 받으시겠어요?"**

(녹음 재생, 10.6초. 답 대기 8초는 **재생이 끝난 시점부터** 센다.)

### 2-A. "네"

**회전이 필요한 경우** (앞쪽에서 멀리 · 1.0~1.5 m):

```
"네, 잠시만 기다려주세요. 로봇이 회전하니 주의하세요."
    ↓ 180° 회전 (약 8초) — 핸들을 사람 쪽으로
"손잡이는 지금 계신 쪽에 있습니다. 진동이 나는 곳을 잡아주세요."   + 손잡이 진동(long)
"안녕하세요? 반갑습니다! 저에게 말을 거실 때는 '비카야'라고 불러주세요.
 자, 이제 어디로 가고 싶으신가요?"
```

**회전이 없는 경우** (뒤쪽 호출 · 1.0 m 미만):

```
                                       ← 회전 예고 없음 (돌지 않으니까)
"손잡이는 지금 계신 쪽에 있습니다. 진동이 나는 곳을 잡아주세요."   + 손잡이 진동(long)
"안녕하세요? 반갑습니다! 저에게 말을 거실 때는 '비카야'라고 불러주세요.
 자, 이제 어디로 가고 싶으신가요?"
```

**회전이 실패한 경우** (벽이 가까워 Nav2 가 거부):

```
"네, 잠시만 기다려주세요. 로봇이 회전하니 주의하세요."
    ↓ 회전 시도 → 0.1초 만에 중단 ("움찔")
"손잡이는 지금 계신 쪽에 있습니다. 진동이 나는 곳을 잡아주세요."   + 손잡이 진동(long)
"안녕하세요? 반갑습니다! … 어디로 가고 싶으신가요?"
```

이 경우 **손잡이가 어긋난 채 남는다.** 그래서 손잡이 안내가 가장 절실한 사람이다.

세 경우 모두 그 뒤 **60초 동안** 다른 "비카야"에 돌지 않는다(사용자가 옆에 있다고 본다.
말을 걸 때마다 60초가 다시 채워진다).

### 2-B. "아니요"

> **"알겠습니다. 이만 물러납니다."**

홈이 지정돼 있으면 홈으로 복귀, 없으면 제자리. 같은 사람에게 **60초 동안** 다시
다가가지 않는다.

### 2-C. 침묵 (답 대기 8초)

> **"실례했습니다. 필요하시면 언제든 불러 주세요."**

그 뒤는 2-B 와 같다.

## 3. 로봇이 대기 중이 아닐 때 — 회전 없음

"비카야"는 그대로 받고("네?"), **회전만** 안 한다.

| 로봇 상태 | 무슨 일이 일어나나 |
| --- | --- |
| 안내 주행 중 | 기존 사용자의 명령으로 듣는다(목적지·취소·일시정지) |
| 목적지 확인 중 ("~로 갈까요?") | 옛 질문을 접고 새 대화로 |
| 도착 후 대화·제자리 대기 중 | 옛 질문을 접고 새 대화로 |
| 사람에게 다가가는 중 | 무시 |
| 회전 중 | 무시 (돌던 것 끝내고 판단) |
| 비상정지 | 무시. 목적지를 말하면 → "지금은 비상 멈춤 상태입니다. 해제 후 다시 말씀해 주세요." |
| 사용자를 받은 뒤 60초 | 무시 (§2-A 끝 참고) |
| **홈 복귀 중** | **복귀 취소·정지.** 아래 §4 |

회전 중에 목적지를 말하면:

> **"지금은 다른 응대 중입니다. 잠시 후 다시 말씀해 주세요."**

---

## 4. 홈 복귀 중에 부르면 `[실기 검증 2회]`

복귀를 **즉시 취소하고 제자리에 선다.** 회전하지 않는다. 그 뒤:

```
 0초   정지 + "네?"
       (청취 창 약 8초 — 목적지를 말하면 안내 시작)
15초   "응답이 없어 안내를 마치고 제자리로 돌아가겠습니다."
       (3초 유예 — 여기서 말하면 안 감)
18초   홈으로 다시 출발
```

- 18초 사이에 다시 불러도 **회전하지 않는다**(사용자 결정 — 오탐 한 번이 30초 넘게
  로봇을 붙잡는 것을 막는다).
- 관리자가 앱에서 **취소**를 누르면 복귀 예약이 지워지고 그 자리에 선다.

## 5. 멘트 원문 (이 기능이 쓰는 것만)

| 이름 | 문구 | 언제 |
| --- | --- | --- |
| `WAKE_GREETING` (음성) | "네?" | 모든 호출 |
| `MSG_APPROACH_QUESTION` | "안녕하세요? 저는 시각장애인 안내로봇 비카입니다! 저와 함께 목적지까지 동행해보시는건 어떠세요? 안내를 받으시겠어요?" | 사람을 찾았을 때 |
| `MSG_APPROACH_ACCEPTED` | "네, 잠시만 기다려주세요. 로봇이 회전하니 주의하세요." | 수락 · **회전할 때만** |
| **`MSG_HANDLE_HINT`** (신규) | "손잡이는 지금 계신 쪽에 있습니다. 진동이 나는 곳을 잡아주세요." | 수락 · 회전 여부 무관 · 온보딩 직전 |
| `MSG_APPROACH_ONBOARDING` | "안녕하세요? 반갑습니다! 저에게 말을 거실 때는 '비카야'라고 불러주세요. 자, 이제 어디로 가고 싶으신가요?" | 수락 · 마지막 |
| `MSG_APPROACH_DECLINED` | "알겠습니다. 이만 물러납니다." | 거절 |
| `MSG_APPROACH_NO_ANSWER` | "실례했습니다. 필요하시면 언제든 불러 주세요." | 침묵 8초 |
| `MSG_APPROACH_BUSY` | "지금은 다른 응대 중입니다. 잠시 후 다시 말씀해 주세요." | 회전·접근 중 목적지 명령 |
| `MSG_LEAVING_NOTICE` | "응답이 없어 안내를 마치고 제자리로 돌아가겠습니다." | 복귀 중단 후 15초 침묵 |
| `MSG_ESTOP_REJECT` | "지금은 비상 멈춤 상태입니다. 해제 후 다시 말씀해 주세요." | 비상정지 중 목적지 명령 |

**못 찾았을 때는 멘트가 없다** — 의도된 침묵이다.

**진동**: `/vica/haptic_request` 에 `"long"`. 진동모터는 아직 **미장착**(`haptic_ok`
항상 false)이라 지금은 요청만 나간다. 장착 즉시 동작한다.

## 7. 알려진 한계 — 실기에서 이렇게 보인다

| 보이는 것 | 실제 | 상태 |
| --- | --- | --- |
| **움찔하고 회전 못 함** | 벽이 가까워 Nav2 가 "Collision Ahead" 로 거부. 손잡이가 뒤로 길어 스윕이 크다 | **대기 위치에 회전 여유를 둘 것.** 사용자에게 알리는 멘트는 없다 |
| 연달아 부르면 두 번째는 안 돎 | 청취 창 안의 호출은 구제 경로로 처리돼 방향이 안 나간다 | 미수리. 원인·방법은 파악됨 |
| 옆에서 가까이 부르면 돌고 손잡이가 어긋남 | 카메라가 옆을 못 봐 거리를 모른다 | 남는 구멍. 손잡이 안내 멘트가 완화 |
| "화장실, 화장실, 화장실…" 되묻기 | STT 반복 환각 (소리가 약할 때) | 별건. 음성 백로그 1순위 |
| 뒤에서 5 m 떨어져 불러도 안 옴 | 뒤쪽은 거리를 모른다 (§1-C) | 라이다로 개선 여지 |
| 안내 받은 사람이 떠난 뒤 60초 동안 다른 사람이 불러도 안 돎 | 60초 자물쇠는 시계지 사실이 아니다 | 터치센서가 살아나면 갈아끼운다 |
