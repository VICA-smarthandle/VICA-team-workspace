## 4. 남은 문제

### 4.1 코너 감속

`|wz|–vx` 상관이 구간별로 +0.04 ~ **−0.69**다. 꺾을 때 감속하는 경향이 남아 있고,
코너가 많은 구간일수록 크다. 경로 꺾임은 이미 p95 4.6°로 낮으므로 원인은
경로가 아니라 controller 또는 차체 쪽이다.

### 4.2 응답 지연 300 ms

`/cmd_vel_safe → /wheel/odom` 실측:

```
vx  200 ms   (CAN·드라이버)
wz  300 ms   (CAN·드라이버)
    +20 ms   (EKF)
```

EKF는 20 ms만 기여하고 오히려 wz 표준편차를 0.84배로 줄인다. 드라이버 램프도
아니었다. 남은 후보는 encoder 갱신 주기(16.3 Hz = 61 ms), CAN 전송(30 Hz = 33 ms),
드라이버 내부 속도 루프다. **파라미터로 접근할 수 없다.**

이 지연 때문에 정지거리가 `max_vel_x` 0.26에서 6~8 cm이고, `footprint_padding`
5 cm보다 크다. 2026-07-28 전방 우측 범퍼 충돌은 명령 vx +0.010인데 실제
vx +0.227이던 순간에 일어났다.

### 4.3 센서 사각지대

X자 책상다리에 좌측 전방이 부딪혔다. 충돌 시점 costmap은 **가장 가까운
lethal이 0.919 m**로 완전히 비어 있다고 판단했다.

| 센서 | 왜 못 보나 |
| --- | --- |
| LiDAR 0.382 m 단일 평면 | X자 다리는 높이마다 수평 위치가 다르다. 그 높이에서는 안쪽에 있다 |
| nvblox (0.05~0.9 m) | D455 수평 FOV 87°라 측면을 못 본다 |

파라미터로 막을 수 없다. nvblox TSDF 적용 시 재검토한다.

### 4.4 직진 비틀거림

경로가 곧은 구간에서도 실제 wz 표준편차가 0.136 rad/s(`max_vel_theta` 0.4의 34 %)다.
정지 중에는 0.002 rad/s로 깨끗하므로 센서 잡음이 아니라 주행 중 거동이다.

## 5. 측정 방법 주의

- `/scan` 기반 "여유" 최소값·p1은 **로봇 부착물에 오염된다.** footprint 안쪽
  점만 제외하므로 footprint 바로 바깥의 손잡이·랩톱이 남는다. 중앙값만 신뢰한다.
- `/local_costmap/costmap`은 OccupancyGrid라 **0~100 스케일**이다. costmap 원시
  0~254로 세면 lethal이 항상 0 %로 나온다.
- DWB 원본 명령은 `/cmd_vel`이 아니라 **`/cmd_vel_nav`**다. `/cmd_vel`은 구독자 0인
  죽은 토픽이다.
- 재샘플(20 ms 격자) 미분은 실제 명령 주기(50 ms)를 왜곡한다. 변화율은 원본
  타임스탬프로 재야 한다.

## 6. 자동화

`~/vica_data/analysis/run_test.py`가 기록 → 왕복 주행 → 정지를 한 번에 수행한다.

```bash
python3 run_test.py <bag이름> 화장실 방2 화장실 안내소
```

`/emergency_stop`이 true가 되면 다음 Goal을 보내지 않는다. 다만 **Mission Manager에
Goal 취소 서비스가 없어** 이미 나간 Goal은 중단할 수 없다. 정지 수단은 물리
E-stop과 앱뿐이므로 사람이 지켜봐야 한다.
