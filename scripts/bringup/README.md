# VICA 음성 주행 매뉴얼

이 문서 하나만 따라 하면, **처음 하는 사람도** 음성 명령으로 VICA 로봇을
주행시킬 수 있다. 명령 6개를 일일이 외울 필요 없이, `start.sh` 한 번이면
Terminator 창 하나가 6칸으로 열리고 각 칸이 필요한 프로그램을 자동 실행한다.

```
[1 Nav2   ] [2 Safety ] [3 Motor ]     ← 로봇을 움직이는 쪽
[4 Mission] [5 Voice  ] [6 STT   ]     ← 말을 알아듣고 판단하는 쪽
```

> ⚠️ **이건 진짜 로봇을 움직인다.** 반드시 [5. 첫 주행 안전 절차](#5-첫-주행-안전-절차-반드시)를
> 먼저 읽는다. 처음에는 **로봇 바퀴를 공중에 띄운 상태**로 시작한다.

## 1. 준비물 체크리스트

주행 전에 아래가 모두 준비돼 있어야 한다.

**하드웨어**
- [ ] **로봇과 연결된 Jetson** (개발용 PC 아님 — CAN·라이다·모터가 실제로 붙은 기기)
- [ ] 마이크와 스피커가 Jetson에 연결·인식됨
- [ ] 라이다 전원 On (위치추정에 필요)
- [ ] 로봇을 올려둘 **받침대** (첫 주행은 바퀴를 띄워야 함 — 5장 참고)

**소프트웨어 / 설정**
- [ ] 로봇 저장소 빌드됨 (`vica_ros2_ws/install` 존재)
- [ ] 음성 저장소 `.venv` 존재, `.env`에 `OLLAMA_API_KEY` 설정됨
- [ ] 지도 파일 존재 (예: `vica_ros2_ws/maps/vica_map_0630.yaml`)
- [ ] 목적지에 **위치(pose)가 등록**돼 있음 (안 되면 로봇이 "안내할 수 없는 곳"이라며 거부)
- [ ] `terminator` 설치됨 (`sudo apt install terminator`)
- [ ] CAN 인터페이스가 켜져 있음 (예: `can1`)

> `start.sh`를 실행하면 위 항목 일부를 자동으로 점검해 경고해 준다. 경고가 떠도
> 실행은 되지만, 그 항목은 고쳐야 정상 주행한다.

## 2. 최초 1회 설정

처음 한 번만 하면 되는 설정이다.

### 2-1. 경로·지도·도메인 맞추기

`scripts/bringup/vica_env.sh` 파일을 열어 **맨 위 "여기만 고친다" 블록**을 환경에
맞게 수정한다.

```bash
export VICA_DOMAIN_ID=7        # ★ 가장 중요: 음성과 로봇이 같은 번호여야 서로 대화됨
export VICA_ROS_WS="/home/<사용자>/…/vica_ros2_ws"   # 로봇 저장소 경로
export VICA_VOICE="/home/<사용자>/…/vica-voice-llm"  # 음성 저장소 경로
export VICA_MAP="$VICA_ROS_WS/maps/vica_map_0630.yaml"  # 사용할 지도(.yaml)
export VICA_CAN="can1"         # 모터 CAN 인터페이스 이름
```

> **`VICA_DOMAIN_ID`가 왜 중요한가:** ROS에서는 같은 "도메인 번호"를 쓰는
> 프로그램끼리만 서로의 메시지가 보인다. 음성 쪽과 로봇 쪽 번호가 다르면,
> 말을 해도 로봇이 전혀 반응하지 않는다(에러도 안 남). 로봇의 다른 노드가 쓰는
> 번호와 반드시 똑같이 맞춘다.

### 2-2. 로봇 저장소 빌드

```bash
cd $VICA_ROS_WS
source /opt/ros/humble/setup.bash
colcon build
```

### 2-3. 음성 LLM 키 설정

목적지 해석에 클라우드 LLM을 쓴다. `vica-voice-llm/.env` 파일에 키를 넣는다.

```bash
# vica-voice-llm/.env
OLLAMA_API_KEY=여기에_발급받은_키
```

### 2-4. CAN 켜기

모터·센서가 쓰는 CAN 버스를 올린다(이름·비트레이트는 로봇 설정에 맞춘다).

```bash
sudo ip link set can1 up type can bitrate 1000000
```

## 3. 실행하기 (단계별)

### 3-1. 실행 명령

터미널에서 워크스페이스 루트로 이동해 실행한다.

```bash
cd /home/<사용자>/…/VICA-smarthandle
scripts/bringup/start.sh
```

### 3-2. 실행하면 벌어지는 일

1. **사전 점검** — 빌드·지도·`.env` 등을 확인하고, 빠진 게 있으면 `[경고]`로 알려준다.
2. **안전 확인 프롬프트** — 바퀴를 띄웠는지 묻는 안내가 뜬다. 지켰으면 **엔터**, 아니면 **Ctrl+C**로 취소한다.
3. **Terminator 창 하나가 6칸으로 열린다.** 각 칸이 자동으로 프로그램을 실행한다.
   - 순서: Nav2 → Safety → Motor → (약 8초 뒤) Mission → Voice → STT
   - Mission이 조금 기다리는 이유: Nav2가 준비되기 전에 목적지를 보내면 거부되기 때문.
4. 각 칸 맨 위에는 **무슨 창인지 + 다시 실행하는 법**이 찍힌다.

### 3-3. 준비 완료 신호

아래가 보이면 명령을 받을 준비가 된 것이다.
- **5 Voice 칸**: LLM/TTS 노드 시작 로그
- **6 STT 칸**: `녹음하려면 엔터 (종료 Ctrl+C) >` 프롬프트

이제 [6장](#6-음성으로-목적지-보내기)으로 간다.

## 4. 창 구성 — 무엇이 어디 있나

| 칸 | 이름 | 하는 일 | 정상일 때 보이는 것 |
| --- | --- | --- | --- |
| 1 | **Nav2** | 지도·현재위치·경로 계산 → 주행 속도 명령 생성 | costmap/controller 로그가 흐른다 |
| 2 | **Safety** | 비상정지 래치 + 속도 최종 승인(`/cmd_vel_safe`) | `Subscribed: /cmd_vel_req …` |
| 3 | **Motor** | 승인된 속도만 받아 CAN으로 바퀴 구동 | `Subscribed: /cmd_vel_safe` |
| 4 | **Mission** | 명령 심사(갈 수 있는 곳인지) 후 Nav2에 목적지 전달 | 대기 로그 |
| 5 | **Voice** | 말 뜻 해석(LLM) + 로봇 음성 답변(TTS) + 상시 긴급어 감지 | 노드 시작 로그 |
| 6 | **STT** | 마이크 녹음 → 글자로 변환 | `녹음하려면 엔터 …` |

핵심 흐름 한 줄: **말(6) → 뜻 해석(5) → 심사(4) → 경로(1) → 승인(2) → 바퀴(3).**

## 5. 첫 주행 안전 절차 (반드시)

이 음성→주행 전체 경로는 문서상 아직 **실기 미검증(P0)**이다. 즉 "코드는 다
이어져 있지만, 진짜 바퀴 달고 끝까지 돌려본 적은 없다." 그래서 **처음에는 절대
바닥에서 바로 주행시키지 않는다.**

**순서**

1. 로봇을 받침대에 올려 **바퀴를 공중에 띄운다.** (움직여도 로봇이 도망가지 않게)
2. `start.sh`로 전체를 실행한다.
3. **먼저 "멈춰"라고 말해** E-stop을 시험한다. → 바퀴가 즉시 멈추고, 2 Safety 칸에
   비상정지 로그가 떠야 한다. (여기서 안 멈추면 더 진행하지 말 것)
4. 물리 비상정지 버튼도 눌러 본다. → 마찬가지로 즉시 정지해야 한다.
5. 여기까지 정상이면, 목적지 명령을 줘서 **바퀴가 공중에서 도는지** 확인한다.
6. 바퀴 구동·정지·비상정지가 모두 정상이면, 그때 처음으로 **바닥에 내려** 짧은
   거리부터 주행한다.

> 상세 현장 시험 절차는 `vica-voice-llm/docs/voice-field-test.md`에 단계별로 있다.

## 6. 음성으로 목적지 보내기

말은 **6 STT 칸**에서 주고받는다. 이 로봇은 아무 때나 듣지 않고, **엔터를 눌러야
녹음**하는 방식(push-to-talk)이다.

**한 번의 대화 흐름**

1. **6 STT 칸을 클릭**해 활성화한 뒤 **엔터**를 누른다. → 녹음 시작.
2. 목적지를 말한다. 예: **"화장실로 가줘"**, **"윤지영 교수님 사무실"**, **"배고파"**(→식당).
3. **엔터**를 다시 눌러 녹음을 끝낸다. → 글자로 변환된다.
4. 로봇이 스피커로 되묻는다: **"○○로 안내해드릴까요?"**
5. 다시 **엔터 → "응"(또는 "네", "맞아") → 엔터**. → 로봇이 "안내를 시작합니다" 하고 출발한다.
6. 주행 중에는 남은 거리("약 10미터 남았습니다")와 도착 안내가 나온다.

**팁**
- 로봇이 말하는 도중에 다시 엔터로 말하면, 로봇은 자기 말을 멈추고 듣는다.
- 잘못 알아들으면 "잘 듣지 못했습니다. 다시 말씀해 주세요"가 나온다. 다시 말하면 된다.
- 못 가는 곳을 말하면 "안내할 수 없는 곳입니다"라고 답한다.

## 7. 멈추기와 비상정지

**주행 중 급히 세우기 (비상정지)** — 셋 다 즉시 정지시킨다.
- **음성**: "멈춰", "정지", "스탑", "안돼", "위험해"
- **물리 버튼**: 로봇의 비상정지 버튼
- **앱**: 관리자 앱의 정지

> 비상정지가 걸리면 **중앙 래치**가 잡아 둔다. 원인(버튼·음성·앱)을 모두 해제해도
> 자동으로 풀리지 않고, **관리자 앱에서 reset**해야 다시 움직인다. (현재 이 reset
> 경로는 구현 진행 중 항목이다.)

**전체 종료**
- 각 칸에서 **Ctrl+C**로 노드를 끄거나, Terminator 창을 닫는다.
- 완전 종료 후 다시 하려면 `start.sh`를 재실행한다.

## 8. 잘 돌아가는지 확인하기

새 터미널에서 환경을 불러 토픽이 보이는지 확인하면, 어디가 끊겼는지 알 수 있다.

```bash
source scripts/bringup/vica_env.sh      # 도메인 등 환경 로드 (인트로가 한 번 찍힘)
ros2 topic list
```

아래가 보여야 정상이다.

| 토픽 | 뜻 | 안 보이면 |
| --- | --- | --- |
| `/vica/user_text` | 내가 한 말(글자) | 6 STT 확인 |
| `/vica/intent` | 해석된 목적지 | 5 Voice 또는 도메인 번호 확인 |
| `/cmd_vel_req` | Nav2가 원하는 속도 | 1 Nav2 / 목적지 pose 확인 |
| `/cmd_vel_safe` | Safety가 승인한 속도 | 2 Safety / 비상정지 상태 확인 |

값이 실제로 흐르는지 보려면: `ros2 topic echo /cmd_vel_safe`

## 9. 오류가 났을 때 — 다시 실행

노드가 죽어도 `exec bash` 덕분에 **그 칸은 닫히지 않고 bash 프롬프트가 남는다.**
문제가 난 칸만 다시 띄우면 된다.

**(A) 창에 찍힌 안내 줄을 그대로 붙여넣기 (가장 쉬움)**
각 칸 맨 위에 이런 줄이 있다. 복사해 붙여넣으면 그 노드만 재시작된다.
```
↻ 이 창만 다시 실행:  source "/…/scripts/bringup/vica_env.sh"; run_nav2
```

**(B) 손으로 입력**
```bash
source /home/<사용자>/…/scripts/bringup/vica_env.sh
run_nav2      # ← 그 칸에 맞는 함수: run_safety / run_motor / run_mission / run_voice / run_stt
```

**값을 바꿔서 다시** 하려면 `vica_env.sh` 위쪽을 고친 뒤 위 명령을 다시 실행한다.
**전체를 껐다 켜려면** 모든 창을 닫고 `scripts/bringup/start.sh`를 다시 실행한다.

> 예: Nav2는 떴는데 Mission이 "Nav2 not ready"로 죽었다면, Nav2가 완전히 뜬 뒤
> Mission 칸에서 `run_mission`만 다시 부르면 된다.

## 10. 각 창이 실제로 실행하는 명령어

각 칸은 `vica_env.sh`를 불러(공통 환경 설정) 아래 함수를 실행한다. **모든 칸이
먼저 하는 공통 준비:**

```bash
source /opt/ros/humble/setup.bash
source "$VICA_ROS_WS/install/setup.bash"
export ROS_DOMAIN_ID=$VICA_DOMAIN_ID
```

| 칸 | 함수 | 준비 후 실행하는 명령 |
| --- | --- | --- |
| 1 Nav2 | `run_nav2` | `ros2 launch vica_nav2 nav2_map_test.launch.py map:=$VICA_MAP start_localization:=true can:=$VICA_CAN` |
| 2 Safety | `run_safety` | `ros2 launch vica_safety safety_bringup.launch.py` |
| 3 Motor | `run_motor` | `ros2 launch mdrobot_can_control motor_bringup.launch.py` |
| 4 Mission | `run_mission` | `ros2 launch vica_mission_manager mission_manager.launch.py` |
| 5 Voice | `run_voice` | `cd $VICA_VOICE && ros2 launch launch/vica_voice.launch.py` |
| 6 STT | `run_stt` | `cd $VICA_VOICE && .venv/bin/python -m src.ros_stt_node` |

## 11. 문제 해결 (증상별)

| 증상 | 먼저 볼 것 |
| --- | --- |
| **말해도 로봇이 전혀 반응 없음** | `VICA_DOMAIN_ID` 불일치를 1순위로 의심. 8장으로 `/vica/intent`가 보이는지 확인. |
| **로봇이 "안내할 수 없는 곳"이라 함** | 그 목적지에 위치(pose)가 등록 안 됨. `destinations.yaml` 확인. |
| **목적지는 맞는데 안 움직임** | `/cmd_vel_safe`가 흐르는지(8장). 비상정지가 걸려 있는지(2 Safety). |
| **목적지 해석이 실패("지금 처리할 수 없어요")** | `.env`의 `OLLAMA_API_KEY`, 인터넷 연결 확인. |
| **소리가 안 남 / 마이크가 안 잡힘** | 스피커·마이크 연결과 Jetson 오디오 장치 인식 확인. |
| **바퀴가 안 돎 / CAN 에러** | `VICA_CAN` 이름과 `ip link`로 CAN이 up인지 확인. |
| **칸이 순식간에 닫힘** | 그 `run_XXX`를 터미널에서 직접 실행해 에러 메시지를 본다. |
| **"멈춰" 했는데 안 풀림** | 정상. 비상정지는 관리자 앱 reset으로만 해제(7장). |
| **배치를 바꾸고 싶음** | `layout.terminator.in`의 `parent`/`order`/`ratio` 수정. |

## 12. 초심자용 용어

- **노드(node)**: ROS에서 도는 프로그램 하나. (예: Nav2 노드, STT 노드)
- **토픽(topic)**: 노드끼리 데이터를 주고받는 "통로 이름". (예: `/cmd_vel_safe`)
- **launch**: 여러 노드를 한 번에 켜는 실행 파일.
- **도메인(domain)**: 같은 번호끼리만 토픽이 보이는 "통신 채널 번호".
- **pose**: 지도 위의 위치와 방향(좌표). 목적지마다 등록돼 있어야 로봇이 갈 수 있다.
- **E-stop / 비상정지**: 로봇을 즉시 세우는 안전 정지. 중앙 래치가 잡아 두고,
  관리자 reset 전에는 안 풀린다.
- **push-to-talk**: 아무 때나 듣지 않고, 엔터를 눌러야 녹음하는 방식.
- **CAN**: 모터 드라이버와 통신하는 버스(케이블/프로토콜).
